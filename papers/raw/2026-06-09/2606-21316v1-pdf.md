**Abstract**
Recent advances in artificial intelligence (AI), particularly large language models (LLMs), have created new opportunities for natural-language interaction with scientific software, but reliable theoretical model building still requires deterministic symbolic calculations. We present bsm_agent, an open-source symbolic framework for beyond the Standard Model (BSM) model building that combines a deterministic physics backend with an LLM chat interface. Starting from the SM field content and a user-specified set of additional scalars and/or fermions, the package constructs renormalizable Lagrangian, performs gauge-anomaly checks, expands operators into component fields, and derives electroweak symmetry breaking stationary conditions and tree-level mass matrices. The key novelty of the framework is that all of these tasks are performed automatically once the user specifies the quantum numbers of the new fields through a natural-language interface, eliminating the need for manual model construction. The symbolic calculations are performed entirely by the Python backend to ensure the correctness and reproducibility of the physics results; the LLM is used only as an orchestration layer that interprets natural-language requests, manages confirmation steps for ambiguous inputs, triggers backend tools, and formats report-ready summaries. The package supports three provider classes: local Ollama inference, remote self-hosted model servers accessed through the implemented remote provider interface, and commercial hosted APIs via OpenAI and Anthropic. This separation between conversational control and deterministic computation preserves reproducibility while making interactive BSM model construction substantially more convenient. § bsm_agent

**I Introduction**A central goal of particle physics is to construct theoretical models that describe and explain the fundamental constituents of nature and their interactions. At present, the Standard Model (SM) [1, 2, 3] of particle physics provides the most successful description of elementary particles and their interactions. The SM is based on a gauge-invariant Lagrangian containing a large number of interaction terms and has been remarkably successful in explaining a wide range of experimental observations.
Despite its tremendous success, the SM is known to be incomplete. Among its most important shortcomings are: (i) the prediction of massless neutrinos, whereas neutrino-oscillation experiments have firmly established that neutrinos possess non-zero masses; (ii) the inability to account for the observed matter–antimatter asymmetry of the Universe; and (iii) the absence of a viable dark matter candidate. These observations strongly suggest the existence of physics beyond the SM (BSM).
One of the simplest approaches to BSM model building is to extend the particle content of the SM through the addition of new scalar and/or fermionic fields while leaving the gauge structure unchanged. This class of models encompasses a large variety of phenomenologically interesting scenarios and serves as a common starting point for theoretical investigations.
Constructing such models, however, can be a laborious and error-prone process. For a given set of new fields, one must identify all renormalizable gauge-invariant operators, verify gauge-anomaly consistency, derive the full Lagrangian, expand operators into component fields for phenomenological studies, and obtain the corresponding mass matrices after electroweak symmetry breaking. As the number of new fields increases, the number of allowed interaction terms grows rapidly, making it increasingly difficult to ensure that all relevant operators are included in the Lagrangian and that only linearly independent operators are retained.
To address these challenges, we introduce bsm_agent, an open-source Python framework for symbolic BSM model building. The package combines a deterministic physics backend with a large-language-model [4] (LLM) chat interface, enabling users to construct and analyze models through natural-language interactions while retaining the reliability and reproducibility of symbolic computations. Given the SM field content and a user-specified set of additional scalar and/or fermionic fields, the framework automatically generates the complete renormalizable operators, performs gauge-anomaly diagnostics, expands the Lagrangian into component fields, inserts vacuum expectation values (VEVs) of color and charge neutral states, lists the stationary conditions, and derives tree-level mass matrices, requiring no manual model construction beyond the specification of the new fields’ quantum numbers through a natural-language chat interface. All physics calculations are carried out by the symbolic backend, while the LLM serves exclusively as an orchestration and user-interface layer.
The primary objective of this software package is to enhance the accessibility of intricate modelbuilding methodologies, rendering advanced theoretical frameworks manageable for students and pedagogical use while maintaining the rigor required by research professionals. To provide a fasttrack for experienced model builders eager to start implementation, the foundational and interfacelevel chapters (Sections II-IV) can be omitted, with Section V serving as the practical entry point. Furthermore, Appendix A provides the quickest way for readers to begin using the package immediately.

**III Deterministic Symbolic Backend**
**III.1 Field Content and Model Extension**
The symbolic workflow begins with a Standard Model template and a list of extra fields. Each field is specified by its name, whether it is a scalar or a Weyl fermion, its*SU(3)*representation, its*SU(2)*representation, its hypercharge, and whether the field is real. The model container prevents duplicate field names and combines the SM content with the new BSM degrees of freedom into a single internal representation. The automatic operator generator is restricted to operators of mass dimension less than or equal to four, i.e., renormalizable. This is intentional: it keeps the generated operator basis finite, model independent, and directly useful for tree-level studies of the scalar and fermion sectors.
The current implementation is within the SM gauge group,*SU(3)c*×*SU(2)L*×*U(1)Y*, and supports the following classes of gauge representations*(Z,X, Y*) under the SM:
♦ Arbitrary values of the*U(1)Y*hypercharge,*Y*.
♦*SU(2)L*representations of dimensions*X*= 1, 2, 3, 4, 5, 6, and 7. —This choice is motivated by minimal dark matter scenarios [22], in which the lowestdimensional viable candidates correspond to a fermionic quintuplet and a scalar septuplet. These minimal realizations do not require the introduction of any additional symmetries beyond those of the SM to ensure dark matter stability. —While the framework supports*SU(2)L*representations up to dimension 7, the computational complexity of scalar-potential expansion increases rapidly for models containing multiple higher-dimensional scalar multiplets. The current implementation therefore focuses on the phenomenologically most common scenarios, for which complete symbolic results can be generated within practical runtimes. In particular, for scalar multiplets with*SU(2)L*dimension*X >*3, the package supports models containing a single field with quantum numbers*(1, X, Y*), including complete expansion of the Lagrangian into component fields.
♦*SU(3)c*representations*Z*= 1, 3, 3, 6, 6, and 8. —This choice is motivated by realistic*SO(10)*[23] grand-unified constructions, where commonly used representations such as 10, 16, 45, 54, 120, 126, and 210 do not contain color representations larger than the adjoint octet under*SU(3)c.*—Due to the computational complexity associated with the symbolic expansion of the La-grangian, the current implementation supports fields transforming as*(Z,X, Y*) with*X*≤ 3.
Taken together, this broad range of gauge representations allows users to construct a wide variety of phenomenologically interesting extensions of the Standard Model. The current restrictions on higher-dimensional representations arise from computational considerations associated with symbolic expansion and will be progressively relaxed in future versions of the package.
It is important to emphasize that bsm_agent is complementary to existing packages such as SARAH [24], FeynRules [25], and Susyno [26], which provide powerful frameworks for implementing and analyzing particle-physics models. In these tools, the user typically specifies the model definition, including the relevant interaction structure or Lagrangian, from which physical quantities such as interaction vertices, mass spectra, and other observables can be derived. By contrast, the primary goal of bsm_agent is to automate an earlier stage of the model-building workflow. Start-ing only from the Standard Model field content and the quantum numbers of newly introduced scalar and/or fermionic fields, the framework automatically constructs the complete renormalizable gauge-invariant operator basis and derives the corresponding Lagrangian. This significantly reduces the manual effort required during the initial stages of BSM model construction. At present, the framework is restricted to extensions that preserve the Standard Model gauge symmetry and introduce additional scalar and/or fermionic fields. Extensions involving enlarged gauge groups constitute a natural direction for future development but are beyond the scope of the present work.
**III.2 Gauge-Anomaly Checks**
Before discussing operator generation, it is useful to note that anomaly checking is implemented natively in the backend. The code computes the standard anomaly coefficients by summing over the left-handed Weyl fermions present in the model. The reported coefficients are
*ASU(3)3 , ASU(2)2U(1), ASU(3)2U(1), Agrav2U(1), AU(1)3 .*(1)
For each fermion representation, the appropriate Dynkin-index and hypercharge weights are accumulated, and the final report states whether all five coefficients vanish.
If non-vanishing anomaly coefficients are detected, the package may suggest the addition of conjugate fermionic representations associated with the fields responsible for the anomaly. Such suggestions are intended only as a convenience for exploratory model building and should not be interpreted as a complete solution to the anomaly-cancellation problem. Indeed, gauge anomalies can be cancelled in many different ways, and the introduction of conjugate representations represents only one possible strategy.
**III.3 Automatic Generation of the Renormalizable Lagrangian**
Once the field content is fixed, the package constructs the full renormalizable gauge-invariant operator basis. Importantly, the user is not required to specify any interaction terms manually. The complete renormalizable Lagrangian is derived directly from the field content and gauge quantum numbers. The generation step is centered on the model container and proceeds by operator class.
**Scalar sector.**All scalar monomials containing up to four scalar fields are enumerated using combinations with replacement. For each candidate monomial, the backend checks whether the product contains at least one gauge singlet and whether its total mass dimension is at most four. Allowed singlets are then added to the scalar potential. The corresponding coefficient symbols are assigned automatically with prefixes that reflect the degree of the operator, namely
*ξ3, m2, µ, λ,*(2)
for linear, quadratic, cubic, and quartic terms, respectively. If a given field product admits several independent gauge contractions, the package indexes them explicitly. For example, consider a scalar quartic interaction with coupling*λi.*If three independent gauge-invariant contractions exist for this interaction, the package labels the corresponding couplings as*λi,c1, λi,c2,*and*λi,c3.*
For every scalar field added to the model, the package automatically assigns a symbolic identifier*ϕi*(for clarity, the package uses BLUE to denote any BSM scalar field), with the index*i*distinguishing different scalar species.
**Fermion mass sector.**All bilinears constructed from Weyl fermions are tested for gauge invariance. Whenever a singlet exists, a fermion-mass operator is generated with an automatically named coefficient*Mi*or*Mi,c*when several contractions are present.
For every Weyl fermion added to the model, the package automatically assigns a symbolic identifier*ψi*(for clarity, the package uses RED to denote any BSM fermion field), with the index*i*distinguishing different Weyl-fermion species.
**Yukawa sector.**The Yukawa sector is generated by combining two Weyl fermions with one scalar factor and again testing for singlet multiplicity. If the product is gauge invariant, the corresponding Yukawa operator is added with a coefficient*Yi*or*Yi,c.*
It is important to note that, in all Yukawa terms, the family/generation indices are suppressed.
**Hermitian-conjugate handling and deduplication.**The generator explicitly avoids double counting. Operators are ordered canonically, compared against their Hermitian conjugates, and only added once when the conjugate term is not independent. The resulting Lagrangian therefore has a deterministic and stable symbolic representation.
The output of this stage is a symbolic Lagrangian object partitioned into scalar-potential, Yukawa, fermion-mass, and gauge-kinetic sectors. This representation serves as the common input for component-field expansion, electroweak-symmetry-breaking analysis, mass-matrix derivation, and report generation.
**III.4 Computational Scaling with Large Gauge Representations**
The runtime of the automatic model-construction stage depends not only on the number of new fields but also on the sizes of their gauge representations. In particular, fields transforming in higher-dimensional*SU(2)L*and/or*SU(3)c*representations generally require longer execution times than singlets, doublets, or triplets. This behavior is expected, because the operator generator must test a larger set of candidate renormalizable field combinations and, for each candidate, determine whether one or more independent gauge-singlet contractions exist.
The underlying group-theoretic cost also increases rapidly with representation size. Larger multiplets produce larger tensor-product spaces, a greater number of admissible index contractions, and, in some cases, a higher multiplicity of independent invariant tensors. The scalar sector is particularly demanding in this respect, since repeated scalar fields require an additional projection onto the Bose-symmetric subspace in order to retain only linearly independent operators. Consequently, even models containing only a small number of new fields can exhibit noticeably longer runtimes when those fields belong to large non-Abelian representations. This is therefore a computational consequence of the exact symbolic construction of the operator basis, rather than an indication of any inconsistency in the model itself.
To mitigate this growth, the implementation includes several representation-aware optimizations for the cases that are known to arise frequently in phenomenological studies. In the weak sector, repeated identical scalar multiplets are treated in a reduced Bose-symmetrized basis rather than in the full tensor-product basis, which is particularly beneficial for large real*Y*= 0 multiplets such as quintuplets and septuplets. For selected self-interaction structures of real weak triplets, quintuplets, and septuplets, the expansion backend also uses direct closed-form constructions of the corresponding invariant combinations. In the color sector, octet contractions are handled through a dedicated adjoint-basis construction together with pruning of redundant contraction patterns. These optimizations substantially improve performance for several computationally demanding cases, although the runtime can still increase appreciably for models containing large non-Abelian representations. **III.5 Expansion into Component Fields**
**Motivation.**A compact gauge-invariant operator basis is useful for classification, but phenomenological calculations often require explicit expressions in terms of component fields. The package therefore provides a deterministic expansion backend that maps every supported scalar, Yukawa, and fermion-mass operator to its corresponding sum of component-field terms.
**Algorithmic Structure.**The component-expansion module acts directly on the gauge-invariant operator object. For scalar operators, it constructs the relevant*SU(2)*and*SU(3)*singlet structures and enumerates the contributing weak-isospin and color assignments. The implementation employs explicit Clebsch–Gordan coefficients for weak contractions together with an explicit color-singlet basis. Each resulting term is assigned the appropriate numerical or symbolic coefficient, including the phase conventions associated with the chosen basis.
For Yukawa and fermion-mass operators, the same procedure is applied while accounting for fermion ordering, possible dual-basis slots, and the phase conventions required to maintain consistency with the internal symbolic representation. It is important to note that, in all Yukawa terms, family/generation indices are suppressed.
Mathematically, the expansion is implemented as a multilinear-algebra problem in the representation spaces associated with the gauge quantum numbers of the fields. Each operator is viewed as a tensor product of field factors carrying weak-isospin and color indices, and the backend constructs the corresponding gauge-singlet tensors by combining the relevant Clebsch–Gordan structures for*SU(2)L*with explicit invariant tensors for*SU(3)c.*The component expressions are then obtained by contracting these invariant tensors with the field-component basis in a fixed convention. In this way, the expanded terms are derived directly from the representation theory of the gauge group rather than from hand-written case-by-case rules.
The resulting output is not a heuristic rewriting of the operator name but an explicit decomposition of the gauge singlets into their field components. This representation is subsequently reused by the mass-matrix extractor, avoiding the need for a separate EWSB expansion stage.
**Compact and Fully Expanded Reports.**The report backend exposes both a compact and a fully expanded representation of the Lagrangian. The compact form preserves the gauge-invariant operator notation, whereas the expanded form writes each supported operator class explicitly in terms of component fields. The current LATEX report output organizes the material by sector, namely Yukawa and fermion-mass terms, the scalar potential, and gauge/kinetic terms.

**Stationary Conditions.**From the scalar potential, the package constructs the vacuum potential by replacing the shifted neutral components by their VEV parts and summing the resulting terms, including Hermitian conjugates when appropriate. The stationary condition is then written as
*∂V*
*∂vi*=*0,*(4)
for every VEV symbol*vi*associated with a color- and charge-neutral scalar component. In the simplest Standard Model-like configuration this reduces to the Higgs tadpole equation, while in extended models the package reports one stationary condition for each independent neutral VEV generated by the field content.
**Mass-Matrix Extraction.**For the mass-matrix extraction, the VEV substitutions are applied term by term. The resulting expressions are scanned for contributions with exactly two surviving fields. These bilinears define the quadratic part of the shifted Lagrangian and are accumulated into symbolic matrices.
For general scalar sectors, the backend stores hermitian blocks of the form*ϕ† iϕj*. This is a
natural representation in the original complex component basis. However, neutral scalar fields are presented in a combined real basis for readability. If the model contains neutral complex fields*H0, ϕ0*
*1, ϕ*0*2, . . .*, the report constructs the neutral scalar mass matrix in the basis
*(ReH0, Reϕ0 1, Reϕ0*
*2, . . . , ImH0, Imϕ0 1, Imϕ0*
*2, . . . ).*(5)
If a neutral field is real, it contributes only to the real part of the basis. Charged or otherwise non-neutral scalar sectors remain listed in their residual hermitian and holomorphic blocks.
The fermion mass matrices are obtained analogously by collecting the bilinears left after the VEV shifts in the Yukawa and fermion-mass sectors. The entire procedure is therefore algorithmic and model independent within the renormalizable scope of the code.
**IV LLM-Assisted Interaction Layer**
**IV.1 Tool-Calling Design**
The conversational layer is built around a tool-calling interface. The symbolic backend exposes a small number of high-level actions, most importantly a model-construction tool and a reportgeneration tool. The LLM receives a system prompt describing when to call these tools and is expected to return either plain text or a structured tool invocation with a machine-readable argument payload. In practical terms, the LLM is responsible for tasks such as
1. interpreting a natural-language description of BSM field content,
2. translating that description into the structured field schema expected by the backend,
3. asking follow-up questions or triggering a confirmation stage if the user input is ambiguous,
4. selecting whether the user is requesting model construction, report generation, or a follow-up action on the current model,
5. formatting the deterministic tool output into a concise human-readable answer.
What the LLM does*not*do is equally important: it does not derive the gauge singlets, compute anomaly coefficients, expand the operators, or calculate the mass matrices. Those tasks remain entirely within the backend code.
**IV.2 Conversation State and Confirmation Workflow**
The chat controller maintains a conversation history, the most recent current-model state, and any pending confirmation request. If the user supplies an incomplete field description, the system can infer a candidate structured interpretation and then explicitly ask for confirmation before creating the model. This guardrail is particularly useful in BSM model building, where a missing statement about whether a field is scalar or fermionic, real or complex, or the sign of a hypercharge can materially change the generated theory. More specifically, the user can define a new field through natural-language input by specifying only:
♦ its quantum numbers under the SM gauge group;
♦ its spin assignment (scalar or fermion);
♦ whether the scalar is real, if applicable. Once the user confirms the interpretation, the controller calls the backend tool, stores the
resulting structured state, and allows subsequent requests such as report generation or EWSB analysis to operate on the same model context.
After a model has been constructed, the same state mechanism also supports resetting the active model context. The user may explicitly ask the package to clear the current model, in which case the controller discards the stored model state and returns the conversation to a fresh construction state. This allows the user to start over and define a different BSM model without residual fields, assumptions, or analysis results from the previous model carrying over.
**IV.3 Supported LLM Backends**
The provider layer is backend agnostic and separates the symbolic workflow from the underlying language model implementation. The package supports three provider classes: local Ollama inference, remote self-hosted model servers accessed through the implemented remote provider interface, and commercial hosted APIs via OpenAI and Anthropic.
1.**Local self-hosted models.**The model is served on the same machine as the symbolic package, typically through Ollama. In this mode, the user must first pull a compatible local model, for example,
ollama pull gpt-oss:20b
and then invoke the installed CLI with the corresponding model name; for example,
bsm-agent –model gpt-oss:20b
2.**Remote self-hosted models.**The model is served on a user-managed remote server and accessed through the implemented remote provider interface. In the current implementation, this corresponds to a remote self-hosted deployment configured through the appropriate providerprefixed model target together with the remote server settings; for example,
bsm-agent –model openai:qwen3.6:35b-a3b –api-base <server-url> –api-key <token>
3.**Commercial API models.**The framework can also connect to third-party hosted language models through commercial provider APIs, in particular OpenAI and Anthropic endpoints. Backend-specific wrappers translate the internal conversation history and tool schema into the format required by the selected service. For example, an OpenAI model may be accessed through
bsm-agent –model openai:gpt-4.1 –api-key <token>
Because the orchestration logic is independent of the provider implementation, the symbolic model-building workflow remains unchanged across backends. Users may therefore switch between local self-hosted models, remote self-hosted deployments, and commercial API services without modifying the symbolic model-construction code.
**IV.4 Software requirements**
The software requirements of the current implementation are modest. The package metadata explicitly requires Python ≥*3.10*and setuptools ≥ 61 for installation, while the symbolic backend depends on SymPy [38]. Since the intended user workflow is through the conversational interface with local Ollama-hosted models, the practical software stack also includes langchain-core [39], langchain-ollama, and a local ollama [40] installation. For local inference, the user must additionally download a compatible Ollama model, for example, gpt-oss:20b or qwen3.5:35b. Alter-natively, the same interface can be connected either to a remote self-hosted model server through the implemented remote provider interface or to commercial hosted APIs through the OpenAI or Anthropic provider configurations. PDF report generation further requires a local pdflatex installation. Support for these additional provider classes is implemented in the source code through the corresponding backend wrappers, although the Ollama-based workflow remains the primary intended mode of use.

**VII Package features**In this section, our goal is not to construct phenomenologically viable models. Rather, we focus on illustrating various aspects of the package’s notation and model-building interface. The primary purpose of this section is to demonstrate the flexibility afforded by the chat-based construction framework: users are not required to follow any rigid syntax or predefined input format. Instead, models can be specified using natural-language descriptions, which is one of the most powerful features of the package.

**VII.6 Basis Choice, Normalization, and Phase Conventions**
It is important to clarify that when the user asks the package to construct a model,
*⋆*The package always uses canonical normalization for all fields. Consequently, the quadratic term for a scalar field*ϕi*is written as*ϕiϕ*
†*i*. If*ϕi*carries*SU(3)*and/or*SU(2)*charges, each
component field within*ϕi*is also normalized canonically.
*⋆*When writing terms in the Lagrangian, the package does not introduce any numerical factors in front of the corresponding coupling coefficients. Therefore, if a scalar field is real, such as*(1, 1,*0), the package does not include the conventional factor of*1/2*multiplying the quadratic term. Similarly, no numerical factors are inserted in front of cubic or quartic interaction terms.
*⋆*When comparing results, the user should be aware that the package may employ phase conventions different from their own. For example, under a rephasing of a component field,
*ϕα i*→*eiφαϕα*
*i ,*
where*α*labels a component field, the canonical normalization remains unchanged. Although different users may adopt different phase conventions, the physical predictions remain identical.
*⋆*The package lists only independent terms in the Lagrangian; redundant or dependent terms are never included. Consequently, when more than one independent term exists for a given operator structure, comparisons between expanded expressions must be performed with care. For example, suppose the package identifies two independent quartic couplings,*λk,c1*and*λk,c2,*for a scalar field*ϕi.*If, in a different convention, the user instead works with couplings*λk*and*λ′*
*k,*then the two sets of parameters are related through a linear transformation,
*λk*=*A1λk,c1 +B1λk,c2, λ′ k*=*A2λk,c1 +B2λk,c2,*
where*Ai*and*Bi*are numerical coefficients.

**IX Conclusion**We have introduced a framework that combines AI-driven natural-language interaction with symbolic BSM model building. The main novelty of this work is that the user only needs to specify the quantum numbers of the new fields in natural language, after which the framework automatically constructs and analyzes the corresponding renormalizable Standard Model extension. From this minimal input, the package performs the core symbolic stages of model building, including operator generation, anomaly checks, electroweak symmetry breaking, and tree-level mass-matrix extraction. The examples presented throughout the paper demonstrate that sophisticated modelbuilding tasks can be carried out with substantially reduced user effort compared to traditional workflows.
More broadly, this work illustrates a practical paradigm for integrating large language models into scientific software. Rather than replacing established symbolic calculations, the LLM serves strictly as an interface and orchestration layer between the user and a deterministic computational engine. This separation preserves transparency, reproducibility, and scientific rigor while making advanced model-building tools more accessible to researchers and students. In this sense, bsm_agent fills a distinct niche in the BSM software ecosystem: it automates the preimplementation stage of model building, transforming a specification of new field quantum numbers into a reproducible symbolic model analysis without requiring the user to manually enumerate the operator content of the theory. The package is freely available at § bsm_agent and is built entirely on open-source software.
**Future directions.**Future developments include support for even higher-dimensional SM representations beyond those currently implemented, additional gauge groups such as Pati–Salam,*SU(5),*and*SO(10),*incorporating discrete and continuous global symmetries, higher-dimensional operators, and the extension of the framework to supersymmetric theories. Further developments may also include more automated phenomenological analyses.
