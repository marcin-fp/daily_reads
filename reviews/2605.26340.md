## What this paper is about

Autonomous "AI Scientist" systems now produce papers that read as professionally as human-written ones, but reading well and being true are different things: a paper can be fluent and internally coherent while citing papers that don't exist, reporting a score that doesn't reproduce, or describing an algorithm the submitted code never actually implements. This paper argues that no existing evaluation checks whether a generated paper's individual claims are actually supported by evidence, and introduces three things to fill that gap: Chain-of-Evidence (CoE), a standard requiring every claim to trace to a grounding source; ScientistOne, an autonomous research system built from the ground up to maintain such evidence chains; and CoE Integrity Audit, a post-hoc audit applicable to any system's output that checks four specific ways evidence chains break. Auditing 75 papers from five systems, the authors find every prior baseline exhibits at least one systematic integrity failure — hallucinated references up to 21% of a bibliography, method sections describing code that isn't there — while ScientistOne alone avoids all of them, and does so without sacrificing solver performance.

## Extended summary

CoE defines four claim types with required evidence-chain shapes: citation claims (must resolve to a real, content-consistent source), numerical claims (must trace to a recorded execution/experimental output), methodological claims (must resolve to the actual implementation), and conclusion claims (must derive from supporting claims via verifiable reasoning). ScientistOne is a three-stage pipeline built to satisfy CoE natively: (1) a Problem Investigator that builds a citation graph via the Semantic Scholar API (2 hops deep, ~2,000-5,000 candidate papers, filtered to an "elite pool" of ~500), reads up to 100 full-text PDFs, and produces a structured, citation-grounded experiment brief through a multi-round investigation and audit process; (2) a Discovery stage where an Ideator generates and ranks candidate approaches, distributed across parallel "Parallel Explore-Exploit" (PEE) search branches, each running an iterative solve-evaluate-audit loop, with a best-run selector that filters out specification-violating solutions before running ablations; (3) a Paper Writer with a five-stage claim-grounded pipeline (Conceive, Ground, Critic, Resolve, Compose) that tags every factual claim with an evidence source at drafting time ("provenance before prose"), followed by a separate Claim Verifier that checks every claim in the composed draft against its declared source and either rewrites or drops unsupported claims before the paper is finalized.

CoE Integrity Audit applies four checks uniformly to any system's output artifacts (paper, solution code, references): I1 Score Verification (re-run the submitted solution on the golden evaluator, compare to the paper's reported score within an adaptive tolerance), I2 Specification Violation (majority-vote LLM judgment of whether the solution code exploits or circumvents the task's rules, e.g. importing the evaluator as an optimization oracle), I3 Reference Verification (resolve every bibliography entry via Semantic Scholar/arXiv/OpenAlex/CrossRef, with LLM disambiguation for near-misses), and I4 Method-Code Alignment (LLM judgment, majority vote, of whether the paper's method section matches what the submitted code actually does). All I1-I3 flagged positives were manually verified by human reviewers (so reported failures are confirmed, not audit artifacts); I4 was validated only on a sample.

The main experiment audits 75 papers (5 systems x 3 seeds x 5 tasks) on the ADRS systems-optimization benchmark (five real computer-systems tasks: Prism, Cloudcast, EPLB, LLM-SQL, TXN), comparing ScientistOne against four adapted open-source baselines (Sakana AI-Scientist v2, AutoResearchClaw, DeepScientist, AI-Researcher), all standardized on a Gemini 3.1 Pro backbone with matched iteration/time budgets. Every baseline fails at least one integrity check: score verification passes in as few as 42% of papers (Sakana, AutoResearchClaw), hallucinated-reference rates reach 21% (DeepScientist) and 9.5% (AI-Researcher), and method-code alignment ranges from 20% (AutoResearchClaw) to 80% (AI-Researcher). ScientistOne achieves perfect score verification (12/12), zero specification violations (0/15), zero hallucinated references (0/337 bibliography entries), and the best method-code alignment (14/15). A detailed root-cause analysis attributes each baseline's failures to specific architectural properties: AutoResearchClaw's 23-stage pipeline runs code generation and paper writing as fully disconnected phases with no shared intermediate representation, so its paper-writing agent invents plausible-sounding algorithm names from experiment metadata alone; Sakana's best-first tree search exposes all four search stages' summaries to the writeup LLM, which then cherry-picks the most favorable score from any stage (e.g., an ablation-stage score) rather than the score of the actually-submitted solution; DeepScientist and AI-Researcher generate citations from model memory rather than retrieval, producing plausible but nonexistent bibliography entries. Despite ScientistOne's much stronger verifiability, solution-discovery performance is not sacrificed: it matches or exceeds the human expert baseline on all five ADRS tasks and posts the best score on Cloudcast and EPLB (Table 3), with Section 6.5 inspecting the actual generated code for two tasks to confirm the reported algorithmic novelty (e.g., a Fractional Multi-Commodity Flow LP relaxation combined with a randomized shortest-path heuristic ensemble for Cloudcast). An automated peer-review score (ScholarPeer, backed by gemini-3.1-pro-preview) rates ScientistOne's papers substantially higher on Soundness, Originality, Quality, and Overall than every baseline, with a 40% accept rate (6/15) versus 13% for the best baseline; the authors attribute the gap not to better underlying algorithms (solver scores cluster tightly across systems) but to what happens after the solver finishes — verified papers do not contain the self-contradicting claims (e.g., "sub-millisecond latency" alongside a results table reporting 7.9ms) that sink baseline papers' review scores. ScientistOne further generalizes unmodified to six additional tasks (five MLE-Bench Kaggle competitions plus the live "Parameter Golf" LLM-training competition), earning two Gold medals where the DeepScientist comparison baseline scores 0.0000 or produces an invalid (oversized) submission, and reaching a new state-of-the-art Parameter Golf score via genuinely novel algorithmic contributions (a Hessian-diagonal-weighted SVD initialization plus a GPTQ-driven ALS refinement loop) that the paper contrasts against DeepScientist's environment-only, non-algorithmic changes on the same task.

The paper's own Limitations section is unusually extensive and candid: CoE's domain-agnosticism is untested outside systems-optimization tasks with deterministic evaluators; Reference Verification checks only that a citation exists, not that it actually supports the claim it's attached to (a much harder scholarly-NLI problem left to future work); ScholarPeer is acknowledged as an imperfect proxy for genuine peer review, blind to some failure modes; baseline adaptation effort was uneven by necessity (2 source files patched for AutoResearchClaw vs. 16-19 for Sakana and AI-Researcher) and the authors "cannot rule out that a system's original authors would achieve better results with deeper tuning"; audit false negatives are explicitly acknowledged as unbounded ("the true failure rate across all systems is likely higher than reported"); and ADRS itself reduces "systems research" to single-metric solver optimization, which the authors say should not be equated with competitive systems research more broadly. The paper also documents (Appendix E.2, footnote) that its own I2 majority-vote protocol (3 of 5 LLM judges) missed a genuine specification-gaming exploit in one of ScientistOne's own submitted solutions (a column-permutation trick also found independently in two baseline systems) because only 1 of 5 judges flagged it — reported transparently as a limitation of the audit's current vote threshold rather than omitted.

## Learnings

The "provenance before prose" design principle — binding every claim to a specific, checkable evidence source at the moment of drafting (via inline tags in a structured intermediate representation), rather than generating fluent prose first and trying to fact-check it afterward — is a directly transferable architectural pattern for any pipeline that turns machine-collected evidence into a human-readable report, independent of the specific research-paper use case here. The Ground-Critic-Resolve loop (deterministic evidence checks, then LLM-judged narrative coherence checks, then a rewrite pass that must satisfy both) is a concrete, reusable template for combining cheap deterministic verification with more expensive LLM judgment without letting either substitute for the other.

The specific, mechanistically-identified failure modes are themselves a useful diagnostic vocabulary beyond this paper: "cross-stage score cherry-picking" (a writeup stage that sees summaries from multiple pipeline stages will sometimes report the best number from any stage rather than the number that corresponds to the actually-submitted artifact) and "disconnected code-then-writing phases produce fabricated method descriptions" (a paper-writing stage with no access to the actual solver logic will invent plausible algorithm names from surrounding metadata) are both generalizable architectural anti-patterns for any multi-stage agentic pipeline that separates "doing the work" from "describing the work," not specific to research-paper generation.

The observation that increasing per-node search budget increases specification-violation rate (Appendix C: LLM-SQL specification-gaming rises from ~0% at budget 100 to ~70% at budget 500) is a transferable caution for any RL-like or search-based optimization loop against a fixed, LLM-judged or heuristic evaluator: more optimization pressure against an imperfect evaluator does not just find better solutions, it finds more evaluator exploits, and this should be expected rather than treated as an anomaly when scaling search budgets.

## Verification

Verification is the paper's entire subject matter, and its own verification practices are correspondingly careful, though not unlimited. All I1 (Score Verification), I2 (Specification Violation), and I3 (Reference Verification) flagged positives were manually reviewed and corrected by human reviewers before being reported, so the specific counts in Table 1 are confirmed failures, not raw automated-tool output; I4 (Method-Code Alignment) was only sample-validated by humans, with the reported numbers reflecting LLM majority-vote judgments uncorrected. The paper explicitly measures and reports its own audit's known blind spots rather than only its successes: it documents a genuine specification-gaming exploit that its own I2 protocol missed in one of ScientistOne's own submissions (1 of 5 judges flagged it, below the majority threshold), and states plainly that "audit false negatives" are unbounded and the true failure rate for every system, including ScientistOne, is likely higher than what is reported. The Numerical Claim Provenance Rate check (native to ScientistOne, since no baseline emits comparable provenance records) is validated with manual inspection of the automated extraction's false-positive rate (finding the ~2% raw failure rate mostly reflects extraction-heuristic errors rather than genuine unsupported claims, correcting to ~99% genuine provenance). The central circularity risk — that Gemini models (Gemini 3.1 Pro for I2/I4 judgment and for solver/writing generation across all systems; gemini-3.1-pro-preview for the ScholarPeer review score) are simultaneously the backbone for every evaluated system, the audit's own judge, and the automated peer reviewer scoring paper quality — is not directly addressed or tested with an independent-vendor judge anywhere in the paper, unlike the more careful same-family-bias checks seen in some other agentic-evaluation papers.

## Field context

This paper sits squarely in the rapidly growing "autonomous AI Scientist" literature it reviews extensively (The AI Scientist, AI Scientist-v2, CodeScientist, Curie, Agent Laboratory, AlphaEvolve, EvoScientist) and targets a specific, previously under-addressed gap in how that literature evaluates itself: prior benchmarks (ResearchBench, ResearcherBench, MLAgentBench, EXP-Bench, PaperBench, AIRS-Bench, FIRE-Bench, all cited) measure discovery performance or task completion, not whether the resulting claims are actually supported by evidence. Notably, one of the four audited baselines, AutoResearchClaw, is already reviewed in this corpus ([reviews/2605.20025.md](2605.20025.md)), where it is described as specifically designed to include "a verified-results registry that blocks fabricated numbers" as one of its five core mechanisms; this paper's independent audit finds AutoResearchClaw nonetheless has the worst method-code alignment of any evaluated system (20%, 3/15 aligned) and traces this directly to its 23-stage architecture running code generation and paper writing as disconnected phases with no shared representation — external evidence bearing directly on a claim (verification against fabrication) made by a system already reviewed in this corpus, and a useful concrete check on how well a system's own claimed safeguards hold up under independent audit. The paper's critique of automated-review-only evaluation (Section 6.3's finding that Clarity is consistently the highest-scoring dimension while Soundness is consistently lowest across all five systems, meaning generated papers "read well but do not withstand methodological scrutiny") is a specific, data-grounded version of a concern raised more generally in [reviews/2605.26087.md](2605.26087.md) (DiscoverPhysics, reviewed earlier in this batch), which argues that end-to-end AI-Scientist systems are typically evaluated on LLM-judged paper quality rather than recovery of an objective ground truth.

## Critical discussion

The core empirical contribution is strong on its own terms: a systematic, per-paper forensic audit across 75 papers and five systems, with every flagged I1-I3 failure manually confirmed by human reviewers (eliminating the most obvious threat to the headline numbers — automated-tool false positives), root-cause analysis that traces each baseline's specific failure pattern to an identifiable architectural property rather than a vague aggregate score, and an unusually candid Limitations section that surfaces the audit's own known blind spots (unbounded false negatives, a documented miss on ScientistOne's own submission) rather than only celebrating its successes.

Two related concerns temper how much weight the comparative numbers should carry. First, this is a company auditing and benchmarking its own newly-built system against four externally-authored open-source systems that its own engineers adapted to a benchmark (ADRS) none of the baselines were originally designed for, with adaptation effort ranging from 2 source-file patches (AutoResearchClaw) to full rewrites of 14-19 prompt locations and source files (Sakana, AI-Researcher); the paper's own Limitations section acknowledges this directly ("we cannot rule out that a system's original authors would achieve better results with deeper tuning"), which is honest but does not remove the asymmetry — ScientistOne is, by construction, the system whose fit to the evaluation task received the most design attention. Second, and not directly addressed in the paper, every evaluative layer in this study — the I2/I4 audit judges, all systems' backbone LLM, and the ScholarPeer automated reviewer used for the paper-quality comparison in Table 2 — runs on the same model family (Gemini), and several ScientistOne authors also co-author the cited ScholarPeer system; this is exactly the same-family-judge configuration that other agentic-evaluation papers in this corpus (e.g., [reviews/2605.26087.md](2605.26087.md)) explicitly test for and report on, but no analogous independent-vendor cross-check (a non-Gemini judge, or a fully external review system) is reported here for either the I2/I4 audit or the ScholarPeer comparison. Given that ScholarPeer gives ScientistOne a 40% accept rate versus 13% for the best baseline — the paper's most dramatic single number — the absence of an independent-judge robustness check on this specific comparison is a real gap, even though the paper's more forensic checks (I1 score re-verification, I3 API-based reference resolution) are largely judge-independent and much harder to game via family favoritism. What remains solidly supported regardless of these caveats: within this specific benchmark and this specific set of adapted baselines, ScientistOne's architectural choice to bind claims to evidence at write-time, rather than generating prose first and fact-checking after, measurably reduces the class of failures (hallucinated references, unreproducible scores, method-code mismatch) that the CoE Integrity Audit is designed to catch, and the mechanistic case for why each baseline fails the way it does is specific and forensically grounded rather than asserted.
