The Last Human-Written Paper: Agent-Native Research Artifacts. arXiv preprint arXiv:2604.24658, 2026.

## What this paper is about

A published paper compresses months of branching, trial-and-error research into a single linear narrative for human readers, discarding almost everything that was tried and rejected along the way. This paper argues that compression, tolerable when a human is the only consumer, becomes actively costly once AI agents are the ones reading papers to understand a field, reproducing experiments to check them, and extending published methods, because agents specifically need the material narrative compilation throws away: exact configurations, the reasoning behind design choices, and a record of what was already tried and failed. The authors propose replacing the PDF as the primary research object with the Agent-Native Research Artifact (ARA): a structured, four-layer, machine-executable package (a layer of falsifiable scientific claims, a layer of executable code, a layer preserving the branching exploration history including dead ends, and a layer of raw evidence grounding every claim) that an agent can query and run directly rather than parse from prose. Around this format they build three supporting mechanisms — a background "Live Research Manager" that is meant to capture a researcher's decisions and dead ends automatically during ordinary agent-assisted work; a "Compiler" that retroactively converts existing PDFs, repositories, and supplementary material into an ARA; and a three-level "Seal" verification protocol meant to let automated checks handle mechanical review so human reviewers can focus on judgment — and evaluate the resulting artifacts against the conventional PDF-plus-repository baseline on three tasks: extracting knowledge, reproducing results, and extending prior work.

## Extended summary

The paper opens by quantifying two costs it names the Storytelling Tax and the Engineering Tax. The Storytelling Tax is measured on the METR eval-analysis-public dataset (24,008 agent runs across 21 frontier models on RE-Bench): failed runs account for 90.2% of total dollar cost and 59.2% of tokens, with a median failed-to-success token ratio of 113×, meaning most of the compute that produces a finished result is spent on exploration a published artifact discards entirely, forcing every subsequent agent to rediscover the same dead ends from scratch. The Engineering Tax is measured by classifying all 8,921 expert-authored reproduction requirements from PaperBench's 23 ICML 2024 papers against their source PDFs: only 45.4% are fully specified, code development is the least-specified category (37.3% sufficient), and missing hyperparameters alone account for 26.2% of all identified gaps.

The ARA protocol organizes a research project into four layers rooted in a manifest file that lets an agent triage relevance in roughly 500 tokens. The Cognitive Layer (/logic) holds the problem statement, solution architecture, falsifiable claims with explicit proof pointers, the verification plan, and a "typed dependency" version of related work (imports, bounds, baselines) that an agent can act on rather than just cite. The Physical Layer (/src) holds executable code, using a lightweight "kernel mode" (only the core modules, with typed I/O, for algorithmic contributions) or a full "repository mode" (annotated via a manifest, for systems contributions), plus a configs directory annotating every hyperparameter with its rationale and search range. The Exploration Graph (/trace) stores the research process itself as a typed, nested directed acyclic graph with five node kinds (question, decision, experiment, dead_end, pivot), explicitly preserving the hypothesis, failure mode, and lesson behind every abandoned direction. The Evidence Layer (/evidence) holds only raw outputs (results tables, logs), kept separate from the other layers specifically so a verification agent can be given the code and claims while the evidence is withheld, preventing it from fabricating a result by simply copying an expected value it was shown. Cross-layer "forensic bindings" link claims to the experiments that test them and the code and evidence that support them.

Because requiring researchers to hand-author these structured files would just replace one documentation burden with another, the Live Research Manager is proposed to populate the artifact as a side effect of ordinary AI-assisted research: it runs as a background agent skill, silently reading a researcher-agent conversation at each session boundary through a three-stage pipeline (a Context Harvester extracting research-significant events, an Event Router classifying each into one of seven typed categories and tagging it with provenance — user, ai-suggested, ai-executed, or user-revised — and a Maturity Tracker promoting staged, tentative observations into formal artifact entries only once a "closure signal" such as explicit researcher affirmation, empirical resolution, or downstream artifact commitment indicates the point has actually been settled, rather than on an arbitrary reference-count threshold). The ARA Compiler serves the complementary, backward-looking need: an agent skill that ingests any combination of a legacy PDF, code repository, expert-authored rubric, or recorded experiment trajectory and produces a single conforming ARA through four ordered stages (Semantic Deconstruction strips narrative framing into fact-dense telegraphic content; Cognitive Mapping populates /logic; Physical Grounding populates /src, including "code-paper reconciliation" that cross-references an available codebase against the paper's claims to surface undocumented tricks; Exploration Graph Extraction reconstructs the research DAG), with a generate-validate-fix loop against structural checks that the paper reports typically converges in 2-3 rounds.

Verification is organized as a three-level "ARA Seal": Level 1 (Structural Integrity) is a deterministic, seconds-scale check that the artifact's schema is well-formed and every cross-layer reference resolves. Level 2 (Argumentative Rigor) is a minutes-scale check, performed without running any code, by a "Rigor Auditor" LLM agent scoring the artifact along six rubric-anchored dimensions (evidence relevance, falsifiability quality, and methodological rigor are the three the paper foregrounds), producing severity-tagged findings rather than a bare grade. Level 3 (Execution Reproducibility) is an hours-to-days-scale check in which a sandboxed agent, deliberately isolated from the artifact's evidence layer and never shown the paper's reported numbers, runs scaled-down directional checks (small data, few epochs) on the artifact's most critical claims under a venue-specified compute budget, reporting whether a claimed direction (for example, "method A beats baseline B") holds rather than reproducing an exact number. Passing levels issue a machine-checkable Seal Certificate. These three levels are proposed to gate a three-stage review pipeline in which conceptual and empirical verification happen before a submission ever reaches a human reviewer, whose role then shifts from checking whether the code runs or the numbers match to judging significance, novelty, and taste.

The evaluation compares ARA against a conventional PDF-plus-repository baseline, holding the underlying research fixed, across three layers. In the Understanding experiment (450 paired Q&A across 30 targets — 23 PaperBench papers and 7 RE-Bench tasks — in three question categories, graded ternary by a blinded Claude Opus 4.6 judge against a gold reference), ARA wins overall 93.7% to 72.4%, with the gap driven by three distinct mechanisms: a +14.8-point win on facts recoverable from the PDF (attributed to targeted file lookup replacing linear scanning, using 12% fewer tokens), a +24.8-point win on configuration details PaperBench's rubric supplies but the PDF omits, and a +65.7-point win on RE-Bench failure-knowledge questions the baseline has no source for at all. In the Reproduction experiment (150 curated subtasks across 15 papers with companion repositories, 1,743 rubric requirements, expected numbers masked to prevent parroting, scored yes/partial/no by a blinded Opus 4.6 judge), ARA reaches a difficulty-weighted success rate of 64.4% versus 57.4% for the baseline, with the gap widening from +4.9 points on easy subtasks to +8.5 points on hard ones; fabricated results occurred in 2 of the baseline's runs and 1 of ARA's. In the Extension experiment (5 open-ended RE-Bench hill-climbing tasks, comparing an ARA carrying real MALT agent failure traces against an LLM-synthesized paper-style writeup of the same reference solution, both run under Claude Sonnet 4.6 with an 8-hour/$50 budget), the ARA agent reaches a useful first move earlier on every task and finishes with the better score on 3 of 5, but the paper agent overtakes on 2 of 5 by inventing moves the trace never names (an int8 kernel-compression idea; committing fully to a single architecture rather than trying every trace-named alternative); repeating the same two tasks under the weaker Sonnet 4.5 base model reverses the outcome in ARA's favor on both, leading the authors to interpret the artifact's marginal value as scaling with the gap between what the trace documents and what the consuming agent can discover unaided. A separate review-system evaluation stress-tests the Seal mechanism itself: the Rigor Auditor is benchmarked via a mutation test (23 ARAs seeded with 5 known defect types each, 115 total injections, an authored injection manifest serving as ground truth with no human annotation needed), catching 100% of three high-severity defect types and 91% of missing-falsification cases but only 22% of "orphan experiment" injections, alongside two named LLM-as-judge pathologies the authors report rather than suppress: grade inflation (in 17 of 23 ARAs the auditor's mean score is rounded up just enough to clear the accept threshold) and finding-score decoupling (a correctly-flagged critical finding does not lower the corresponding dimension score by the amount the rubric prescribes).

The Related Work section situates ARA against machine-readable-science standards (FAIR, RO-Crate, nanopublications, PROV-O, the Open Research Knowledge Graph, Whole Tale), arguing each covers at most two of five properties the paper considers necessary (structured logic, executable code, exploration trajectory, grounded evidence, and cross-layer bindings); against reproducibility infrastructure (workflow engines, computational notebooks) as encoding pipelines without claim semantics; against a growing "negative knowledge" literature showing raw failure trajectories are hard to use without root-cause structure, and that large hyperparameter-search logs already retain far more search history than the papers reporting them ever disclose; and against post-hoc paper-to-code and knowledge-graph recovery pipelines and fully autonomous end-to-end research-agent systems, both of which the paper argues discard or never capture the target work's own decision history because they operate after, rather than during, authorship. The Limitations section states three bounds plainly: the evaluation covers only machine learning, where computational reproducibility fits the four-layer structure naturally, and generalization to experimental or physical sciences is explicitly untested; ARA's fidelity is bounded by whatever the source material actually contains, so the Compiler cannot recover what a PDF never stated, and the Live Research Manager's central promise assumes an AI-native workflow the paper does not evaluate with real researchers; and stated "deployment prerequisites" — sandboxed execution, access control for the exploration graph, and a stable schema-migration story for a long-lived format — are acknowledged as aspirational and not yet implemented.

## Learnings

Classifying an expert-authored reproduction rubric's leaf requirements against their source PDF, by category (missing hyperparameter, vague description, cross-reference only, missing baseline detail, and so on), turns a vague, familiar complaint ("papers are underspecified") into a measured, typed gap analysis that identifies exactly which categories of information a structured format should prioritize recovering, rather than assuming structure alone would help. The paper's own numbers (45.4% fully specified overall; missing hyperparameters alone accounting for 26.2% of gaps) are a directly reusable methodology for auditing any other benchmark's or field's own reproduction rubric the same way.

The Extension-task result is a genuinely double-edged, worth-remembering finding on its own terms: handing an agent a documented record of a prior agent's failures gives it a real head start on every task tested, but on the two tasks where the consuming model was independently capable enough to invent a better move the record never named, following the record faithfully anchored it to a documented-but-suboptimal strategy — and the same comparison, repeated with a weaker base model on the same two tasks, reversed in the record's favor. Preserved failure knowledge is not an unconditionally good input to hand a reasoning agent; its marginal value is conditional on the gap between what the record documents and what the consuming agent could discover unaided, and a highly capable agent can be anchored by a documented-but-suboptimal record it would otherwise have surpassed.

Isolating an automated verifier from a system's ground-truth answer layer (giving it only code and method descriptions, never the reported numbers or expected outcomes) while still scoring it on whether a claimed direction of a result holds, is a concrete, general-purpose way to block an automated check from "passing" simply by reproducing the number it was shown — a specific instance of the broader principle that a verifier's own inputs, not only its outputs, need to be constrained for its grade to mean anything.

## Verification

Verification is close to this paper's central subject, and it is treated with real self-scrutiny in at least one place: the Level 2 Rigor Auditor is benchmarked with a mutation test against a hand-authored ground-truth injection manifest (23 artifacts seeded with 5 known defect types each, 115 total cases), which avoids the need for human annotation and lets the paper report the auditor's own blind spot (22% detection on "orphan experiment" injections, versus 91-100% on four other defect types) and two specific, named LLM-as-judge pathologies (grade inflation and finding-score decoupling) as findings rather than omissions. The Level 3 execution-reproducibility design applies a specific, sound anti-fabrication mechanism: the verifying agent never sees the artifact's reported numbers, only its code and method descriptions, and is scored on whether a claimed direction holds under a bounded compute budget rather than on exact numerical recovery; the paper reports, rather than hides, that fabrication still occurred once in an ARA-based reproduction run and twice in baseline runs even with this masking in place, concluding plainly that "structured artifacts reduce but do not eliminate hallucinated results." The Understanding and Reproduction experiments both use a blinded LLM judge (Claude Opus 4.6) scored against a gold reference or expert rubric, with expected numerical results masked in agent prompts specifically to prevent parroting. What is not verified anywhere in the paper is the Live Research Manager itself: every ARA used in every reported experiment (Understanding, Reproduction, Extension) is produced by the Compiler from already-finished source material — published PDFs and repositories, or RE-Bench reference solutions and MALT transcripts — not captured live by the Manager from an actual, ongoing researcher-agent collaboration. The Manager's stated central property, silently and faithfully capturing a real project's decisions and dead ends at "negligible marginal cost" via closure-signal-based promotion, is therefore a design specification with no reported experiment testing whether it holds in practice, a materially different epistemic status from the Compiler and the Seal, both of which are evaluated directly against a real corpus.

## Field context

The paper positions ARA against several distinct prior lines of work rather than as an incremental refinement of any single one. Against machine-readable-science standards (FAIR, RO-Crate, nanopublications, PROV-O, the Open Research Knowledge Graph, Whole Tale, and the emerging AGENTS.md convention for agent-oriented repository documentation), it argues, via a comparison table, that each covers at most two of five properties it considers jointly necessary (structured scientific logic, executable code, exploration trajectory, grounded evidence, and explicit cross-layer bindings between them), positioning ARA as the first to jointly structure all five. Against reproducibility infrastructure (workflow engines such as Snakemake and Nextflow, computational notebooks), it argues these encode execution pipelines without claim semantics, so they preserve how to run something without preserving why or what was concluded from it. Against a growing "negative knowledge" literature on failure traces, it cites evidence that raw trajectory dumps are hard to use without root-cause annotation, and that large-scale hyperparameter-search and architecture-search logs already retain vastly more search history than the papers reporting them ever disclose — a point the paper uses to argue the raw material for failure-aware research already exists at scale, just disconnected from the claims it could inform. Against post-hoc paper-to-code and knowledge-graph recovery pipelines (which the paper credits with real, measured gains, up to 10.9 percentage points on PaperBench in one cited approach) and against fully autonomous end-to-end research-agent systems (AI Scientist, ResearchAgent, Agent Laboratory), it argues both classes of system operate on or produce unstructured trajectories that are themselves discarded once a paper is written, the same fate ARA is built to prevent by capturing structure at authoring time rather than recovering it afterward. The paper also draws on independently reported figures from adjacent benchmarks to corroborate its own diagnosis rather than relying solely on its own numbers — for instance, a cited benchmark reporting only 0.5% end-to-end experiment success despite 20-35% component-level accuracy, and a cited paper-code alignment study finding LLMs detect fewer than 46% of discrepancies between a paper and its code. None of these specific precedents (PaperBench, RE-Bench, RO-Crate, nanopublications, EXP-Bench) are yet reviewed in this corpus, and this is the first paper reviewed here proposing a new format or protocol for the scientific paper itself, as distinct from a benchmark, a trained model, or an architecture case study.

## Critical discussion

The Live Research Manager is, by the paper's own framing, the mechanism that matters most for whether this protocol could ever become how research is actually produced going forward, since the Compiler only converts material that has already been written and finished. It is also the one mechanism never evaluated: every ARA used across all three evaluation layers is compiled after the fact from existing, already-published or already-logged material (PaperBench PDFs, repositories, and rubrics; RE-Bench reference solutions and MALT transcripts), not captured live from a real ongoing researcher-agent session. The paper's own central claim for the Manager — that it captures decisions and dead ends silently, faithfully, and at "negligible marginal cost" via closure-signal-based promotion — is therefore a design specification supported by no experiment in this paper, a meaningfully weaker epistemic status than the Compiler and the Seal, both of which are tested directly against a real corpus with concrete failure modes reported.

Even the best-supported claims rest on a narrow evaluation corpus that the paper itself does not overstate: 23 papers from a single venue and year (ICML 2024, plus two NeurIPS 2024 workshop papers) and 5 to 7 RE-Bench tasks, entirely within machine learning, evaluated using a single model family (Claude) for every role — the agents under test, the compiler, the reproduction judges, and the rigor auditor. Both the Understanding and Reproduction judges are Claude Opus 4.6, scoring outputs produced primarily by Claude Sonnet 4.6 agents; the paper does not report a cross-family judge check or an independent human-expert validation of judge accuracy the way it does for the Rigor Auditor's mutation benchmark, so the headline 93.7%-vs-72.4% and 64.4%-vs-57.4% numbers rest on an unaudited same-family automated judge for their central comparisons, even though the paper's overall design otherwise shows real attentiveness to exactly this class of concern (evidence isolation for Level 3, masked numerical answers, blinded grading).

The Extension experiment is reported with unusual candor, including the two tasks where the baseline wins and the model-dependent reversal under a weaker base, which is a genuine strength; it also means the paper's single most ambitious claim — that preserved failure knowledge "accelerates progress" on genuinely open-ended extension — holds unambiguously on 3 of 5 tasks under the stronger tested model, is a documented anchoring cost on the other 2, and the paper's own explanation (marginal value scales with the gap between what the trace documents and what the agent can discover unaided) is an informed post-hoc reading of a 5-task, 2-model result rather than something independently varied and tested. Relatedly, since RE-Bench tasks have no genuine published paper, the Extension experiment's baseline "paper" is itself an LLM-synthesized writeup of the same underlying reference solution the ARA condition also draws on — a controlled and clearly-described way to isolate the trace's specific contribution, but a comparison against an idealized synthetic writeup rather than a real, historically messy published paper, which could plausibly make either condition a more or less generous stand-in for what an agent extending an actual paper would receive in practice.

The paper's own mutation-benchmark test of its central automated-review mechanism surfaces a real, admitted weakness worth weighing against the mechanism's stated purpose: a 22% detection rate on orphan-experiment injections, plus grade inflation in 17 of 23 cases and a documented finding-score decoupling pattern, together describe a review gate that reliably catches roughly four of five injected defect types and whose numeric grades do not consistently track its own qualitative findings — a meaningfully less airtight "resolve the mechanical issues before a human reviewer engages" step than the paper's framing of Level 2 might suggest on first read, even though the paper reports this limitation itself rather than obscuring it.

What remains supported after these caveats: the underlying diagnosis is grounded in a concrete, sourced quantitative analysis rather than merely asserted (measured PaperBench rubric under-specification; measured RE-Bench cost and token concentration in failed runs); the format, compiler, and three-level Seal are each tested with a specific, describable protocol against a real conventional baseline, with exceptions (fabrication cases, the orphan-detection blind spot, the two Extension-task reversals) reported rather than smoothed over; and the paper is explicit, in its own Limitations section, about exactly which parts of the proposed ecosystem — generalization beyond machine learning, the Live Research Manager's real-world operation, and production-grade sandboxing and access control — remain untested or unbuilt, rather than implying the full vision has already been validated end to end.

## Relevance to us

This paper is about the format of scientific communication rather than physics reasoning specifically, but several mechanisms map directly onto our own interests in verification and agent orchestration. The Level 3 design — isolate a verifying agent from a system's ground-truth evidence, check whether a claimed direction holds rather than demanding exact numerical recovery, and cap the check with an explicit compute budget — is a clean instance of the "constrain the verifier's inputs, not only grade its outputs" principle central to our own verification thinking, worth citing as an example drawn from outside our usual ML-benchmark literature. The Rigor Auditor's mutation-benchmark self-test (inject known defects, measure detection against the injection manifest, and report the detector's own blind spots and judge pathologies honestly rather than only its successes) is a directly reusable template for validating any automated critic or judge we build ourselves, independent of this paper's specific reviewer or domain. The Extension-task finding — that a documented failure record can genuinely accelerate a weaker agent while anchoring a stronger one to a documented-but-suboptimal strategy it would otherwise have surpassed — is a concrete, if narrow, data point for our own thinking about how much "here is what was tried before" context to hand a reasoning agent on a hard, open-ended problem: more prior-attempt context is not free, and its value is conditional on the gap between what the record documents and what the consuming agent could discover unaided, a nuance worth keeping in mind whenever we design a similar scaffold for our own agents.
