Citation: Ji, S., Li, Y., Hooi, B. Memory is Reconstructed, Not Retrieved: Graph Memory for LLM Agents. Proceedings of the 43rd International Conference on Machine Learning (ICML), Seoul, South Korea, PMLR 306, 2026. https://arxiv.org/abs/2606.06036v1

## What this paper is about

Most memory systems for LLM agents treat recall as a one-shot lookup: given a question, fetch the most similar stored text (or expand a fixed number of graph hops from a matched node) and hand it to the model. Cognitive neuroscience instead describes human memory retrieval as active and reconstructive — a cue triggers a partial reactivation that progressively reveals more of a coherent memory across several steps, not a single readout. This paper builds MRAgent, a memory system that takes that reconstructive view literally: memory is organized as a Cue-Tag-Content graph where "tags" act as an explicit semantic bridge between fine-grained cues and stored content, and an LLM iteratively reasons over this graph, expanding and pruning candidate paths based on what it has found so far, rather than retrieving everything up front. The paper backs this with both a theoretical argument (adaptive retrieval strictly out-expresses non-adaptive retrieval, given at least two retrieval steps) and empirical results on two long-memory benchmarks, where MRAgent beats several established memory systems while using fewer tokens and less time.

## Extended summary

The paper formalizes two retrieval policy classes: a passive policy that selects all memory units to retrieve as a fixed function of the query alone, and an active policy that selects each next unit conditioned on the evidence accumulated from previous retrieval steps. It argues existing memory systems, despite sometimes using graph structure (A-Mem, Zep), are passive in this sense — they perform similarity-based seeding followed by a predefined N-hop neighbor expansion, which either introduces irrelevant neighbors or simply fails to find evidence that is not directly graph-connected to the query's surface features (illustrated with a worked example where a question about "Caroline's activity in July" cannot be answered by graph expansion from "video game tournament" nodes, since the relevant fact is not linked to that surface cue at all).

MRAgent's memory is a heterogeneous graph with Cue nodes (fine-grained keywords/entities), Content nodes (episodic events, semantic facts, or topic-level abstractions), and typed Tag relations connecting them; tags let the LLM select a small set of promising associative directions before touching the more expensive content nodes, avoiding the combinatorial blow-up of exhaustively expanding neighbors. Memory is populated via an LLM distillation pipeline that segments dialogue into episodic units and extracts a tag plus fine-grained cues per unit (and similarly for semantic and topic-level nodes), organized into three layers: an Episodic layer (Cue-Tag-Episode, temporally ordered concrete events), a Semantic layer (Cue-Tag-Semantic, stable facts/preferences anchored to entity cues), and an Abstraction layer (Topic nodes summarizing recurring patterns across episodes, supporting top-down localization before descending to specific episodes). At query time, MRAgent runs an iterative loop: it initializes a candidate set from cues matching the query, then at each step an LLM selects traversal actions (forward: cue-to-tag, then cue+tag-to-content; reverse: content-to-cue/tag, letting retrieved evidence surface new search directions), executes them via a fixed toolkit of typed operators (e.g., "retrieve episodic events for a cue-tag pair," "return the timestamp of an event," "retrieve semantic content for a person-aspect pair"), and an LLM routing step prunes the candidates and updates the accumulated context, deciding at each step whether enough evidence has been gathered to answer or more exploration is needed.

The paper proves (Theorem 4.1/C.5, full proof in Appendix C) that for any retrieval budget T>=2, the active hypothesis class strictly contains the passive one: a passive policy is trivially a special case of an active policy that ignores history, and strictness is shown via a "Binary-Tree Needle-in-a-Haystack" construction — a complete binary tree where each node's payload encodes which child to follow next toward a target leaf holding the answer label, so active retrieval can walk the revealed path to zero error in d+1 steps, while any passive (non-adaptive) policy must guess the target leaf and incurs error at least as large as the irreducible prior-only error unless its budget is exponential in the tree depth.

Empirically, MRAgent is evaluated on LoCoMo (long conversational memory, ~300 turns/conversation, single-hop/multi-hop/temporal/open-domain questions) and LongMemEval (multi-session interaction histories, ~115K tokens per instance), against RAG, LangMem, A-Mem, MemoryOS, and Mem0, using Gemini-2.5-Flash and Claude-Sonnet-4.5 as backbones and GPT-4o-mini as an LLM judge for semantic-correctness scoring (each configuration run three independent times with mean/std reported for the judge score). On LoCoMo, MRAgent improves overall LLM-Judge score from 68.31 to 84.21 under Gemini (23.3% relative gain) and from ~78-79 to 88.32 under Claude, with the largest gains concentrated in multi-hop and temporal questions specifically (e.g., temporal J-score rises from 61.68 to 80.37 under Gemini). On LongMemEval, MRAgent improves overall score from the strongest baseline's 54.92 to 72.95 (32% relative gain); a variant using Claude for retrieval while memory is constructed by the (cheaper) Gemini backbone reaches 86.76, though this specific mixed-backbone configuration is reported only for MRAgent and not replicated as a controlled comparison against similarly mixed-backbone baseline configurations. On cost (Table 3, LongMemEval), MRAgent uses 118k tokens per sample versus 632k for A-Mem, attributed to deferring complex relational reasoning to query-time (rather than doing it exhaustively during memory construction) and using tags to prune before touching expensive episodic content; runtime (586s) is competitive though not the fastest (Mem0 at 533s). Ablations on LoCoMo multi-hop questions (Claude backbone) isolate three structural variants (Cue->Episode direct indexing; Cue-Tag-Episode; the full Cue-Tag-Content) each with and without the iterative-reasoning mechanism, finding that active multi-step reasoning improves performance across every structural variant, that richer associative structure (CE to CTE to CTC) improves the no-reasoning baseline monotonically, and that removing the semantic-memory layer specifically degrades multi-hop performance, indicating episodic and semantic layers are complementary rather than redundant. A multi-turn analysis finds single-hop and temporal queries converge to near-perfect evidence recall within about three reasoning turns, while multi-hop queries continue improving recall by over 30% across additional turns; the number of turns at which new valid evidence stops appearing closely tracks the number of turns the agent actually uses before stopping, and a separate budget-sensitivity analysis (Appendix D.6) finds that increasing reasoning depth (more sequential turns) helps substantially more than increasing per-turn parallel tool-call breadth, which saturates quickly. The paper explicitly states its own limitations: because relational reasoning is deferred to retrieval time rather than resolved during construction, reconstruction cost grows with exploration depth (queries needing many traversal steps are slower than single-shot retrieval), and the memory graph is static and monotonically growing with no consolidation or forgetting mechanism, raising storage overhead for long-lived deployments. ## Learnings

The Cue-Tag-Content graph design — inserting an explicit, LLM-generated "Tag" node type as a semantic bridge between fine-grained cues and specific memory content, so the model chooses among a small set of associative tags before touching expensive content — is a directly reusable architectural pattern for any graph-memory or knowledge-base system trying to avoid the two failure modes of plain graph expansion (missing evidence not directly graph-connected to the query, and combinatorial blow-up from exhaustive neighbor expansion): the tag layer gives an explicit, inspectable decision point at which an LLM can prune before paying the cost of examining full content nodes.

The formal separation between active (evidence-conditioned) and passive (query-only) retrieval policies, proven via a clean Binary-Tree Needle-in-a-Haystack construction, is a portable theoretical result independent of this paper's specific graph design: it gives a rigorous, not just intuitive, justification for why any agentic/iterative retrieval scheme can in principle solve problems that no fixed-budget, non-adaptive retrieval scheme can solve at all (rather than merely solving them more efficiently), which is a useful reference point for anyone arguing for adaptive retrieval architectures generally.

The ablation finding that active multi-step reasoning improves performance across every tested memory structure — including the simplest direct Cue-to-Episode indexing — while richer structure alone (without reasoning) only helps in the no-reasoning setting, suggests that for iterative multi-hop reasoning tasks, the biggest lever is giving the model room to explore and revise across multiple steps, and structural sophistication of the underlying memory representation is a secondary, complementary factor rather than the primary driver of the reported gains.

## Verification

The paper backs its central claim with a rare-for-this-literature formal proof (Theorem 4.1/Theorem C.5), not just an empirical comparison: the Binary-Tree Needle-in-a-Haystack construction is fully worked through in the appendix (Lemmas C.6, C.8, C.9), giving a concrete, checkable distribution on which active retrieval achieves zero error while any passive policy is provably bounded away from zero — a genuine mathematical verification of the paper's core "active beats passive" thesis, independent of whether MRAgent's specific empirical numbers replicate. On the empirical side, each reported LLM-Judge configuration is run three independent times with mean and standard deviation reported (Table 1's ± values), and an Evidence Recall metric independent of final-answer correctness helps distinguish retrieval quality from generation quality. The main gap is that the correctness judgments underlying every headline number rest on a single LLM judge (GPT-4o-mini) determining "semantic equivalence" between a generated and reference answer, with no human-agreement or inter-rater validation of this judge reported anywhere in the paper — a real methodological gap relative to other agentic-evaluation papers in this same corpus that specifically validate their LLM judges against human annotators before relying on them (e.g., the SciIntBench paper in this batch reports Cohen's kappa against human raters for exactly this purpose). The paper's strongest single result (the mixed-backbone MRAgent* variant reaching 86.76 on LongMemEval) is also reported without an equivalent mixed-backbone control for any baseline, so it is not possible to tell from the paper's own data whether this specific gain is a genuine property of MRAgent's architecture or would appear for other systems given the same backbone-mixing trick.

## Field context

MRAgent sits in the fast-growing "agent long-term memory" literature it reviews directly (RAG, GraphRAG, A-Mem, Zep, MemoryOS, Mem0, LangMem, SeCom, LiCoMemory), and its central argument — that even graph-structured memory systems remain passive because traversal is governed by predefined, non-adaptive operators — is a specific critique that applies to essentially every prior system in its own comparison table. It evaluates on LoCoMo, the same benchmark used in this batch's [reviews/2606.02437.md](2606.02437.md) ("On the Scaling of PEFT"), whose Scale Down section evaluates a very differently designed memory mechanism, delta-mem, a stateful low-rank adapter that reads and writes a compact online recurrent state rather than an explicit symbolic graph. The two papers represent genuinely opposite architectural bets for the same underlying problem (persistent memory for LLM agents): MRAgent keeps memory as inspectable, natural-language graph structure and pushes all the adaptive intelligence into an LLM's iterative reasoning over that structure at query time, while delta-mem keeps memory as compact parametric state baked directly into the model's forward computation, with no explicit symbolic structure to reason over at all. Neither paper compares against the other's approach, but a downstream synthesis of agent-memory architectures would need to weigh MRAgent's inspectability and precise multi-hop reasoning (demonstrated here specifically on multi-hop and temporal LoCoMo questions) against delta-mem's much smaller per-query compute footprint (no iterative multi-turn LLM reasoning required at inference) and its reported gains on the same benchmark family.

## Critical discussion

The paper's dual empirical-plus-theoretical support is a genuine strength: the formal separation result is not decorative, since it directly predicts and explains the empirical pattern the paper observes (multi-hop and temporal questions, which most need adaptive path revision, show the largest gains, while single-hop questions that any retrieval method can already solve show much smaller gains). The ablation design (three structural variants crossed with reasoning on/off) is a genuinely informative decomposition that isolates structure's contribution from reasoning's contribution rather than reporting only the full system's aggregate score.

The main limitation is that every headline correctness number depends on a single, unvalidated LLM judge (GPT-4o-mini), with no reported check against human judgment anywhere in the paper — for a benchmark literature where LLM-judge volatility and self-preference effects are well documented (and specifically addressed via human validation in at least one other paper reviewed in this same batch), this is a meaningful gap, especially since the reported gains (e.g., 23-32% relative improvement) are large enough that judge-level noise or systematic bias could plausibly account for a non-trivial fraction of the reported margin, though it cannot fully explain results this large and this consistent across two backbones and two benchmarks. The strongest single number in the paper (MRAgent*'s 86.76 on LongMemEval, using a mixed-backbone configuration not applied to any baseline) is presented without the same controlled-comparison discipline used elsewhere in the paper, and should be read as a suggestive additional data point rather than a directly comparable result. The ablation study itself, while informative, is run on only one question type (multi-hop) on one benchmark (LoCoMo) under one backbone (Claude), so its specific conclusions about the relative contribution of structure versus reasoning are not independently confirmed on temporal, open-domain, or single-hop questions, or under the Gemini backbone, or on LongMemEval. What remains solidly supported: the theoretical claim that adaptive, evidence-conditioned retrieval is strictly more expressive than any fixed-budget non-adaptive retrieval policy is proven rigorously and does not depend on any of the paper's empirical choices; and within the specific benchmarks, backbones, and baselines tested, MRAgent's combination of an explicit cue-tag-content associative structure with iterative LLM-driven traversal produces substantial, benchmark-appropriate gains (concentrated exactly where the theory predicts they should appear) at meaningfully lower token cost than at least one graph-based baseline.
