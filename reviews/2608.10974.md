Citation: Tsofia Cohen and Tom Hope. MUSE: A Full-Text Cross-Domain Knowledge Base of Scientific Problems, Solutions, and Rationales. arXiv preprint, 2026. https://arxiv.org/abs/2608.10974v1

## What this paper is about

Scientific papers are full of small, local problem-solving moves that never show up in the abstract: "training became unstable, so we clipped gradients, because that prevents updates from collapsing." The authors call this a Problem-Solution-Rationale (P-S-R) triplet and build MUSE, a resource for mining these triplets at scale from full-text papers across many scientific fields, not just from abstracts and not just the paper's headline contribution. They hand-annotate a seed set, build an automated pipeline to scale it into a 37K-triplet knowledge base, and then run a small pilot showing the extracted rationales can be used to fine-tune a model for scientific problem solving.

## Extended summary

**Task and data.** A problem is a limitation, obstacle, gap, or desideratum; a solution is the method, mechanism, or design choice used to address it; a rationale is the author's own stated justification connecting the two. The annotation schema also captures conceptual coreference (linking fragmented or repeated mentions of the same problem/solution) and marks salient spans that can be discontinuous. 579 full-text paragraphs were expert-annotated (via TeamTat, with a screening task, training session, and disagreement-driven revision), sampled from unarXive across all its subject categories after a keyword pre-filter (manually reviewed problem/solution and rationale indicator word lists, LLM-assisted expansion). Agreement is reported at three levels: paragraph relevance (precision/recall/F1), entity/span (match if non-trivial token overlap or SciBERT BERTScore > 0.7), and relation (type match plus ≥50% span overlap on both arguments).

**Why not end-to-end LLM extraction.** The authors first tried prompting GPT-4 to extract all P-S-R triplets from a paragraph in one pass (Appendix B), manually reviewing a 10% sample of outputs, and found failure modes that motivated a modular pipeline instead: paragraph filtering → problem/solution span+entity extraction → relation extraction → post-processing/rationale construction (using GPT-4o) → coreference. Each stage is evaluated separately against the annotated seed set (Tables 2-5: paragraph classification, entity extraction, relation extraction), rather than only reporting an end-to-end number.

**Knowledge base.** Running the pipeline over a large arXiv full-text collection (submissions through 2026, spanning cs, math, physics, astro-ph, cond-mat, q-bio, q-fin, stat, and more per Table 9) yields 36,960 source-grounded P-S-R triplets with full provenance.

**Preliminary application.** As a downstream test of whether the extracted rationales carry useful signal, the authors run a small-scale LoRA + GRPO fine-tuning study (Section 6, Tables 6-8) comparing rationale-supervised training against plain solution supervision for scientific problem solving, with an LLM judge providing the blinded evaluation and the downstream reward. The headline finding: rationale supervision improves performance on complex, multi-constraint problems but can hurt performance on simple ones — a reversal the authors flag explicitly as unexpected. They also report that the untuned base models were strongest on absolute overall score for both model families tested, and describe rationale-generation quality as the least mature component of the pipeline.

**Stated limitations.** The authors themselves note two things: generalization beyond the tested scholarly domains to medicine, social science, or humanities is untested, and the fine-tuning study used constrained compute, LoRA (not full fine-tuning), and small effective batch sizes, so it should be read as a demonstration of one possible use of the dataset rather than a conclusive result about reasoning-model training.

## Learnings

Rejecting end-to-end LLM extraction in favor of a modular, per-stage-evaluated pipeline — after first trying and diagnosing the single-pass approach's failures on a real sample — is a reusable methodological move for anyone building an extraction dataset with an LLM in the loop: it turns "the LLM extraction pipeline works" into a set of separately falsifiable claims (paragraph filter precision/recall, entity match rate, relation match rate) instead of one opaque number.

The complexity-stratified reversal (rationale supervision helps on hard, multi-constraint problems but hurts on easy ones) is a concrete, testable instance of a broader pattern worth tracking across this corpus: extra reasoning scaffolding or supervision signal is not uniformly beneficial, and its value can depend on task difficulty in a way that a single aggregate metric would hide. The authors surface this by stratifying rather than only reporting an overall average — a design choice that is itself the useful takeaway, independent of whether the specific mechanism replicates.

## Verification

Central, and unusually multi-layered for a dataset paper: (1) inter-annotator agreement on the 579-paragraph seed set at paragraph, span/entity, and relation levels, each with its own matching rule (BERTScore threshold for spans, type-plus-overlap for relations); (2) each extraction pipeline stage evaluated separately against that seed set (Tables 2-5), rather than only end-to-end; (3) a documented comparison against an end-to-end GPT-4 baseline, checked by manual expert review of a 10% sample (Appendix B); (4) the downstream fine-tuning study uses an LLM judge for blinded evaluation and as the GRPO reward signal. The weakest link is stage (4): the paper does not report an independent human check on the LLM judge's blinded evaluations or its complexity ratings (Claude Opus 4.8) beyond what is described for the extraction pipeline itself, so the downstream result rests more heavily on LLM-judged signal than the KB-construction pipeline does.

## Field context

MUSE positions itself explicitly against a lineage of scientific information-extraction resources: keyphrase/relation extraction (ScienceIE, SciREX), full-text entity-relation extraction (SciER, SciNLP), discourse/rhetorical-role annotation (Liakata et al. 2010, SciDTB, CODA-19), and prior problem/solution/idea knowledge bases (Heffernan and Teufel 2018; Lahav et al. 2022's search engine for scientific challenges and directions; and CHIMERA, Sternlicht and Hope 2026 — explicitly the same senior author's own prior knowledge base of idea recombination). MUSE's stated point of differentiation is granularity: it targets fine-grained, sub-problem-level P-S-R triplets that can occur anywhere in the full text (not just the paper's headline contribution), with an explicit rationale link rather than only problem/solution pairing.

No paper already in this corpus builds or evaluates a comparable full-text scientific P-S-R knowledge base, so there is no direct overlapping-claim connection to check against. The closest thematic neighbor in this corpus is Google's Co-Scientist system ([26cosci.md](26cosci.md)), which also aims to accelerate scientific work with LLMs grounded in the literature, but at a different point in the pipeline: Co-Scientist generates new hypotheses, while MUSE extracts and structures problem-solving reasoning that already exists in published text. The two are complementary rather than competing, and MUSE's KB is a plausible input resource for hypothesis-generation systems like Co-Scientist rather than a rival to them.

## Critical discussion

The dataset-construction claim is well-supported: agreement is reported at three granularities with explicit matching criteria, each pipeline stage is evaluated against held-out annotated data rather than only inspected qualitatively, and the rejection of end-to-end LLM extraction is backed by a documented failure analysis rather than asserted. This is a stronger evidentiary standard than many scientific-IE dataset papers use.

The downstream fine-tuning claim is weaker and the authors are candid about why: the LoRA/small-batch/constrained-compute setup means the complexity-stratified reversal is a suggestive pilot finding, not a validated training recipe, and the paper says so directly ("a potentially interesting finding for future exploration," not a settled result). Two things sharpen this caution further. First, the paper's own reported result that untuned base models scored highest overall on absolute score for both model families tested is in tension with a paper whose downstream section is meant to showcase the value of the extracted rationales — the benefit shows up only within the complexity-stratified breakdown, not in the topline number, and a reader skimming only the abstract's claim that "rationale supervision improves performance on complex problems" could miss that this is a conditional, not unconditional, improvement (`overclaim` risk if the finding is later cited without the stratification caveat). Second, the evaluation stack for this pilot leans on LLM judges at multiple points — GPT-4o for rationale construction/post-processing, Claude Opus 4.8 for refinement and complexity rating, and an LLM judge for both the GRPO reward and the blinded evaluation — without a reported independent human check on the judge itself at this stage (`same-family-judge`/missing-control-adjacent concern), so some of the apparent signal could reflect judge biases (e.g., a preference for longer or more elaborated rationale-conditioned outputs) rather than genuine problem-solving quality. The authors' own description of rationale generation as "the least mature component of the pipeline" is a useful, self-aware admission that supports treating this section as exploratory.

What remains supported after these caveats: MUSE is a carefully validated, well-documented extraction pipeline and resulting knowledge base of scientific P-S-R triplets, evaluated rigorously at the level it is meant to be evaluated (extraction quality). The downstream training result is real but preliminary, conditional on problem complexity, and evaluated by LLM judges without an independently reported human validation layer at that stage — a genuine open question for future work rather than a demonstrated capability.
