Citation: Zhu, J., Ro, Y., Robertson, J., Wang, K., Li, J., Vikalo, H., Akella, A., Wang, Z. Your Agents Are Aging Too: Agent Lifespan Engineering for Deployed Systems. arXiv:2605.26302, 2026.

## What this paper is about

Standard agent benchmarks test a model once, on a fresh session. This paper argues that a deployed agent's reliability is a "lifespan" property, not a snapshot one: even with frozen model weights, the agent's effective state keeps changing as it compresses history, accumulates memories, has facts revised, and undergoes routine maintenance like memory flushing. The authors name this failure class "agent aging," break it into four distinct mechanisms (compression, interference, revision, maintenance), and build AgingBench, a benchmark that runs agents across many sessions and uses controlled counterfactual probes to say not just that an agent degraded, but which part of its memory pipeline (writing, retrieval, or reasoning over what was retrieved) is responsible — so a practitioner knows what to actually fix.

## Extended summary

The paper defines four aging mechanisms grouped into two families. Accumulation-driven aging worsens gradually as state grows: compression aging (write-time summarization drops future-relevant details, e.g., a specific drug dosage collapsing into "a daily medication") and interference aging (accumulated similar entries crowd out the target fact even when nothing has changed or been lost, e.g., confusing two similarly-named contacts). Event-driven aging is triggered by discrete changes: revision aging (changed or derived state — e.g., a running budget total built from many deltas — is not correctly updated or propagated) and maintenance aging (routine lifecycle events like memory recompaction, history flushing, or prompt updates silently regress behavior).

To measure these, AgingBench uses programmatic generators that produce a "temporal dependency DAG" per run, encoding version chains (fact supersession), dependency edges (probes requiring synthesis across sessions at controlled chain depth), and interference pairs (confusable entities). Seven scenarios (S1 research-literature tracking, S2 lifestyle/budget assistant, S3 project knowledge base, S4 software-engineering planning, S5 self-managed memory, S6 naturalistic multi-domain, S7 autonomous-agent self-planning) each naturally activate a different subset of the four mechanisms (Table 1), and each is backed by a seed-reproducible generator with independently tunable dials (dependency density, update rate, chain depth, interference count). The evaluation runs a session loop: at each session the agent reads its compressed memory, answers a task and held-out probes, and its interaction history is compressed into the next state; at designated sessions the runner injects a lifecycle event. The resulting per-session score sequence is an "aging curve," from which the paper computes half-life (sessions to 50% capability loss), decay slope, and a hazard proxy.

For attribution, the paper decomposes the agent's memory pipeline into Write, Retrieval, Store, and Utilization stages and runs a three-probe counterfactual ladder on held-out validation tasks: P1 is the agent's own full pipeline; P2 swaps in an oracle retriever over the agent's own (possibly lossy) written memory; P3 additionally swaps in oracle (gold) context, isolating any remaining error to Utilization. The gaps Acc(P3)−Acc(P2), Acc(P2)−Acc(P1), and 1−Acc(P3) are read as Write-error, Read-error, and Utilization-error shares respectively (explicitly framed as a diagnostic profile under paired counterfactual controls, not a claimed exact additive causal decomposition — a caveat the paper states directly in its Appendix H "Evaluation Card"). Maintenance aging is measured separately as the pre/post-event change in Write-error around a lifecycle event, since it is otherwise observationally aliased with ordinary write error.

Experiments cover 14 models across 5 open-source families (7B-120B) and 2 closed-source API families, run through three agent frameworks (ReAct as a runner-controlled loop, OpenHands, and Claude Code), across two evaluation tiers: Tier 1 (runner-controlled ReAct with a fixed, swappable memory policy — lossy compaction by default, with careful-compaction, no-memory, append-only, and growing-history variants) over 8-12 sessions, and Tier 2 (autonomous CLI agents managing their own workspace memory) over 10-block runs. Headline findings: (I) no model or policy dominates across all four mechanisms — rankings reverse depending on which mechanism is probed, so a single "memory score" is argued to obscure deployment-relevant behavior. (II) On S2, explicit constraint-violation rate stays near zero across sessions while factual constraint precision drops sharply — behavioral/compliance monitoring can be blind to silent factual decay. (III) Revision aging (accumulator error on a running budget total) does not consistently improve with model scale or with a more careful compaction policy, suggesting a representational rather than pure-capacity problem. (IV) In Tier-2 autonomous agents, workspace fidelity (what was actually written to disk) consistently exceeds downstream recall accuracy across all configurations, with the gap smaller for Claude Code than OpenHands, pointing to a persistent Utilization-stage bottleneck (the agent under-retrieves relative to what it wrote) rather than a Write-stage one. (V) Within the Claude Code model family, the flagship Opus-4.7 has the worst write-time artifact fidelity (pytest pass rate, workspace fidelity) despite competitive retrieval/revision-stage metrics; a forced re-read ablation (Appendix D.5) closes the recall/fidelity gap but leaves the pytest gap intact, separating a Utilization-stage issue from a distinct write-quality residual. Two preliminary mitigation probes are reported: a typed-state JSON sidecar for revision-heavy variables reduces S2 accumulator error by 25-47% depending on compaction policy at ~10% overhead, and a threshold-triggered runtime controller for one-shot corrective actions captures ~91% of an always-on intervention's benefit at 86% of its wall time — both explicitly flagged as preliminary, single-scenario probes rather than validated general interventions.

## Learnings

The paper's most transferable methodological idea is the P1/P2/P3 counterfactual ladder itself: rather than reporting one aggregate "memory score," it isolates which stage of a fixed pipeline (write, retrieval, utilization) is responsible for a given failure by successively replacing upstream stages with oracle versions and reading the resulting accuracy gaps as a diagnostic profile. This is a generically reusable pattern for diagnosing any pipeline where a single end-to-end score conflates multiple failure-capable stages, and the paper explicitly distinguishes it from trajectory-based LLM-as-judge attribution methods (which infer a responsible step from a rollout) by noting it intervenes rather than infers, addressing failure modes that are "observationally ambiguous" without gold knowledge of what should have been written.

A second, more specific learning is Finding II's demonstration that behavioral-compliance monitoring and factual-accuracy monitoring can diverge: an agent can continue producing well-formed, rule-following responses (no explicit constraint violations) while the underlying facts it is reasoning over have already silently decayed. This is a concrete, falsifiable caution against relying on safety- or compliance-style behavioral probes as a proxy for whether a long-lived agent's factual state is still correct — the two can be decoupled, and only mechanism-level fact-recall probes catch the second failure.

A third learning is the paper's finding that scaling model capability does not close the "revision aging" gap for derived/accumulated state (e.g., a running total built from many deltas): the accumulator-error metric shows no consistent improvement across a 7B-120B+ range or across compaction policies, which the paper interprets as a representational mismatch (using free text as the medium for state that must be exactly maintained through incremental updates) rather than a capacity or context-budget problem — motivating the explicit design suggestion of a typed-state side-channel rather than relying on prompting or bigger models.

## Verification

Verification is close to the paper's central subject, structured around the counterfactual-probe ladder described above; the paper is unusually careful about the epistemic status of this method, stating explicitly (in the Appendix H "Evaluation Card," which this review treats as load-bearing content rather than boilerplate) that the diagnosis is "counterfactual diagnosis under paired controls, not exact additive causal decomposition," that it does not claim unique causal identification, and that it flags cells violating the required probe monotonicity (Acc(P1)≤Acc(P2)≤Acc(P3)) as "diagnostic anomalies" rather than silently reporting a nonsensical stage split. This kind of explicit scope-boundary statement is stronger self-verification discipline than many system papers in this corpus provide. The benchmark itself is fully synthetic and generator-backed (seeded, reproducible), which the paper defends as a deliberate choice to isolate longitudinal failures that are "difficult to disentangle in noisy production traces" rather than as an attempt to model the full distribution of real deployment behavior — a reasonable and disclosed trade-off, though it also means every quantitative finding in the paper (half-lives, accumulator errors, mechanism shares) describes behavior on constructed scenarios rather than on measured production agent traces, and the paper's own "Limitations and the open frontier" section names anchoring this vocabulary to real production telemetry as future work rather than something demonstrated here. Statistical treatment of the main tables is otherwise thin: Table 3's cross-model comparison and most headline findings report point estimates without confidence intervals or variance across seeds in the main text, though Appendix E.4 is titled "Multi-Seed Validation" (not read in full here) which appears intended to address this at least partially.

## Field context

The paper positions itself against two adjacent lines of prior work it discusses directly: long-context benchmarks (RULER, LongBench) that test attention over a single growing window, which it argues collapse a qualitatively different problem (a fixed write→store→read pipeline operating under a persistent budget across many separate sessions, where the raw transcript is not even available at the next session) into a single "long-context" axis; and existing multi-session memory benchmarks (LongMemEval, MemoryArena, LoCoMo, PERMA, TierMem) which it credits with individually contributing pieces of what full longitudinal evaluation needs (cross-session dependency structure, snapshot Q&A over history, or partial write/reasoning-failure attribution in TierMem's case) but argues none jointly combines cross-session dependency encoding, lifecycle-event injection, aging-curve statistics, and component-level diagnostic attribution in one framework — a claim substantiated by name-by-name discussion in the paper's own Table 4/Appendix A rather than left as an unsupported assertion. Within this corpus, the paper's core observation that a deployed multi-stage agent pipeline can have its aggregate failure rate decomposed into distinct, mechanism-specific root causes requiring different fixes (Finding V's within-family Opus-4.7 case: a write-quality problem masquerading as a retrieval problem) is conceptually adjacent to this batch's recurring "artifact generation outpaces verification" theme (2605.18661's cross-cutting synthesis, 2605.20025's AutoResearchClaw registry ablation): all three papers independently argue that a single aggregate quality or accuracy score hides which specific pipeline stage is actually failing, and that the correct remedy depends on that stage rather than on generically "adding more" capability, memory, or oversight.

## Critical discussion

The benchmark's central strength — full programmatic control over dependency density, update rate, chain depth, and interference density — is also its central limitation for external validity: every quantitative claim in the paper (aging curves, half-lives, mechanism-share decompositions) is measured on synthetic, generator-produced scenarios rather than on real deployment traces, and the paper is explicit that this is untested against production telemetry ("Limitations and the open frontier" states this as the open item), while also asserting, without supporting evidence beyond the constructed scenarios, that the characterized mechanisms are "largely scale-invariant" and will "compound over weeks-long deployments" — a forward-looking extrapolation stated with more confidence than the paper's own evidence base (8-12 sessions per Tier-1 run, 10-block runs for Tier 2) can directly support, since none of the reported runs actually span the weeks-long real-user timescale the claim is about. This is a defensible, disclosed limitation rather than a hidden one, but the specific "scale-invariant" claim reads as an expectation rather than a measured result and would benefit from being flagged with the same epistemic care the paper applies to its own counterfactual-attribution claims.

Several of the headline cross-model comparisons in Table 3 and the component-attribution figures (Figure 6) are drawn from a small number of scenarios and models per cell (often 3-7 models, single-digit session counts) without confidence intervals or explicit seed-variance reporting in the main text, so magnitude comparisons between close values (e.g., the 0.60-0.82 error-rate band in Finding V's "same wrong answer, different repairs" claim) should be read as suggestive rather than statistically established; the paper does gesture at a "Multi-Seed Validation" appendix (E.4) that may partially address this, but it is not integrated into the main-text claims themselves. Additionally, because Tier 2 (autonomous agents) uses a different metric surface re-scoped specifically to scenario S7 and the paper itself states Tier-2 results are "not directly comparable to Tier-1 within the same mechanism group," several of the paper's most vivid illustrations (e.g., the Opus-4.7 within-family finding) rest on a single scenario's task surface rather than being cross-validated against the broader 7-scenario suite used for the Tier-1 claims.

What remains well supported after these caveats: the four-mechanism taxonomy itself is a clear, well-motivated conceptual contribution independent of any specific benchmark number, distinguishing failure types (e.g., interference vs. revision) that are easy to conflate under a single "memory got worse" diagnosis; the qualitative finding that behavioral-compliance and factual-precision metrics can diverge (Finding II) is demonstrated with a specific, interpretable scenario rather than asserted generically; and the counterfactual-ladder methodology, together with the paper's own explicit statement of its diagnostic (not strictly causal) status, is a methodologically disciplined contribution that other agent-evaluation work could adopt regardless of whether AgingBench's specific synthetic scenarios turn out to match real production aging dynamics.
