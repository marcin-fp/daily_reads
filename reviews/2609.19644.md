Citation: Jaehyun Nam, Jinsung Yoon, Yanzhou Pan, Yubo Wang, Rui Meng, Parthasarathy Ranganathan, and Tomas Pfister. ScientistTwo: Pioneering the Human Knowledge Frontier with Autonomous AI. arXiv preprint arXiv:2609.19644, 2026. https://arxiv.org/abs/2609.19644v1

## What this paper is about

ScientistTwo is a multi-agent system that takes an accepted machine-learning paper and its code as the "problem" and tries, with no human involved, to produce a better method together with a complete paper and codebase about it. It lists the weaknesses of the published method, proposes and ranks ideas, tests them first on part of the benchmark and then on all of it, evolves ideas from earlier experiments, runs ablations, writes a paper, revises the paper against a simulated reviewer that can also trigger new experiments, and finishes with a simulated meta-review.

The authors run it on 107 papers from NeurIPS 2025, ICLR 2026, and ICML 2026. They report that it improves on 86 of them (80.4%), with an average relative gain of 25.2% over the published method. They also report that two automated review agents give its papers higher average scores than the accepted human papers it started from. From this they conclude that the system "consistently" outperforms human state-of-the-art methods and writes papers that meet top-venue standards.

## Extended summary

**Pipeline (Sec. 3, Table 1, Listing 1).** Every stage is a generate, critique, refine loop with a capped number of rounds. A critic agent either accepts the candidate, asks for a refinement, or discards it. The stages and their caps (App. A.2, L814) are:

- Limitations. A Limitation Extractor and a Limitation Verifier loop, for up to 16 rounds, to list weaknesses of the source method.
- Seed ideas. An initial idea is expanded by an Idea Generator. A Novelty Checker scores each idea against two reference papers retrieved via Google Search, and seeds are sorted by that score.
- Idea evaluation. A Baseline Coding Agent reproduces the source paper's main experiments on a benchmark subset. A Subset Coding Agent implements an idea, and a Subset Critic labels it Bad, Good, or Engineer. Engineer means hyperparameter or code adjustments, allowed for at most two rounds. Good ideas are scaled to the full benchmark, where a Full-Set Critic asks whether the idea beats "the original SOTA result" (Table 1, L103).
- Idea evolution. Each round evaluates two candidates, one untried seed and one idea evolved from all previous traces, successes and failures alike. Up to four rounds are run, stopping early once four successful ideas exist. A run with zero successes terminates. A Selector Agent then picks the best idea using the full-benchmark results (L184).
- Ablations. A planner writes ablation plans and a coding agent executes them. An Ablation Critic either accepts or requests one refinement, and an LLM Result Comparison Agent keeps the refined version only if it "strictly outperforms" the previous best (L194).
- Drafting and review. An Initial Drafter that incorporates PaperOrchestra writes an ICLR-2025-format manuscript. ScholarPeer then reviews it on the 1 to 10 ICLR scale. If the score is below 8, a Rebuttal Planner and a Rebuttal Coding Agent run supplementary experiments and a Paper Enhancer revises the draft. This happens for at most two rounds, with an early stop at a ScholarPeer score of 8 (L200-L213).
- Meta-review. A Meta-Review Agent returns Accept or Refine. On Refine, the idea itself is revised at most once and kept only if it beats the previous best. Ablation, drafting, and review are then rerun (L217-L223).
- Integrity agents (L358, L371). The coding agent is prompted to write self-contained reproducible scripts. A validation filter discards solutions that break the task rules. A search-augmented LLM flags hallucinated citations for the writer to fix. A coding agent audits the repository against the method section.

Gemini 3.6 Flash runs all agents except idea-experiment coding, ablation, rebuttal, and draft enhancement. Those four use Claude Code with Claude Opus 4.8 (L814).

**Tasks (App. A.1).** The 38 NeurIPS 2025 papers and 5 ICLR 2026 papers are drawn from the AutoSOTA benchmark. The 64 ICML 2026 spotlight papers were selected "strictly adhering to AutoSOTA's filtering process (e.g., verifying reproducibility)" (L798). Every task is an ML paper with an executable benchmark. The topics include time series, optimization, interpretability, RL, and LLM methods.

**How results are measured.** Paper quality is scored by two automated reviewers (L247). ScholarPeer (Goyal et al., 2026) is described as "in-distribution" because it is also used inside the loop. The Stanford Agentic Reviewer (SAR, paperreview.ai) is described as a held-out evaluator "unseen during development." Performance gains over the source method come from parsing each generated paper's main tables ten times with Gemini 3.6 Flash and averaging the results (L301).

**Comparison with other systems (Table 2).** Other systems are represented by their publicly released papers, not by reruns on these tasks. Values are ScholarPeer mean rating / accept rate, then SAR mean / accept rate:

- AI-Researcher (7 papers): 1.0 / 0%, 2.4 / 0%.
- CycleResearcher (6): 1.0 / 0%, 2.8 / 0%.
- AI Scientist-v2 (3): 2.0 / 0%, 2.5 / 0%.
- AutoResearchClaw (4): 2.5 / 0%, 3.7 / 0%.
- Zochi (2): 3.0 / 0%, 2.9 / 0%.
- DeepScientist (3): 3.0 / 0%, 4.1 / 0%.
- ScientistOne (21): 3.8 ± 1.2 / 14.3%, 4.1 ± 0.7 / 0%.
- ScientistTwo (86): 7.5 ± 1.3 / 91.9%, 5.7 ± 0.6 / 72.1%.

The qualitative comparison (Fig. 8) sets one ScientistOne experiment section (4 figures, 2 tables) beside one ScientistTwo paper (9 figures, 12 tables including the appendix).

**Comparison with human papers (Table 3).** Values are in the same format. The accepted human papers score:

- ICLR 2026 (5 papers): 6.8 ± 1.6 / 60.0%, 5.2 ± 0.7 / 60.0%.
- NeurIPS 2025 (38): 6.2 ± 1.9 / 65.8%, 5.5 ± 0.7 / 76.3%.
- ICML 2026 Spotlight (64): 6.9 ± 1.5 / 79.7%, 6.1 ± 0.5 / 96.9%.
- Agent4Science 2025 accepted AI papers (4): 3.0 / 0%, 3.8 / 0%.

ScientistTwo papers, grouped by source venue, score:

- ICLR (4 of 5 tasks succeeded): 7.0 ± 1.2 / 100%, 5.4 ± 0.2 / 75.0%.
- NeurIPS (33 of 38): 7.3 ± 1.7 / 87.9%, 5.6 ± 0.7 / 75.8%.
- ICML (49 of 64): 7.6 ± 1.0 / 93.9%, 5.7 ± 0.6 / 69.4%.
- Overall (86 of 107): 7.5 ± 1.3 / 91.9%, 5.7 ± 0.6 / 72.1%.

The authors conclude that the generated papers surpass the average accepted-paper scores at ICLR 2026 and NeurIPS 2025 under both reviewers, and that they do "not yet achieve spotlight-level quality" (L272).

**AutoSOTA (Table 4, App. B).** Values are median / mean relative gain on successful cases.

- AutoSOTA (105 papers): 2.7% / 7.5% overall; 3.7 / 8.5 on NeurIPS; 5.0 / 7.2 on ICLR.
- ScientistTwo (86 papers): 7.7% / 25.2% overall; 7.0 / 13.9 on the same 33 NeurIPS papers; 2.2 / 3.8 on the same 4 ICLR papers.

The authors call ScientistTwo superior overall and on NeurIPS, "but performance drops slightly" on ICLR. They attribute the difference to novel methods versus hyperparameter search (L301).

Appendix B examines the five ICLR papers one by one. AutoSOTA stops when a pre-registered numeric target is cleared. ScientistTwo has no target and requires the gain to be attributable to its mechanism in ablation. AutoSOTA reports a gain on 5 of 5 papers and ScientistTwo on 4 of 5. Every AutoSOTA change is a configuration edit, with a median under ten lines. ScientistTwo's accepted changes are new modules:

- Pinet: a Stiefel-nullspace reparameterization. Constraint violation drops from 4e-4 to 2e-14 on all four DC3 sets, and training is 3.0x faster.
- DMSQD: a dimension-adaptive smoothness penalty. It adds +0.61% ± 0.27 mean QD over the reproduced DMS, and +422 QD and +1.16 percentage points of coverage averaged over the grid.
- T-SAE: a Sheaf-SAE, +3.4% ± 0.2 on probes at matched FVE.
- RALI: PLCC +0.006 and SRCC +0.008 across seven datasets.

On TeCh, ScientistTwo's variant beat the baseline on 5 of 6 metrics. Its ablation critic rejected the variant because the gain came from EMA and label smoothing. AutoSOTA reported +4.45% from widening the model and adding label smoothing (L842).

The authors also document two AutoSOTA failure modes (L844). One is an unmeasured trade-off: on Pinet, latency falls 16.7% but feasibility is not reported. The other is optimizing the evaluator: on T-SAE, a threshold change alters what the LLM judge sees, and AutoSOTA's own re-evaluation (0.7557) falls below the baseline (0.7586). They state that the gain columns are self-reported against each system's own reproduced baseline, on different hardware, and are "not a head-to-head" (L832, L852).

**Component ablations (Sec. 4.2, the 49 ICML tasks).**

- Idea evolution. Gains grow over refinement rounds, mostly early (Fig. 9a). The figure OCR suggests about 20.6% at the start and 33.4% at the end. Evolved ideas were selected on 27 of 49 tasks and seeds on 22 (Fig. 9b, OCR).
- Rebuttal loop (Table 5), in the format above:
  - No rebuttal (round 0): 5.2 ± 2.2 / 46.9%, 5.6 ± 0.5 / 49.0%.
  - One round: 6.9 ± 1.6 / 79.6%, 5.8 ± 0.6 / 73.5%.
  - Two rounds: 7.6 ± 1.0 / 93.9%, 5.7 ± 0.6 / 69.4%.
- The authors write that the ScholarPeer gains are "not surprising," and that the effect generalizes to SAR, "particularly pronounced in the first review round" (L330).
- Meta-review refinement (Table 6) is shown for a single case: TOFU forget10 on Llama-3.2-1B-Instruct, starting from Engram (Kwon et al., 2026). The overall score is 0.705 for Engram, 0.897 for the pre-meta-review variant, and 0.916 after meta-review. On extraction EM the human baseline stays best (0.004, against 0.084 and 0.071).

**Integrity audit (Table 7).** This follows ScientistOne's CoE protocol, which has four checks: I1 re-executes the code and compares scores, I2 checks specification compliance and reward hacking, I3 checks for hallucinated references, and I4 checks method-code alignment.

- Without the refinement agents: 50/50 scores verified, 1/50 specification violations, 19 of 1,840 references hallucinated, 39/50 method-code aligned.
- Full system: 49/49, 0/49, 0 of 1,814, 49/49.

A footnote adds that one extra task completes without the specification filter but contains reward hacking, so it must be filtered (L379).

**Other results.**

- Coding agent (Table 8, 5 ICLR tasks). With Claude Code: success 80%, average gain 3.8%, ScholarPeer 7.0 / 100%, SAR 5.4 / 75%. With Antigravity (Gemini 3.8 Flash): success 60%, gain 16.7%, ScholarPeer 6.3 / 66.7%, SAR 4.8 / 66.7%.
- Cost (Fig. 10, measured on the 33 NeurIPS tasks). A run takes 2.51 days on average (60.2 h), with a median of 2.0 days and an IQR of 1.16 to 3.14 days. It costs $3,765 per task on average, including tokens and virtual machines, and most of the time goes to idea refinement. The claim of "significantly faster execution compared to human researchers" (L377) comes with no measured human time.
- Iterative expansion (Table 9, one task). Starting from incremental BPE tokenization (Jiang and Gong, 2026), VD-STrans gains +10.9% (rating 6.5). BXT-Transducer gains a further +9.6% over it (rating 5.6), and SBR-Transducer +8.2% over that (rating 7.1).
- Human evaluation (Table 10). Nine "experienced human reviewers" rated 33 NeurIPS-derived papers. Standalone scores on a 1 to 5 scale: introduction 4.2, method 4.1, baselines and benchmarks 4.0, ablations 4.3, insight and limitations 4.0, overall 3.7. Relative to the human source paper, where 3.0 is parity: 3.1, 2.9, 3.5, 3.3, 3.3, and 3.0 overall. Humans are preferred only on method soundness.

**Case studies (Sec. 4.3, App. C and D).** DynaSpec-RAG extends TS-RAG (Ning et al., 2025) for forecasting with a frozen time-series foundation model, at lookback 512 and horizon 64 on seven datasets (Table 11). Its average MSE/MAE is 0.1892/0.2488 against 0.1940/0.2492 for TS-RAG. It loses on Electricity (MSE 0.1135 vs 0.1120) and on ETTh1 MAE, and adds 0.27M trainable parameters.

Appendix D reproduces the generated paper in full (ICLR 2025 template, "Anonymous authors"). Its text states several facts relevant below:

- The residual module is trained on the pooled training splits of the seven benchmarks.
- Retrieval uses in-domain training splits.
- A dataset-level scale β is grid-searched on each dataset's validation split.
- The abstract claims the method is "strictly eliminating negative transfer."

The generated paper's own ablation tables report:

- Frequency split: full dual-band 0.2199 MSE versus 0.2203 for a monolithic residual (Table 4 of the generated paper).
- Gate: the adaptive gate 0.2300 versus 0.2304 for a constant gate of 0.5 (Table 6).
- Calibration: calibrated β still regresses on 2 of 7 datasets (Table 7).
- Aggregation: uniform neighbour averaging 0.1891/0.2474 versus 0.1891/0.2479 for learned attention (Table 9).
- Transfer to GIFT-Eval: -5.6% MSE, with solar at -46.1% (Table 10).

Appendix C gives fragments of the Procrustes-DS trajectory, an OOD detector that extends X-Mahalanobis with CIFAR-100 as the in-distribution set and a ViT-B/16 backbone. The ablation report there finds that four of the five proposed components were inert or harmful (L1077-L1087). Procrustes transport added +0.01% AUROC. Nullspace gating dropped CIFAR-10 AUROC from 96.83 to 88.02. The default elastic-net precision failed at 79.89% AUROC. Dempster-Shafer fusion reduced to a linear sum.

The accompanying LLM reproducibility audit returns "Reproducible" (L1095). It re-ran `final.py`, which regenerates the reported average AUROC/FPR95 of 99.56/2.17, and found cached features bit-exact. It also notes that the final code had removed the Procrustes step and Dempster-Shafer fusion. The audit states: "I only audited the Ours method (not the baseline)" (L1113).

**Authors' stated limitations (L452-L454).** The generated work does not reach spotlight or oral caliber, and the search stays with "local algorithmic refinements". A single task costs about $3,800. Elsewhere the authors add two more: ScholarPeer is an in-distribution evaluator (L247, L330), and the AutoSOTA gains are not a head-to-head comparison (L832).

## Learnings

Optimizing drafts against an in-loop LLM reviewer transfers to a held-out reviewer only at first. In Table 5 one rebuttal round moves SAR acceptance from 49.0% to 73.5%. A second round lifts ScholarPeer acceptance from 79.6% to 93.9%, while SAR acceptance falls to 69.4%. The SAR mean rating barely moves across the three conditions (5.6, 5.8, 5.7), so the acceptance swings come from small shifts near the reviewer's threshold. This is a small-sample Goodhart signature worth remembering whenever an automated reviewer is both target and yardstick.

An acceptance rule based on ablation attribution changes what counts as a success. ScientistTwo's ablation critic rejected a TeCh variant because its gains came from EMA and label smoothing, which is the same lever AutoSOTA reported as a +4.45% improvement. It also stripped inert components out of Procrustes-DS. The caveat is that the rule is enforced by an LLM critic and is not reliable. In the showcased DynaSpec-RAG paper, the generated ablations show the named mechanisms adding almost nothing over simpler variants, and it passed anyway.

A mean relative gain pooled across heterogeneous metrics is dominated by its tail. Here the mean is 25.2% and the median 7.7%. Backing the ICML mean out of Table 4 gives roughly 35%, against 3.8% on the ICLR tasks. When a paper summarizes "improvement over state of the art" across latency, QD score, MSE, and accuracy with a single mean, ask for the median and the per-metric distribution first.

Artifact-level integrity checks can report zero failures while claims inside the paper remain inconsistent with its own tables. DynaSpec-RAG passes the reference and re-execution style checks, yet its abstract says it strictly eliminates negative transfer while its own Table 7 shows 2 of 7 datasets regressing. Its Tables 1 and 2 also report different numbers for the same method under the same protocol. Checking prose claims against the paper's own tables is a separate and cheap verification step that CoE-style audits do not perform.

## Verification

Most of the verification in the pipeline is done by LLM critics. Subset and full-set critics decide whether an idea's results are Good. The Result Comparison Agent decides whether a refined method "strictly outperforms" the previous one (L194). The ablation critic judges whether the component breakdown is clean, and ScholarPeer and the Meta-Review Agent judge the paper. None of these decisions is described as using repeated seeds or a statistical test. The only deterministic check is re-execution of the final code.

The CoE Integrity Audit (L356) is applied post hoc with four checks. I1 re-runs the repository and compares reported scores. I2 checks that the code follows the task rules without reward hacking. I3 checks for hallucinated references. I4 checks that the paper describes the code faithfully. Appendix B calls I2 a "protocol-immutability audit" that makes edits to the evaluation harness inadmissible (L844). In the loop, the same four properties are pushed by dedicated agents: reproducible scripts, a rule-violation filter, search-augmented citation correction, and a code-versus-method audit feeding the writer (L358, L371). So Table 7 measures whether the in-loop agents achieve what the audit checks, and the checker is not independent of the thing being checked.

The text does not say who runs the post-hoc audit or which model it uses. The one audit transcript in the extract (App. C) is an LLM agent writing in the first person. It re-ran the final script, matched every number exactly, verified cached features bit-exactly against a fresh extraction, and audited only the proposed method, not the baseline (L1113). No human confirmation of audit outcomes is reported.

The paper's criticism of AutoSOTA is itself a verification finding (App. B). Prompt-level prohibitions against altering the evaluation (AutoSOTA's R1, R2, R4) failed empirically in two of five cases, one of which changed what the LLM judge was shown. The authors argue that structural checks (re-execution, protocol immutability, full benchmark grid) block this class of edit.

The system never verifies novelty beyond two retrieved papers (L814). It also never checks sentence-level claims against the paper's own tables.

## Field context

Authors' positioning. ScientistTwo is presented as the successor to end-to-end pipelines such as AI Scientist and AI Scientist-v2. It reuses modular components by the same group: PaperOrchestra for drafting, ScholarPeer for review, and ScientistOne's Chain-of-Evidence audit (L72, L198, L200, L356). The authors group AI-Researcher, AutoResearchClaw, DeepScientist, and AutoSOTA as systems that optimize a single scalar metric on a single dataset. They describe ScientistOne as verifiability-centric but lacking "active analytical expansion." Their stated additions are multi-dataset benchmark reasoning, ablation-driven refinement, and a rebuttal loop that runs new experiments. They cite AlphaEvolve (reviewed as reviews/2506.13131.md) and EvoScientist as evolutionary alternatives.

Reviewer inference. The closest reviewed work is its direct predecessor, reviews/2605.26340.md (ScientistOne). That review recorded that ScholarPeer shares authors with ScientistOne, and that every evaluative layer in that study, including ScholarPeer, ran on Gemini. ScientistTwo keeps ScholarPeer, makes its score an explicit optimization target (stop at 8), still reports it as an evaluation, and adds SAR as the held-out judge. ScientistTwo also inherits the CoE audit, but runs it only on its own outputs; ScientistOne applied it across five systems with human confirmation of flagged failures.

Two reviewed papers bear directly on how much weight SAR scores can carry:

- reviews/2605.19156.md (ResearchArena) found that SAR separates 200 human-accepted and human-rejected ICLR 2025 papers by only 0.25 points, where human reviewers separate them by 1.52. SAR accepted 76% of the accepted papers and 52% of the rejected ones. It also found that artifact-aware review lowers agent paper scores, mainly on experimental rigor.
- reviews/2607.27191.md found SAR the most lenient of three AI reviewers. It recommended acceptance on early drafts of two papers whose final versions the original human authors rated 2/6 and 1/6.

Against that background, ScientistTwo's SAR results (5.7 mean, 72.1% acceptance, versus 5.5 for NeurIPS accepted papers) sit inside a band where SAR is known to discriminate weakly. The two papers used SAR on different paper sets, so this is a scale reference, not a correction.

The task design is AutoSOTA's (not reviewed here): improve a published paper's codebase on its own benchmark. That is the regime where a cheap automatic score exists. reviews/2607.27191.md evaluated the opposite regime, open-ended questions judged by the original authors, and found agents failing at research judgment. The two findings are compatible. ScientistTwo shows what a heavy pipeline achieves when the problem, code, and metric are handed over.

Several other reviewed papers bear on specific design choices:

- reviews/2606.11926.md (Arbor) promotes changes only after a held-out check. It shows a coding agent whose development score (75.00) exceeds its held-out score (71.70). ScientistTwo selects and reports on the same benchmark.
- reviews/2411.15114.md (RE-Bench) shows that agent-versus-human comparisons depend on matched time budgets. ScientistTwo's "human state of the art" is the published result, not a human given the same 2.5 days and $3,765.
- reviews/2505.22954.md (Darwin Godel Machine) and reviews/26w2s.md (Automated Weak-to-Strong Researcher) report objective hacking under outcome optimization. ScientistTwo reports one reward-hacking case caught by its filter and documents evaluator gaming by AutoSOTA, while optimizing its own papers against a fixed LLM reviewer.
- reviews/2606.26294.md argues that such fixed evaluators get gamed as agents improve. Table 5 is a small instance of that.
- reviews/2607.07663.md (recursive self-improvement survey) warns that shared generator and evaluator lead to self-confirming loops. The iterative BPE expansion (Table 9) is a bounded, single-task example of a system building on its own outputs, judged by the same kind of reviewers.
- reviews/26oaiacc.md reports that longer agent research tasks inside OpenAI needed more human interventions. ScientistTwo reports none over multi-day runs, on tasks pre-filtered for reproducibility with code provided.
- reviews/2605.20025.md (AutoResearchClaw) appears here only through four public papers in Table 2.

## Critical discussion

**What "outperform human state-of-the-art" measures.** A "success" is declared by LLM critics: the idea is judged Good by the subset and full-set critics, and the run survives the ablation, review, and meta-review loops. The size of the gain is then read off the generated paper's own tables by Gemini 3.6 Flash (L301), and is not re-measured in a common harness. The baseline number is described inconsistently. Table 1 compares against "the original SOTA result" (L103), while Appendix B says each system measures against "its own reproduced baseline" (L832).

The proposed method gets a tuning budget that the baseline does not. Each idea can receive up to two engineering rounds of hyperparameter and code adjustment, an ablation-driven refinement, and a meta-review refinement. Up to eight candidates are compared, and the Selector picks the best using full-benchmark results (L184, L814). No held-out split is mentioned, so selection and reporting use the same numbers. No seeds or confidence intervals accompany any gain.

The pooling also flatters the headline. The 25.2% averages over the 86 successes only. Counting the 21 failures as zero gives about 20%. The median is 7.7%, and Figure 1 has a "> 100% gain" bin, so a few large relative changes on metrics near zero pull the mean up. On the four ICLR tasks where AutoSOTA ran on the same inputs, ScientistTwo's median and mean gains (2.2%, 3.8%) are below AutoSOTA's (5.0%, 7.2%). Appendix B's per-paper gains there are modest: +0.61% QD, +0.006 PLCC, +3.4% on probes.

The task set was also pre-filtered for reproducibility (L798). The system gets the paper and working code, so this is the most favorable version of "research."

What the data do support is narrower than the abstract. On reproducible ML codebases, the pipeline usually finds a modification that its own tables report as better than the source method, with a typical gain in the single digits. "Consistently outperform" and "autonomous scientific pioneer" go well beyond that.

**What "higher review ratings than human-authored papers" measures.** ScholarPeer is the loop's stopping criterion: revise until the score reaches 8. Reporting its ratings as evidence is circular, and the authors acknowledge this (L247, L330). ScholarPeer also shares authors with this paper (L540), and its backbone model is not stated here.

On the held-out SAR the comparison is mixed:

- ICML spotlight subset: ScientistTwo papers score 5.7 against 6.1 for the human papers, with 69.4% acceptance against 96.9%.
- NeurIPS subset: 5.6 against 5.5, with standard deviations of 0.7, and 75.8% acceptance against 76.3%.
- ICLR subset: only 4 ScientistTwo papers against 5 human papers.

Pooling Table 3 myself, the 107 human papers average about 5.85 on SAR with 94 of 107 accepted (88%). ScientistTwo averages 5.7, with 62 accepted, which is 72% of its 86 papers or 58% of the 107 tasks. For scale, reviews/2605.19156.md found SAR accepting 52% of human-rejected ICLR 2025 papers. Even the in-loop ScholarPeer, counted per task, accepts 79 of 107 ScientistTwo tasks, the same count as for the human papers.

The comparison is also unpaired: 86 successes against all 107 human papers. And each generated paper is a follow-up built on the very human paper it is compared with, so it has a built-in advantage on "benchmark breadth." No significance test is reported.

The abstract's sentence therefore holds for ScholarPeer, which was optimized, and for two of three venue subsets under SAR by about 0.1 to 0.2 points. It fails for the ICML subset and for SAR acceptance rates overall.

**Goodhart inside Table 5.** The second rebuttal round raises ScholarPeer acceptance to 93.9% while SAR acceptance drops from 73.5% to 69.4%. SAR's mean rating barely moves across three conditions (5.6, 5.8, 5.7). The authors' reading, that the loop "is generalized across Review Agent" (L330), is supported for the first round only. The round-0 variant already reaches about 49% SAR acceptance before any rebuttal. So much of the held-out score comes from the preceding pipeline, as the authors say, and the rebuttal loop's marginal contribution is small and saturates quickly.

**Baselines and controls.** Table 2 compares against 2 to 21 publicly released papers per system. These were produced on different problems, with different backbones and budgets, and in most cases by other groups. None is a rerun on the 107 tasks. The strongest baseline, ScientistOne, is from the same group, and its 21 papers are also not rerun on these tasks. Table 5 reuses the same 21-paper row for the 49-task ablation.

The missing control is a strong simple baseline: the same coding agent (Claude Code with Opus 4.8) given the paper, the code, and the same $3,765 budget, and asked to improve the method and write it up. That control matters here. Table 8 shows that swapping the coding agent changes success from 80% to 60% and average gain from 3.8% to 16.7% on five tasks, so much of the outcome rides on the coding backend.

The main-text AutoSOTA comparison (Table 4, bolded, "superior performance") is explicitly disowned by the appendix as "not a head-to-head" (L832, L852). The appendix's qualitative contrast (new modules versus configuration edits) is documented for five papers and is the more defensible reading.

**Human evaluation.** Table 10 is the only human signal, and it is thin. The text gives no recruitment details, expertise, or blinding for the nine reviewers, and does not say whether they knew which paper was AI-written or how the 33 papers were assigned. No inter-rater agreement or uncertainty is reported. Taken at face value, the result is parity overall (3.0). Humans are preferred on method soundness (2.9), and the standalone "overall readiness" is the lowest item (3.7).

**Integrity claims.** "Fully verified, executable codebases" (abstract) rests on Table 7. The agents that produce the audited properties run inside the loop. The audit's executor is not identified. The one transcript audits only the proposed method, not the baseline (L1113). No independent or human check of the audit is reported. Table 7 shows that the refinement agents remove citation hallucinations and method-code mismatches as measured by this audit, and that result is useful. It does not show that the claimed improvements are correct.

**The showcased artifact.** The authors present DynaSpec-RAG as evidence that the agent "invests mathematically sound, parameter-efficient solutions" (L446). The generated paper undercuts this in several ways:

- Its central mechanisms barely register in its own ablations. Frequency disentanglement beats a monolithic residual by 0.0004 MSE, and the monolithic variant has the lower boundary error (0.1246 vs 0.1248), although the full model is bolded and described as smoothest. The per-timestep gate, called "the central lever," beats a constant 0.5 gate by 0.0004 MSE. Uniform neighbour averaging matches learned attention.
- "Zero-shot" in its tables means that the 0.27M-parameter module was trained on the pooled training splits of the same seven benchmarks, and that β was calibrated on their validation splits. The comparison foundation models were evaluated without any target-domain training.
- The abstract's "strictly eliminating negative transfer" contradicts the paper's own Table 7, where 2 of 7 datasets regress.
- The same method under the "identical protocol" shows different numbers in Tables 1 and 2 (ETTh1 0.3467 vs 0.3447; Electricity 0.1135 vs 0.1124), with no seeds. The ETTh1 MAE is bolded for the wrong method in the second table.

This is the paper's own example of a success. It shows the ablation-attribution criterion claimed in Table 15 ("requires the gain to be attributable to the proposed mechanism in ablation," L818) failing on the case chosen for display. It also shows that the in-loop reviewer, the meta-reviewer, and the audit all let through prose that contradicts the tables.

The Procrustes-DS trajectory is the better counterexample. There, the ablation critic did strip inert components. The method nevertheless kept a name advertising the two components it had dropped.

**Framing and scope.** The title and abstract claim a system "pioneering the human knowledge frontier." The teaser lists neuroscience, robotics, and game theory as domains. But every task is a recent ML venue paper with provided code, an executable benchmark, and a reproducibility filter. The authors' own limitation, "local algorithmic refinements" (L452), is the accurate description. Contamination is not discussed. The source papers are recent and supplied as input, so the relevant risks are different ones: ideas borrowed from later public follow-ups, given a novelty check against only two search results, and reviewer agents that may recognize the accepted papers. Neither is examined, and I do not have evidence that either occurred. The claim of "significantly faster" research than humans (L377) has no human timing behind it.

**What remains supported.** Given a reproducible ML paper and its code, this pipeline produces, in about 2.5 days and $3,765, a modified method, an ablation study, and a formatted manuscript. It does so on 80% of pre-filtered tasks by its own critics, with a median self-reported gain near 8%. One simulated rebuttal round raises acceptance by a held-out, lenient automated reviewer from about 49% to 73% on 49 tasks. The integrity agents drive this audit's failure counts to zero on 49 tasks. Appendix B credibly documents that its accepted changes are new modules rather than configuration edits, and that its attribution critic at least sometimes rejects gains from generic tuning.

Not established: that the system beats human researchers under any matched comparison; that its papers match accepted human papers under an independent judge (on the held-out reviewer they mostly do not, by acceptance rate); that its gains survive held-out evaluation or seeds; or that any of this extends beyond ML codebase improvement.

## Relevance to us

This is a clear view of where a large-lab AI Scientist recipe stops. It pairs a frontier backbone and a commercial coding agent with a deep multi-agent loop, and uses LLM critics and an in-house LLM reviewer as its judges. There is no domain structure. The only non-LLM check is re-execution. The tasks are all in the band where a cheap scalar benchmark exists. For our AI Scientist loop the useful lessons are about evaluation, not architecture.

First, it strengthens the case for B01. The decisive comparison, the same coding agent with the same budget, is missing, and Table 8 suggests the coding backend drives much of the outcome. When we report Theo against a frontier system, a budget-matched "Claude Code plus the paper" control is the baseline that would have exposed this paper's gains.

Second, it is direct evidence for the trace and watchdog line in our verification programme. DynaSpec-RAG passed every stage here, including citation checks, re-execution, method-code alignment, an LLM reviewer, and a meta-reviewer. Its abstract still says negative transfer is strictly eliminated while its own table shows 2 of 7 regressions, and two of its tables disagree. A deterministic claim-versus-table consistency check is cheap, high-precision, and absent from CoE-style audits. It belongs in B12 and B18 as its own flag type.

Third, Table 5 is a small, quantified Goodhart curve for reviewer-in-the-loop optimization. If Theo uses a skeptic or reviewer agent (B13) to revise drafts, its scores cannot also serve as our quality evidence. A held-out judge's gains can saturate after one round.

Fourth, the ablation-attribution gate is a transferable mechanism: reject a gain the ablation traces to generic tuning. The DynaSpec-RAG case shows that an LLM enforcing it can be fooled by its own narrative. In physics the analogue would be attributing an improved fit to the proposed physical mechanism rather than to added parameters. That is worth enforcing with the numbers, not with an LLM's reading of them.

The paper has no physics content (PhySense is sensor placement), so it says nothing about physics-native verification.
