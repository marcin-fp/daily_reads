ScienceBuddy: Recursive-in-Recursive Self-Improvement for Interactive Scientific Agents. arXiv preprint, 2026. https://arxiv.org/abs/2609.17523v1

## What this paper is about

Correcting an AI assistant's answer within one conversation does not make it better at the next similar task. This paper introduces ScienceBuddy, a deployed biomedical research workspace, and asks how ordinary researcher-agent collaboration (questions, follow-ups, corrections) can be turned into durable improvements rather than one-off fixes. Its technical contribution is "recursive-in-recursive self-improvement": an inner loop that revises the agent's working procedures (instructions and skills) while keeping the underlying model fixed, nested inside an outer loop that retrains the model's weights under whichever procedures the inner loop currently has selected, with both loops fed by tasks and evaluation criteria distilled from real researcher interactions.

## Extended summary

**System.** ScienceBuddy provides 224 tools across 22 modules (genomics, molecular/cancer biology, pharmacology, bioimaging, literature retrieval, database queries) in a persistent, multimodal workspace (documents, tables, sequences, images) with a ReAct-style reasoning-action-observation loop and inspectable execution traces. The agent harness (instructions, skills, context-management procedures) is architecturally separated from the surrounding infrastructure, so procedural revisions can be evaluated under fixed execution conditions.

**From collaboration to tasks and rubrics.** Requests, clarifications, execution records, and artifacts from real researcher sessions are consolidated into self-contained tasks with reconstructed instructions (not the historical answer) and rubrics derived from the full collaboration trajectory; conflicting requirements are resolved before scoring, and researcher approval or historical answers are explicitly not treated as automatic ground truth. These become "Harbor tasks" (instruction, input assets, execution environment, rubric) usable for both rejection-sampling SFT and on-policy RL.

**Inner recursion (harness evolution, model fixed).** At each step, a fixed auxiliary model (GPT-6 Astra, a different model family from the task policy) reviews recent trajectories and rubric evaluations, identifies unmet criteria with cited supporting actions/observations, and proposes exactly one bounded edit (add/remove/revise one scoped skill, edit one instruction, or change one exposed context setting), leaving everything else, including tools, execution infrastructure, rubrics, and evaluators, unchanged. The candidate is evaluated against the current ("parent") harness on identical development tasks, seeds, and budgets; it is accepted only if it strictly improves the mean rubric score (ties retain the parent), and prior successful tasks are included in re-evaluation to catch regressions. Development tasks, RL-training tasks, and the final held-out test set are kept strictly separate; only development tasks inform harness selection.

**Outer recursion (model RL, harness fixed).** Once a harness is selected, task environments are recalibrated (pilot execution with the current model and harness) so that tasks remain appropriately challenging as capability grows, since a harness improvement can make previously hard tasks routine. Task-specific rubrics combine executable checks where available with a fixed judge for criteria requiring scientific interpretation, weighted per criterion, aggregated into a trajectory-level reward. GRPO trains the task model on fresh on-policy rollouts under the fixed, selected harness; afterward the harness is re-evaluated under the updated model before the pair is redeployed, since harness effectiveness depends on its interaction with the specific model using it.

**Case studies (four research questions).** RQ1 (qualitative, real researchers): two real deployed-system interactions (a JAK1 immunotherapy study plan; an ARL4C evidence-linked presentation) illustrate how follow-up requirements translate into task objectives, criteria, and artifacts; no quantitative metric is reported for these. RQ2 (coupled dynamics): starting from Qwen3.5-4B, three successive outer cycles (10 harness-search steps + 20 RL updates each) show validation accuracy rising within each cycle (38.9%→44.4%, 34.4%→46.7%, 61.1%→70.0%) and training reward rising within each RL phase; overall held-out test accuracy rises from 42.2% to 73.3% across the full three-cycle process, with 33.3% of test problems flipping from incorrect to correct and only 2.2% flipping the other way, with gains reported across all four task families (LitQA2, DbQA, ProtocolQA, GWAS, drawn from LAB-Bench and Biomni-Eval1, 895 tasks across 16 subtopics). RQ3 (harness only, model fixed): a standalone harness-adaptation run (288 adaptation conversations, 24 update batches, using a bounded, scripted user simulator, described below) raises validation-set first-response accuracy from 31.1% to 51.1% (+20 points) with model weights entirely unchanged; the selected harness ends with four instruction entries and nine scoped skills covering things like gene-set membership checks and database-specific evidence extraction. RQ4 (model only, harness fixed): holding the initial harness H0 fixed throughout, RL training raises problem coverage (pass@4, fraction of test problems solved in at least one of four attempts) from 48.3% to 67.8% (+19.5 points).

**Simulated feedback loop for RQ3/RQ4.** The quantitative RQ2-RQ4 experiments do not use live researcher feedback; instead a separate, fixed helper model (Qwen3.8-27B) plays a "bounded, reference-assisted" user simulator that selects from a small set of allowed, non-answer-revealing replies (confirm, request a format fix, request a procedural check/redo), and a separate feedback-interpreter role classifies each simulated reply into a ternary diagnostic score used only for harness diagnosis, kept distinct from the trajectory reward used for RL. The paper is explicit that this is a bounded simulator, not unrestricted expert feedback or a human trace, and that RQ1's real researcher interactions are a separate, purely qualitative illustration of the broader collaboration setting.

**Related work and scope.** The paper distinguishes itself from persistent-procedural-adaptation methods (Reflexion, GEPA, ACE, Meta-Harness, PILOT), from recursive-self-improvement methods that evolve the improvement mechanism itself (Darwin Godel Machine, Hyperagents, SEAL), and from learning-from-interaction methods (OpenClaw-RL, RLAnything). It states plainly that its own "reflector" (the harness-editing auxiliary model and the RL algorithm) remains fixed across cycles, so improved task performance under recursive-in-recursive improvement does not imply the improvement mechanism itself has become stronger, distinguishing its nested-loop design from the stronger, meta-level self-improving systems it cites.

## Learnings

Deriving both a task's instruction and its evaluation rubric from the same real collaboration trajectory, rather than treating the historical answer or researcher approval as automatic ground truth, is a specific and transferable design for converting ordinary usage logs into trustworthy training signal: it avoids simply distilling whatever the researcher happened to accept (which could reinforce sycophancy or a wrong-but-approved answer) while still grounding the task and its success criteria in what a real user actually needed.

Constraining each harness-evolution step to exactly one bounded, schema-checked edit (one skill added/removed/revised, one instruction changed, or one context setting changed), evaluated head-to-head against the unedited parent on identical development conditions before acceptance, is a specific and conservative alternative to less constrained harness-search approaches; the explicit inclusion of previously-successful tasks in each re-evaluation to catch regressions is a concrete, reusable safeguard against a common failure mode in iterative prompt/harness editing (fixing today's failure while silently breaking something that used to work).

The paper's explicit scoping statement, that its "reflector" (the auxiliary editing model and the RL algorithm) stays fixed across cycles, so recursive-in-recursive task-performance gains should not be read as evidence that the improvement mechanism itself is getting better, is a useful conceptual distinction for evaluating any paper using "recursive self-improvement" language: a system can nest two nested learning loops (harness and weights) that each genuinely improve, without the meta-level process that does the improving becoming any more capable, and conflating the two claims would overstate what has actually been demonstrated.

## Verification

Verification is built into both recursion levels rather than assumed. Harness candidates are accepted only after head-to-head, paired evaluation against the parent harness on identical development tasks, seeds, and execution budgets, with development, RL-training, and held-out test tasks kept strictly separate and the final test set explicitly never used to inform editing or selection. RL rewards combine executable checks (where scientifically expressible) with a fixed judge only for criteria that genuinely require scientific interpretation, rather than defaulting to an LLM judge for everything, and the diagnostic feedback score used for harness editing is explicitly kept distinct from the trajectory reward used for policy optimization (Table S2 documents exactly which role sees which information, including that the task policy, user simulator, and harness reflector are each denied access to the private answer). What is comparatively under-specified: the paper does not state which model serves as the "fixed judge" for interpretation-requiring rubric criteria during RL (Section 2.4), leaving it unclear whether this judge shares a model family with the task policy, the harness-editing model, or neither. More importantly, the RQ2-RQ4 quantitative results are generated entirely against a scripted, bounded user simulator rather than real researcher feedback (explicitly disclosed by the authors), so while the internal train/dev/test discipline is genuinely careful, the realism of the feedback signal itself, on which the headline recursive-in-recursive numbers depend, is not independently verified against unscripted human interaction.

## Field context

ScienceBuddy's inner recursion is explicitly positioned against "[Meta-Harness](2603.28052.md)" (reviewed in an earlier batch), which the paper cites directly as extending harness search to full harness code using prior candidates and execution records; ScienceBuddy's own harness-evolution mechanism is considerably more constrained by comparison, restricting each accepted edit to one scoped skill, instruction, or context setting under a schema-checked size budget, rather than giving its diagnosing model unrestricted access to rewrite arbitrary harness code, which is a genuine methodological difference the paper's own citation makes explicit rather than one this review infers. Within this same batch, "[AgentGrad](2609.08572.md)" pursues a related but mechanistically distinct goal in multi-agent prompt optimization: both papers diagnose a specific failure from an agent's own execution trace and gate an accepted change behind a validated improvement, but AgentGrad targets which of several cooperating agents' prompts should change (via sequential intervention across a pipeline) and aggregates many sample-level textual gradients into a clustered update, while ScienceBuddy targets a single agent's own harness and proposes one bounded structural edit at a time rather than a natural-language gradient. The paper's explicit citations to HELIX (model-harness co-evolution for recursive self-improvement) and SIA (self-improving AI with harness and weight updates) as its closest joint harness-plus-weight precedents mark this specific research direction (coupling harness evolution with model RL rather than treating either as fixed) as an active, contested area with several concurrently developed variants; neither HELIX nor SIA is yet reviewed in this corpus. No paper in this corpus previously addressed a deployed, interaction-grounded scientific research workspace specifically, making the system-level contribution a new entry point independent of the recursive-in-recursive method itself.

## Critical discussion

The paper's internal experimental discipline is genuinely careful in several specific, checkable ways: strict separation of development, RL-training, and held-out test tasks with the test set never informing selection; an explicit role-information boundary (Table S2) that denies the task policy, user simulator, and harness reflector any access to the private correct answer; a documented distinction between the diagnostic feedback score used for harness editing and the trajectory reward used for RL, so one signal cannot silently substitute for the other; and an isolation design (RQ3, RQ4) that holds one recursion fixed while varying the other, directly answering whether each half of the coupled system contributes independently rather than only reporting the combined system's aggregate gain.

The central limitation, which the paper discloses rather than hides, is that the quantitative headline results (RQ2-RQ4) are generated against a scripted, reference-assisted user simulator rather than real researcher feedback, while the only real-researcher evidence (RQ1) is presented purely qualitatively with no accuracy or coverage metric attached to it. This means the paper's strongest evidence for "recursive-in-recursive self-improvement working" and its strongest evidence for "this reflects genuine researcher collaboration" currently live in two separate, non-overlapping parts of the paper rather than being demonstrated together on the same data, and it is not established how much of the clean, ternary-classifiable feedback structure the simulator provides (accept, correct, new information, new requirement, ambiguous) would survive contact with genuinely open-ended, unscripted researcher dialogue (`narrow-evaluation`). Related to this, no confidence interval, variance across seeds, or repeated-run estimate is reported for any of the headline percentages in RQ2-RQ4, and the exact number of test/validation problems underlying several reported percentages is not stated precisely alongside the percentage itself in the main text (`missing-uncertainty`). The cross-cycle validation-accuracy trajectory in Figure 8(a) also deserves a careful reading: because task environments are deliberately recalibrated to remain challenging as the system improves (Section 2.4), the drop in starting validation accuracy from cycle 1's end (44.4%) to cycle 2's start (34.4%) most plausibly reflects harder recalibrated tasks rather than capability regression, but the paper's own figure plots cumulative harness steps across all three cycles as a single continuous-looking curve, which could be misread as a smooth improvement trajectory rather than three separate before/after comparisons on shifting task distributions; the fixed held-out test set's 42.2%-to-73.3% jump across the full three-cycle process is the more directly comparable headline number precisely because it is not subject to this recalibration. Finally, the backbone used for the quantitative experiments (Qwen3.5-4B) is comparatively small, and the paper does not state whether this is the same model actually running the publicly deployed ScienceBuddy product researchers interact with in RQ1, or a separate research-scale configuration used only for the controlled RinR experiments, which leaves the connection between the quantitative results and the real-world product somewhat underspecified.

What remains well supported after these caveats: the isolated contributions of harness evolution alone (+20 points, model fixed) and model RL alone (+19.5 points, harness fixed) are each independently demonstrated rather than only inferred from the combined system's performance; the train/dev/test separation and role-information boundaries are concretely disclosed and checkable rather than asserted; and the paper's own honest scoping, that its improvement mechanisms (the harness-editing model and RL algorithm) remain fixed across cycles, correctly limits what "recursive-in-recursive self-improvement" is being claimed to demonstrate.
