## What this paper is about

LLM-based agent systems are good general problem solvers, but they communicate entirely through natural language, which is a poor fit for scientific work that increasingly relies on specialized, non-language foundation models, such as ones trained specifically to forecast time series or predict properties of tabular data, that have no built-in way to talk in words at all. This paper proposes Eywa, a framework for letting an LLM agent treat one of these non-linguistic domain specialists as a callable expert it can query and interpret the output of, rather than trying to force the specialist's job into text, and then builds up from a single such hybrid agent to full multi-agent systems, and finally to a planner that automatically decides, per task, which mix of language agents, domain specialists, and communication structure to use.

## Extended summary

The paper's core building block is the "Tsaheylu" interface (named after the neural-bond concept from the film Avatar), a bidirectional communication channel connecting a language model to a domain-specific foundation model F_k that does not natively understand language. A query compiler function translates the current reasoning state into a structured invocation of F_k (implemented concretely via the Model Context Protocol, with each foundation model exposed as a remote MCP service with a defined input/output schema), and a response adapter function converts the specialist's structured output back into a form the language model can incorporate into its ongoing reasoning. An EywaAgent combines a language model with one such interface and a control policy that decides, at each reasoning step, whether to invoke the foundation model or continue reasoning purely in language; because this control policy always retains the option to skip the specialist entirely, an EywaAgent formally subsumes a plain language-only agent as a special case. The paper offers a short formal argument (Theorem 3, building on an explicit "Domain Advantage" assumption that a domain-specific foundation model strictly outperforms any language-only model when the input is meaningfully structured/domain-specific) that an EywaAgent's optimal achievable task loss is no worse, and strictly better whenever the domain-specific component is informative, than that of a language-only agent, since the EywaAgent's action space is a strict superset that includes the language-only agent's behavior as one option. This same architecture is then extended to EywaMAS, a multi-agent system in which some agents are ordinary LLM agents and others are EywaAgents, with the paper noting existing multi-agent systems can be converted into an EywaMAS with minimal structural change (simply swapping some agents for EywaAgents while keeping the same communication topology), and to EywaOrchestra, where a "conductor" (itself an LLM) selects, per task, which language models to use, which domain-specific foundation model(s) to attach as EywaAgents, and which communication topology from a fixed candidate pool to instantiate, motivated by the observation that the best fixed multi-agent configuration for one task type may not be best for another.

To evaluate the framework, the authors introduce EywaBench, a new benchmark assembled from four existing scientific and general-reasoning resources (DeepPrinciple for scientific QA/hypothesis reasoning; MMLU-Pro's science-relevant questions, converted from multiple-choice to open-ended; fev-bench for realistic time-series forecasting; and TabArena for tabular classification/regression), organized into three parent domains (physical, life, social science), each with three sub-domains (e.g., physical: material, energy, space), spanning three data modalities (natural language, time series, tabular). The released evaluation split, EywaBench-V1, contains 200 task instances drawn from 67 distinct underlying source datasets, and the authors report several diversity/balance statistics (near-uniform coverage across the three parent domains, sub-domains, and modalities, measured via normalized Shannon entropy values all above 0.84, with the single largest source dataset contributing only about 20% of samples) intended to demonstrate the benchmark is not dominated by any one domain, modality, or source. A unified utility score in [0,1] is defined per task, computed via exact/numeric-relative-error/lexical-overlap matching for language tasks and via a combination of symmetric mean absolute percentage error and mean arctangent absolute percentage error for time-series and tabular numeric-target tasks, chosen so that scores are directly comparable across the three otherwise very different modalities.

The two concrete domain-specific foundation models used in the main experiments are Chronos (a general-purpose pretrained time-series forecasting model) and TabPFN (a transformer that solves tabular prediction via in-context learning in a single forward pass), neither of which has a native language interface. Compared against single-LLM-agent baselines (GPT, Gemini, and Claude families), homogeneous LLM-only multi-agent baselines (Refine, Debate) instantiated on the same backbone, and heterogeneous LLM-only multi-agent baselines that combine multiple different language models without any non-linguistic specialist (Mixture-of-Agents, X-MAS), the results show: EywaAgent improves average utility by about 6.6% over the matched single-LLM-agent baseline while cutting token usage and latency by close to 30%, attributed to delegating structured-data computation to the specialist rather than reasoning over it token-by-token in language; EywaMAS achieves the best overall utility among all multi-agent methods tested, outperforming both homogeneous baselines (using fewer tokens than Debate under the identical debate topology) and the heterogeneous-LLM-only baselines, which the authors interpret as evidence that combining different language models alone is a weaker form of heterogeneity than combining language models with genuinely non-linguistic specialists for scientific workloads specifically; and EywaOrchestra, despite using no expert-specified configuration and instead letting its LLM-based conductor automatically select the foundation model and topology per task from a fixed candidate pool, reaches utility close to (and on several sub-domains exceeding) the expert-configured EywaMAS, while substantially reducing both token usage and latency relative to the fixed multi-agent systems. A further, specific observation from the per-domain breakdown is that not every domain benefits from heavier multi-agent machinery: in economy and business tasks, the single-agent EywaAgent is already highly competitive, which the authors use to motivate the value of task-adaptive orchestration rather than always defaulting to a more complex multi-agent pipeline. Additional experiments show the framework's gains are robust across a range of LLM sampling temperatures, the tabular foundation model's softmax temperature, and different prompting strategies (detailed instructions, chain-of-thought, ReAct), and that performance improves, as expected, when swapping in progressively more capable LLM backbones (gpt-4.1-nano to gpt-5-nano to gpt-5-mini) while the qualitative pattern of Eywa's advantage over the corresponding single-agent baseline persists across all three.

## Learnings

The paper's most broadly transferable conceptual contribution is a clean, general abstraction (the query-compiler/response-adapter interface pair, concretely realized via the Model Context Protocol) for incorporating any non-linguistic specialist model into an LLM agent's reasoning loop as a first-class, dynamically-invokable participant rather than either forcing its input/output through a lossy text serialization or treating it as an opaque, always-called tool; the explicit control policy that can choose to skip the specialist entirely is a small but important design detail, since it means the resulting system can never do categorically worse than the pure language-only baseline it is built on top of, only potentially better when the specialist is actually useful.

A second, more empirically grounded and directly useful learning is the specific finding that combining several different language models (heterogeneous-LLM-only multi-agent systems) is not, by itself, a reliable source of improvement on scientific tasks that involve genuinely structured, non-linguistic data, whereas combining language models with even a small number of specialized non-linguistic foundation models is; this is a concrete, falsifiable claim about where multi-agent heterogeneity actually pays off for this class of tasks, distinct from and more specific than the more general intuition that "more diverse agents should help."

A third, more practically-oriented learning is the paper's demonstrated case for task-adaptive orchestration over a fixed multi-agent design: the observation that a single, simple EywaAgent is already highly competitive on some task types (economy, business) while more elaborate multi-agent coordination pays off on others is a concrete, quantified instance of a broader principle worth generalizing beyond this paper, that the right amount of agentic machinery to deploy is itself something a system should learn to vary per task rather than being fixed in advance by the system designer.

## Verification

The paper takes real, specific steps to check that its new benchmark is not trivially biased in ways that would make method comparisons uninformative: it reports normalized Shannon entropy statistics for the distribution of task instances across parent domains, sub-domains, and data modalities (all above 0.84, with the fully-uniform maximum being 1.0), and separately reports that the single largest of 67 distinct underlying source datasets contributes only about 20% of the benchmark, directly and quantitatively addressing the concern that method rankings might simply reflect performance on one dominant source distribution rather than genuine cross-domain, cross-modality capability. The core architectural claim (that EywaAgent cannot do worse, and can do strictly better, than a language-only agent) is backed by an explicit theorem with a stated assumption and a proof deferred to the appendix, rather than only asserted informally, and the corresponding claim for the multi-agent extension (EywaMAS) is stated to follow analogously. The main empirical comparison is run against a genuinely varied set of baselines spanning three distinct categories (single-agent, homogeneous multi-agent, heterogeneous-LLM-only multi-agent) rather than only a single weak point of comparison, and a dedicated hyperparameter-sensitivity study (LLM sampling temperature, foundation-model softmax temperature, prompt design) plus a separate LLM-backbone ablation are included specifically to check that the reported gains are not an artifact of one particular configuration choice.

Verification is comparatively thinner in two related places. First, the theoretical result (Theorem 3) is, on inspection, close to an immediate structural consequence of the paper's own construction rather than a substantive, independently informative claim: because an EywaAgent's control policy always retains the option to reduce to exactly the language-only agent's behavior (the "skip" branch), and the paper's own Assumption 1 stipulates by fiat that the attached foundation model is strictly better on the relevant subtask whenever that subtask is informative, the "strict improvement" conclusion follows almost definitionally from having a superset of available actions that includes an assumed-better option, rather than from any additional analysis of when or how much this architectural flexibility helps in practice; the paper does not discuss this near-tautological character of the result, and readers should not take Theorem 3 as establishing anything about the actual, non-guaranteed empirical question of whether a given real foundation model (Chronos, TabPFN) actually possesses this assumed domain advantage on a given real task, which is precisely the question the empirical benchmark, not the theorem, is positioned to answer. Second, the main results table (Table 1) reports point-estimate utility, latency, and token counts for each method across nine sub-domains without any reported standard error, confidence interval, or significance test, despite several sub-domain cells containing quite small sample counts (as few as 15 total task instances in the smallest sub-domain, further subdivided across three data modalities); some of the reported per-sub-domain utility gaps between methods (e.g., single-LLM-agent versus EywaAgent on the Space sub-domain) are numerically substantial but are not accompanied by any statistical basis for judging whether they exceed what might be expected from ordinary sampling variability at this scale.

## Field context

The paper explicitly positions itself against three related lines of work it distinguishes directly: scientific LLMs and language-centric scientific agentic workflows, which it argues remain fundamentally limited by treating all scientific data as text or symbolic sequences even when a more faithful, structure-preserving representation exists; the broader ecosystem of domain-specific scientific foundation models (time-series models, TabPFN and successors, materials-science interatomic-potential models like GNoME and MACE-MP-0, weather models like GraphCast and Pangu-Weather, and protein models like AlphaFold and the ESM family), which it credits with strong domain-specific predictive power but critiques as lacking any native language interface that would let them participate directly in an agentic reasoning loop; and existing orchestration frameworks for multi-agent systems (AutoGen, MetaGPT, and more recent learned-orchestration approaches like evolving-orchestration and difficulty-aware routing), which it argues remain fundamentally language-centric, treating any non-linguistic expert models only as passive, always-the-same callable tools rather than as dynamically-selected, heterogeneous participants on equal footing with language agents. Within this corpus, EywaOrchestra's core mechanism, a conductor that selects agent roles, backbone models, and communication topology per task from a candidate pool, is a direct structural relative of [2512.04388] (the Conductor) and [2512.04695] (TRINITY), two other multi-agent orchestration papers reviewed earlier in this batch, though this paper's specific axis of heterogeneity is data modality (bridging non-linguistic domain specialists into the loop) rather than those two papers' focus on coordinating multiple different, all-language-native LLM providers; a natural, currently-unexplored question connecting all three is whether a single orchestration framework could jointly learn to select across both axes of heterogeneity, modality-specialized non-linguistic tools and multiple competing language-model providers, at once. This paper's broader ambition, extending agentic AI systems to genuinely participate in scientific workflows involving structured, non-linguistic data, also sits within the same territory surveyed by [2510.09901] (the autonomous-agents-for-science survey, reviewed earlier in this batch) and concretely instantiated by [2510.26887] (Denario, also reviewed earlier in this batch), both of which are directly concerned with agentic systems that must eventually run real computation and analysis on real scientific data rather than only reasoning about it in natural language; Eywa's MCP-based Tsaheylu interface offers one concrete, generalizable mechanism for exactly the kind of "acting in the physical/computational world beyond language" capability those two papers identify as a key bottleneck for current AI-for-science systems.

## Critical discussion

The paper's empirical design has real strengths: three genuinely distinct categories of baseline are tested rather than only a weak strawman, the new benchmark's balance and source-diversity statistics are reported quantitatively rather than only asserted, and a real hyperparameter-sensitivity and backbone-ablation study is included to check the robustness of the central comparative claims, all of which meaningfully strengthen confidence that the reported EywaAgent/EywaMAS/EywaOrchestra advantages are not narrow artifacts of one specific configuration.

The clearest limitation is the paper's central theoretical result, Theorem 3, which on close inspection provides less substantive information than its presentation as a formal theorem with an appendix proof might suggest: because the EywaAgent architecture is constructed so that it always retains the option to behave exactly like the language-only baseline, and the paper's own stated assumption stipulates that the attached foundation model is strictly better whenever the domain-specific input is informative, the conclusion that EywaAgent's optimal risk is no worse (and sometimes strictly better) follows nearly automatically from the construction itself rather than from any deeper analysis of when this architectural flexibility actually translates into practical gains; this is not a mathematical error, but it does mean the theorem functions more as a formal restatement of the architecture's design intent than as independent theoretical evidence that the approach works, and the paper's own empirical section, not the theorem, is what actually establishes whether real specialist models (Chronos, TabPFN) deliver the assumed domain advantage on the real tasks tested. A second, more moderate limitation is the absence of any reported variance, confidence interval, or significance test for the main comparative results in Table 1, despite several sub-domain evaluation cells containing quite small sample counts (as few as 15 task instances, further split across three modalities); several of the specific per-sub-domain utility differences highlighted in the paper's own discussion are therefore reported without a stated basis for distinguishing a real, reproducible effect from sampling noise at this scale, even though the paper's overall, aggregated pattern (EywaAgent, EywaMAS, and EywaOrchestra all outperforming their respective baselines) is consistent enough across many domains and metrics to make a purely-noise explanation for the whole pattern implausible. A third, smaller and largely self-disclosed limitation, noted directly in the paper's own Limitations section, is that EywaBench-V1's 200-instance evaluation split, while deliberately designed to be balanced and diverse, is still a comparatively small, curated slice of a much larger possible benchmark space, and the framework has so far only been demonstrated with two concrete domain-specific foundation models (Chronos and TabPFN), leaving open how well the same Tsaheylu interface design generalizes to the very different input/output schemas of other specialist model families (e.g., protein structure or materials-science models) the paper cites as motivating examples but does not itself integrate or test.

What remains well supported after these caveats: augmenting a language agent with the ability to dynamically invoke a genuinely non-linguistic domain-specific foundation model, with the explicit option to skip that model when it is not useful, measurably improves task utility while reducing token and latency cost relative to a matched language-only agent, across a benchmark deliberately constructed to be balanced across domain and modality; this same pattern of improvement, and the specific finding that heterogeneous-LLM-only multi-agent systems do not reliably match this benefit, replicates consistently across the single-agent, fixed-multi-agent, and dynamically-orchestrated settings tested; and the finding that different task domains benefit unequally from added agentic complexity is a genuine, specific, and actionable empirical observation, independent of how rigorously the paper's own formal theorem establishes the architecture's guaranteed benefits in the abstract.
