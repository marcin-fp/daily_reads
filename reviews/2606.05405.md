Citation: Sun, Y., Han, X., Zhang, W., Pang, Y., Wang, T., Cao, Y., Huang, Y., et al. Agents' Last Exam. arXiv preprint, 2026. https://arxiv.org/abs/2606.05405v2

## What this paper is about

AI systems keep clearing celebrated benchmarks (olympiad math, competitive programming), yet this hasn't translated into measurable economic transformation in most industries. This paper argues the disconnect is largely an evaluation problem: existing benchmarks either test abstract knowledge, narrow software-engineering tasks, or a handful of curated domains, none of which represent the breadth and duration of real professional work. Agents' Last Exam (ALE) is a benchmark of over 1,000 task instances spanning all 55 digital-work subfields the US occupational taxonomy (SOC 2018/O*NET) defines, built by recruiting 250+ industry practitioners to contribute actual projects they have already completed — not synthetic scenarios — and scoring the results with deterministic scripts or narrow rubrics rather than open-ended LLM judgment wherever possible. The headline finding is that even frontier "generalist computer-use agents" clear the easiest tier at under 50% and the hardest tier at under 10%, with most mainstream harnesses scoring near 0% on the hardest tasks.

## Extended summary

ALE's task taxonomy is derived by screening all 1,016 O*NET 30.2 occupation records with a fixed LLM prompt for in-scope digital workflows, consolidating them to 117 unique SOC base codes, grouping by field/methodology/work-product similarity into 51 SOC-anchored subdomains, and adding four frontier subdomains plus seven extensions for emerging digital work not yet reflected in SOC 2018 — yielding 55 subdomains across 13 top-level industry clusters (engineering/architecture, business/finance, life sciences, health/medicine, visual/media arts, and others), all with non-zero task coverage. Tasks must satisfy three admission criteria: representativeness (using the actual software a domain professional would use, e.g. SolidWorks/Rhino rather than AutoCAD for a given workflow), complexity (an end-to-end deliverable requiring a coupled multi-step workflow, not a single UI action), and verifiability (a deterministic or rubric-checkable artifact). A five-gate construction pipeline (expert sourcing via an advisory committee, task submission through a public portal, conference-style first-pass review, engineering implementation with dry-runs, and final peer QC) converts practitioner-submitted past projects into runnable benchmark instances; of 1,490 total task instances, 960 come from external expert submissions and 530 are internally commissioned, with only 150 (~10%) released publicly and the rest held private for rolling, anti-contamination evaluation (private tasks periodically rotate into the public pool as retired public tasks are replaced).

The evaluation pipeline decouples task specification (an executable main.py with load/start/evaluate lifecycle functions), agent (a harness plus foundation model), and environment (a remote VM with input/software/output/reference directories), so any conforming agent can run on any task unmodified. Scoring composes two axes — comparison form (exact/hashed values, tolerance-bound numeric fields, geometric distance, vision-LLM appearance judgment, behavioral world-state checks, or free-text rubrics) and composition (a binary gate that must pass before a continuous quality metric is scored, or averaged checklist/per-file scores) — and the paper states ALE "deliberately avoids LLM-as-judge wherever a deterministic alternative exists," rejecting task proposals whose only verification path is "ask a model if it looks right"; the minority of tasks that do need an LLM judge use narrow, evidence-anchored yes/no probes rather than holistic scoring. The paper defines the target evaluation subject as a Generalist Computer-Use Agent (GCUA) spanning five functional layers (Brain/reasoning, Eyes/GUI perception, Body/orchestration, Hands/tool invocation, Feet/runtime), arguing existing CLI-agents (SWE-agent) and GUI-agents (vision-language-action systems) each cover only part of this surface, and lifts CLI-native harnesses (Claude Code, Codex, OpenClaw) to GCUA via a "GUI-as-Tool" or "GUI-as-SubAgent" bridge exposing desktop actions as ordinary tool calls.

Main results (Table 1) evaluate agent-harness/backbone-model combinations across three difficulty tiers: Near-Term (67 tasks, current frontier top pass rate ~38%), Full-Spectrum (55 tasks, one per subdomain for broad coverage), and Last-Exam (38 hardest tasks, near-universal 0% pass rate). The strongest configuration (Codex with GPT-5.5) reaches 38.1%/22.7%/0.0% full-pass rates across the three tiers (24.0% overall); most mainstream harnesses record exactly 0.0% on Last-Exam, with only three configurations (Codex, Cursor, Droid variants) reaching a non-zero 2.6%. On ALE-CLI, a 105-task Linux-only subset directly comparable to Terminal-Bench, the same strongest configuration that scores 82% on Terminal-Bench reaches only 23.3% overall on ALE-CLI, with 0.0% on its hardest tier — offered as direct evidence that ALE's tasks require substantially longer, harder agent sessions than an existing terminal-focused benchmark despite superficial domain overlap. A self-implemented reference harness, ALE-Claw (a simplified OpenClaw derivative without long-term memory or personalization features), performs comparably to full OpenClaw when the backbone model is held fixed, suggesting the basic GCUA components (single action loop, modular tools, GUI-as-Tool, context compaction) are sufficient to match a more full-featured product harness for single-task benchmark evaluation. Domain-level analysis finds computational mathematics and agriculture/environment scoring highest (~55-85%) and education lowest (under 25%) for both evaluated frontier models, a pattern the authors attribute to uneven training-data exposure across domains rather than a fundamental capability gap. A failure-taxonomy analysis of Claude Code + Opus 4.7 failures finds "Understanding" and "Approach" failures (domain-knowledge gaps causing agents to default to ad-hoc scripts instead of the intended professional software) account for roughly three-quarters of failures, more than execution-level bugs. A tool-usage analysis reports that although 34% of public task instances designate graphical domain software as the primary intended tool, GUI-tool usage stays low across configurations because agents substitute Bash/CLI workarounds. Appendix-reported additional analyses (cited from the main text) find model choice explains roughly 3x the score variance of harness choice among well-engineered systems, and that higher resource consumption (cost, time, tokens) does not reliably predict better performance. The paper positions ALE against 16 prior benchmarks (Table 2): knowledge/exam benchmarks (MMLU, GPQA, HLE) test what a model knows, agentic/computer-use benchmarks (SWE-bench, OSWorld, WebArena, GAIA, Terminal-Bench, PinchBench) add interaction but cover only a handful of domains via curator-authored tasks, and the closest prior work — GDPval and the Remote Labor Index — targets economically grounded, project-scale evaluation but covers only 16 and 14 of ALE's 55 industries respectively and relies on expensive human grading rather than automated deterministic verification; ALE claims to be the first to cover all 55 industries with expert-sourced tasks and fully automated scoring. Funding: Tianqiao & Chrissy Chen Institute, Snorkel AI, and UniPat AI provided financial and credit support; no other grants are disclosed.

## Learnings

The five-layer GCUA capability decomposition (Brain/Eyes/Body/Hands/Feet) is a clean, reusable framework for classifying any agent system by which parts of the full computer-use surface it actually covers — it makes precise and falsifiable the paper's specific claim that CLI-agents and GUI-agents are not simply weaker or stronger versions of one general "agent" capability but cover genuinely disjoint operational surfaces, which is a useful lens for evaluating any future agent architecture regardless of this specific benchmark.

The finding that model choice accounts for roughly 3x the performance variance of harness choice (among well-engineered harnesses) is a transferable, decision-relevant result for anyone choosing where to invest engineering effort in an agentic system: for a reasonably mature harness, swapping the backbone model matters substantially more than further harness engineering, at least within the range of harnesses tested here (a reference implementation, ALE-Claw, matching a full-featured product harness like OpenClaw further supports this, since it suggests harness sophistication beyond a basic competent implementation has diminishing marginal value).

The "gate-and-score" verification pattern (a binary precondition that must pass — no collision, file parses, no crash — before a continuous quality metric is even evaluated, with gate failure forcing a zero score regardless of partial progress elsewhere) is a reusable, generalizable verification design for any benchmark trying to score heterogeneous real-world deliverables without resorting to LLM-as-judge: it lets an automated pipeline distinguish "fundamentally broken" from "graded partial credit" without needing to hand-write a bespoke scoring function for every possible way an output can be malformed.

## Verification

Verification is a central design commitment of this paper, not an afterthought: every task's evaluate() function is a deterministic script or narrow evidence-anchored rubric written and reviewed by the same domain experts who supplied the task, and the paper explicitly rejects any task proposal whose only verification path would be a holistic "does this look right" LLM judgment, which is a stronger anti-shortcut discipline than most agentic benchmarks in this space (the paper's own Table 2 positions this directly against GDPval and the Remote Labor Index, both of which rely on human expert grading). The public/private release split, with periodic rotation, is a specific and testable anti-contamination mechanism, and Appendix D.1 (referenced but not read in full here) is stated to verify empirically that the public subset is representative of the full private pool — a reasonable check whose actual numbers this review has not independently confirmed from the sampled appendix material. The paper's own disclosed limitation on statistical rigor is that "due to compute budget constraints, only a subset of configurations include repeated runs" — most cells in the large main-results table (Table 1) are single-run point estimates, and only a minority carry a reported standard deviation (denoted by superscript ± values from three independent runs), so most of the fine-grained ranking differences between similarly-scoring configurations in Table 1 cannot be distinguished from run-to-run noise using the data the paper itself provides.

## Field context

ALE sits at the frontier of a fast-moving "economically grounded agent benchmark" niche it explicitly maps itself against (GDPval, Remote Labor Index, Terminal-Bench, PinchBench, OSWorld, WebArena, GAIA, SWE-bench), and its central methodological bet — replacing GDPval/RLI's human expert grading with deterministic or narrowly-rubricked automated verification at comparable or greater domain breadth — is a genuine attempt to resolve the realism-vs-verifiability trade-off that the paper argues has forced every prior benchmark in this space to sacrifice one of realism, breadth, or verifiability. The paper's own GCUA harness taxonomy and its choice of baseline systems (Claude Code, Codex, OpenClaw, Cursor, Droid, Hermes, ForgeCode, Terminus, OpenHands) directly overlaps with the systems examined architecturally in [reviews/2604.14228.md](2604.14228.md) ("Dive into Claude Code: The Design Space of Today's and Future AI Agent Systems"), reviewed earlier in this batch, which reverse-engineers how Claude Code, OpenClaw, and Hermes each answer recurring design questions (context management, sub-agent delegation, safety posture); this paper's finding that a simplified from-scratch reference harness (ALE-Claw) matches full OpenClaw's performance once the backbone model is fixed is a direct, if indirect, empirical data point bearing on that other paper's architectural analysis — it suggests the specific product features that differentiate a full-featured harness from a minimal one contribute little to single-task benchmark performance, even if they matter for the interactive, multi-session use cases those systems are actually built for. The benchmark's finding that agents route around intended domain-specific GUI software via Bash/CLI substitutes (Sec. 4.2) is also a concrete, measured instance of a broader pattern noted in this corpus's other agentic-evaluation papers — that verification checking final output state, rather than process fidelity, can reward an agent for solving a task in a way that does not actually demonstrate the professional-software competence the task was designed to probe.

## Critical discussion

The benchmark's core design is unusually disciplined for its scale and ambition: grounding task scope in an external, non-arbitrary occupational taxonomy (SOC 2018/O*NET) rather than an ad hoc industry list, sourcing tasks from practitioners' own completed work rather than synthetic scenarios, and enforcing a strict preference for deterministic verification over LLM-as-judge are all methodological choices that directly and credibly address specific, named weaknesses of the closest prior benchmarks (GDPval, RLI) rather than simply claiming to be harder or broader. The domain-level and failure-taxonomy analyses (Section 4.2) go beyond a single leaderboard number to offer a mechanistic account of where current agents fail (domain knowledge and approach selection, not raw execution), which is more actionable than an aggregate score alone.

The main limitation, which the paper discloses but does not fully mitigate, is statistical: compute-budget constraints meant only a subset of the many reported agent/harness/model configurations received repeated runs, so most of the fine-grained rankings in the large main table — a natural target for anyone using this benchmark competitively — rest on single-run point estimates with no way to distinguish genuine differences from run-to-run variance, in a setting (long-horizon, multi-hour agentic execution with tool use and GUI interaction) that is plausibly noisier than typical single-turn LLM evaluation. A second, more structural limitation concerns what "verified" actually certifies: the paper's own tool-usage analysis shows that even though 34% of public tasks designate a specific professional software tool as the intended means of completion (part of the "Representativeness" admission criterion), agents frequently complete these tasks via generic Bash/CLI workarounds instead — meaning a task's deterministic output-based verification can be satisfied without the agent ever exercising the domain-specific tool fluency the task was constructed to test, a possible gap between what the benchmark's design principles aspire to measure and what its evaluate() functions actually check, which the paper's methodology section does not directly address. What remains solidly supported: current frontier generalist computer-use agents are genuinely far from completing the hardest tier of real, expert-verified professional workflows across a very broad taxonomy of industries (near-universal 0% on Last-Exam), the gap between existing narrower agentic benchmarks (like Terminal-Bench) and ALE's harder, longer-horizon tasks is real and substantial even within a directly comparable CLI-only subset, and the specific finding that domain-knowledge and strategy failures dominate over raw execution failures is a well-supported, mechanistically grounded characterization of the current capability ceiling rather than an aggregate score alone.
