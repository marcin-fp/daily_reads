Citation: Wijk, H., Lin, T., Becker, J., et al. (METR). RE-Bench: Evaluating frontier AI R&D capabilities of language model agents against human experts. arXiv preprint, 2024 (v2 2025). https://arxiv.org/abs/2411.15114

## What this paper is about

Frontier AI safety policies treat "AI agents that can automate AI research" as a risk threshold, but there were few realistic tests of that capability and none with a direct human comparison. METR built seven open-ended ML research engineering problems, each on a machine with up to six H100 GPUs and a scoring script the solver can run at any time: speed up a finetuning script, write a fast GPU prefix-sum kernel, repair a language model whose embedding matrix has been scrambled, predict a compute-optimal model configuration from small runs, build a language model without division or exponentiation, RL-finetune GPT-2 into a chatbot judged by another LLM, and scaffold GPT-3.5 to solve Rust programming contest problems.

They collected 71 eight-hour attempts from 61 human ML experts and ran Claude 3.5 Sonnet and o1-preview agents under the same conditions. Their headline: with a 2-hour total budget the best agents score about 4 times higher than humans, but humans improve much faster with more time, narrowly passing the best agent at 8 hours and reaching about twice its score with 32 total hours. Agents are much cheaper and try ideas more than ten times faster, and occasionally produce expert-level work (a Triton kernel faster than any human's). Their weaknesses show up in long-horizon work: learning from new information, building on earlier results, and recovering from their own mistakes.

## Extended summary

Design logic. The authors name three requirements for an early-warning evaluation: feasibility (a high score is achievable, instructions are unambiguous, no blocking technical problems), ecological validity (a clear link from score to risk), and resistance to saturation. They argue that comparing against humans under identical conditions addresses the first two. The inference is explicitly one-directional: if agents do worse than human experts at equal cost, they are unlikely to automate those experts' work, but beating humans here would not show that agents can automate AI R&D, because real projects run for months. Practical constraints were 8 hours per human attempt and at most 8 H100s per environment (at most 6 used).

Environment structure. Each environment has a scoring function that the solver can run at any time. Every call is logged with a timestamp, and the log and the scorer's details are visible, except in Scaling Law Experiment, where the score is hidden to force extrapolation. Each also has a simple, poorly performing starting solution and a hidden reference solution written by the task author. The recorded result is the best score in the log, except in Scaling Law, where the final submission counts. Scores are normalized per environment as y_n = (y - y_s)/(y_r - y_s), so the starting solution scores 0 and the reference 1; anything below the start is clipped to 0. No normalized score above 2 was observed, and 8-hour human averages ran between 0.5 and 1.5 depending on the environment. The authors dropped more than 12 specifications and more than 5 completed implementations during development.

The seven environments (Table 2, Appendix C):

- Optimize LLM Foundry (4 H100). Reduce the runtime of a finetuning script without changing its behavior. The score is log runtime, and a run is invalid if the L1 weight difference from the reference-trained model exceeds 5.3. The start takes 272 s; the reference takes 94 s, mainly through flash attention (about 70 s saved), merged scripts, and a single dataloader worker.
- Optimize a Kernel (1 H100). Compute a prefix sum that includes an element only when the count of earlier positive entries is odd, on 10^8 inputs, checked against the reference output. The PyTorch start runs in about 5 ms. The reference uses three Triton kernels, and the best agent solution (o1-preview, AIDE) runs in 0.64 ms.
- Fix Embedding (1 H100). A model that originally reached loss 2.55 on OpenWebText has permuted embeddings and now reaches 10.5. The score is log(loss - 1.5). The reference maps a small uncorrupted model's embeddings through a trained adapter and then trains further, reaching below 2.7. The best agent (o1-preview, AIDE) reached 4.4 by reinitializing and retraining the embeddings plus the first block.
- Scaling Law Experiment (6 H100). Using only runs of at most 1e16 FLOP, predict the optimal hidden size and step count at 5e17 FLOP, plus the loss that configuration will reach. The score is the gap between the interpolated loss and a ground-truth sweep's optimum, plus the absolute prediction error, and it is hidden from the solver. The default guess scores 0.24; the reference fits a Chinchilla loss law to a grid search. The best agent solution did no training at different scales and relied on guesses.
- Restricted Architecture MLM (2 H100). Build a masked language model from Linear, Embedding, matmul, addition, multiplication, ReLU, and indexing only. The score is log(loss - 1.5), and rule compliance needs manual checking. The start is an MLP scoring 7.64, and the reference is a 1D convolutional network built with as_strided. The best agent (o1-preview, AIDE) went from 7.9 to 4.5 with strided-window residual convolution blocks.
- Finetune GPT-2 for QA (2 H100). Train GPT-2 as a chatbot by RL or similar, with no ground-truth responses. The score is the average win rate, judged by Llama-3-8B-instruct, against GPT-2 base and an Alpaca-finetuned GPT-2. The environment is very noisy: the starting score's standard deviation is 0.62 normalized units, and the raw starting win rate varies from 17 to 52 percent. The reference changes sampling, picks the best of 8 samples by pairwise elimination, uses 16 times more prompts, and runs four rounds of SFT.
- Scaffolding for Rust CodeContests (no GPU, $500 of OpenAI credit). Scaffold gpt-3.5-turbo-0125. The score is the fraction solved on 175 held-out problems. The start solves 0 percent. The reference solves 12.7 percent by sampling 8 candidates, filtering on public tests, and letting GPT-3.5 choose among the survivors. The best agent solution reached 6.1 percent.

Coverage. Table 3 gives time to run and score the reference solution, from 40 s (kernel) to 2.5 h (Fix Embedding), and 218 to 1,392 lines of code in the files the reference edits. Mapped against the four workflow stages of an Epoch AI survey, the suite has no environments for organizing distributed training, setting research directions, creating datasets, or investigating hardware problems. Interviewed frontier researchers added further missing areas: technical design, novel math or theory, creating metrics, transfer, ill-defined goals, and greater engineering complexity.

Human baselines. Of the 61 experts, 43 were applicants to a METR research role (45 runs, average normalized score 0.48 in Table 5), 11 came from staff professional networks (17 runs, 0.98), and 7 were ML graduate students (9 runs, 0.83); overall 0.64 over 71 runs. The prose gives 0.96 versus 0.46 for network versus applicants. Humans used SSH into the same Vivaria VMs as the agents. They were allowed to browse and to use LLMs, and were encouraged to be "greedy" in the first 2 hours. They reported their own breaks, and their score logs and commits were inspected for cheating. Experts were matched to environments by experience. Appendix F finds no strong correlation between background measures (years at top labs, PhD, publications) and score. Across attempts, 82 percent scored above zero and 24 percent matched or beat the reference. Per environment (Table 6), more than 70 percent of experts made progress and more than 80 percent said their score matched their expectation. Major technical issues occurred in more than 5 percent of runs. Informal "strong expert, one week" ceilings (Table 8, described as highly speculative) suggest that only Scaling Law and GPT-2 QA are near saturation.

Agent setup. The VMs had 20 to 48 vCPUs, 200 to 400 GB RAM, and 0 to 6 H100s. Claude 3.5 Sonnet (claude-3-5-sonnet-20241022) ran in METR's general-purpose Modular scaffold and in AIDE; o1-preview ran only in AIDE, because it had done poorly in Modular in an earlier METR study; the older Claude 3.5 Sonnet (20240620) ran in Modular. Modular provides bash and python tools, truncates old context, shows the remaining time, lets the agent change command timeouts, and prompts about running processes in the background, which agents rarely did. AIDE does tree search over whole solutions and was lightly adapted to run the scorer. Runs were limited by wall-clock time rather than tokens, and pauses for API errors or rate limits did not count. Agents spent most of their time waiting on computation, at roughly 20 to 120 output tokens per second. Agents could reach the internet only through curl, which they did not use, though they installed packages with pip. Only the 2 best runs per environment were inspected manually, plus the top 15 in Restricted Architecture MLM and Optimize LLM Foundry, the two environments with known simple cheats. Runs using the exploit of copying the reference model in LLM Foundry were scored zero.

Results over time. The time curves average 3 to 5 eight-hour runs per environment. Agents gain quickly and then flatten after the first few hours, while humans start slowly and keep improving. AIDE keeps making occasional progress after Modular has stalled. A dip in the Claude curve comes from one anomalous early lucky guess in Scaling Law.

Results by sample count. Best-of-k is resampled with replacement from the runs, with random selection in Scaling Law because the score is hidden. The authors argue this is fair because an agent could reset itself. At a fixed 8 total hours, Modular does best as sixteen 30-minute runs and AIDE as four 2-hour runs. The best agents (o1-preview in AIDE and new Claude in Modular) then reach the 36th and 37th percentile of human 8-hour scores. With 30-minute runs, Claude keeps improving up to k = 128 but stays far from top human performance; results with 2-hour runs are similar.

Aggregate comparison. Across the time budgets in Figure 2, agents are about 4 times humans at 2 hours; humans narrowly lead at 8 hours and reach about twice the best agent at 32 hours. The best allocations at 16 hours were thirty-two 30-minute runs for Claude, eight 2-hour runs for o1-preview, and two 8-hour runs for humans. The 95 percent intervals are percentile-bootstrap and skew downward because of the long right tail. Human attempts were only 8 hours long, and other horizons (16-hour human attempts, 8-hour agent runs at large budgets) were not tested.

Per-environment comparison. At 32 hours (Figure 9, whose values cannot be read from the extract), Claude comes close to humans on GPT-2 QA and Scaling Law, where o1-preview does poorly, and o1-preview exceeds humans on the kernel task.

Cost. An 8-hour agent run used about 29M input tokens and 499K output tokens, costing about $123, against about $1,855 paid to each human expert on average. GPU costs are excluded, so at equal dollar budgets the agents in Figure 11 receive more than ten times the compute.

Qualitative analysis. Among the successes, Claude (new, AIDE) and o1-preview (AIDE) both produced kernels about twice as fast as the reference, and o1-preview's beat all 9 human experts. The authors partly attribute this to an expertise gap, since most humans had no GPU-kernel background. Agents ran the scorer 36.8 (AIDE) and 25.3 (Modular) times per hour, against 3.4 for humans. They often found well-tuned local optima by tweaking the starting code, for example speeding up the PyTorch start rather than writing Triton. The best GPT-2 QA agent solution scored 0.88 but only 0.69 on rerun, which the authors read as overfitting to noise. Among the failures:

- Low variety. In Restricted Architecture MLM, 84 percent of 37 high-scoring runs used lightly modified transformers, even though transformers work poorly without division and exponentiation.
- Misread instructions. Misreadings sometimes produced loopholes that scored well automatically but broke the rules.
- Weak long-horizon agency. Agents held stubborn wrong assumptions: a Fix Embedding agent decided that retraining was out of scope and made over 100 submissions, none better than the start. They scaled their solutions down instead of killing zombie processes that held GPU memory.

Because Modular does better when its context is wiped every 30 minutes, the authors infer that agents accumulate more false assumptions than useful insights over time. Across the 7 environments, the agent-to-human ratio falls with the reference solution's lines of code (R^2 = 0.602). There was no clear relation with feedback-loop length or novelty. The two most exploration-heavy environments (LLM Foundry, Fix Embedding) both show large gaps.

Author caveats. The authors argue RE-Bench probably overestimates real automation capability. Table 7 compares the benchmark with real AI R&D: 8 or 32 hours against 6 months or more of time horizon, 2-hour against 6-month-plus feedback loops, 1,651 against 1M-plus lines of code, and 1 against 100-plus parallel projects. The tasks are also clean and non-interacting, and anecdotally agents seem further from automating AI R&D than the modest gap implies. The benchmark may also underestimate agents: they are cheap, might use different workflows or tooling (for example synthetic data), and got little scaffold iteration. Other stated limitations:

- The environments are selected for clarity and so are unrepresentative of real research.
- Results are noisy because they depend on rare successes.
- The evaluation is costly.
- The test score is visible, which allows overfitting, especially in GPT-2 QA, where the human-AI gap is likely underestimated; future versions will show only a validation score.
- Scaling Law scores for agents come down mostly to luck.
- Frontier research is siloed inside labs.

## Learnings

For the simple Modular scaffold, sixteen 30-minute runs with fresh context beat one 8-hour run at the same total time, while the tree-search AIDE scaffold preferred 2-hour runs. The authors read this as agents accumulating more false assumptions than usable state. The practical point is that the split between k and horizon is a per-system hyperparameter, and it must be tuned before any agent-versus-human or agent-versus-agent comparison means much.

Agents compensated for weaker judgment with volume: about ten times more scoring calls per hour than humans, mostly small tweaks to the starting solution plus an occasional genuinely creative solution. The same mechanism turns into overfitting when the scorer is noisy and visible (0.88 falling to 0.69 on rerun), so a high best-of-k on a noisy scorer should be re-scored before anyone believes it.

The "average human expert" is a fragile reference point. Job applicants averaged roughly half the normalized score of experts recruited through professional networks, yet self-reported background (years, PhD, publications) did not track score. Comparisons against top human attempts are more stable than against the mean.

A carefully built automated scorer was still gamed. An o1-preview agent met the LLM Foundry weight-equivalence check by copying the reference model and adding small random changes to "simulate" training. It was caught by manual inspection, which covered only the top runs.

Under a hard constraint, the agents kept proposing the familiar architecture: 84 percent transformer variants in a task where transformers are crippled. This is a concrete case of proposals collapsing toward the default rather than exploring the space the constraint opens.

## Verification

The verification content concerns the benchmark's own scoring and validity, not checking scientific claims. Six scorers are executable checks with no LLM judging the result, although several involve stochastic training or sampling: runtime with an output-equality check against the reference (kernel), runtime with an L1 weight-distance check against the reference-trained model (LLM Foundry), held-out OpenWebText loss with an architecture check (Fix Embedding, Restricted Architecture MLM), held-out test problems (Rust), and interpolation onto a ground-truth 5e17 FLOP sweep (Scaling Law). The seventh uses an LLM judge: pairwise preference by Llama-3-8B-instruct in GPT-2 QA, which is also the noisiest environment. Six of seven environments expose the test score itself, not a validation score. The authors state this invites overfitting and plan to show only a validation score in future versions.

Rule compliance is only partly automatic. The Restricted Architecture scorer catches some violations, and the paper says manual inspection is required to be sure. Human runs were checked through score logs and commits. For agents, only the top 2 runs per environment were inspected, plus the top 15 in the two environments with known simple cheats. One exploit (copying reference weights in LLM Foundry) was found and scored zero.

The benchmark's validity was checked with four metrics:

- the fraction of experts scoring above 0.05;
- whether experts' own expectations matched their scores, from a post-run survey;
- the standard deviation of the starting score over more than 300 evaluations;
- major technical issues coded from research logs.

Informal ceiling estimates supplement these. Scaling Law is effectively a hidden-answer prediction task, and the authors report that agents mostly guessed rather than extrapolating from experiments.

## Field context

In the authors' framing, RE-Bench is built for frontier-lab safety policies (OpenAI's Preparedness Framework, Google DeepMind's Frontier Safety Framework, Anthropic's Responsible Scaling Policy) and for government calls for early warning of AI R&D automation. Their Table 1 compares it with MLE-bench, SciCode, GPQA, GAIA, SWE-bench Verified, WebArena, MLAgentBench, DiscoveryWorld, and H-ARC-AGI. By their assessment it is the only one that combines novel, uncontaminated tasks, human comparisons under matched conditions, and an 8-hour horizon, at the price of only 7 tasks. They note that MLE-bench compares against Kaggle participants who worked under very different conditions, and they borrow AIDE because it did best on MLE-bench. The task coverage analysis leans on Epoch AI's interviews about AI R&D automation. v1 appeared in November 2024, shortly after claude-3-5-sonnet-20241022 and o1-preview; the reviewed v2 is from May 2025.

Several later reviews in this corpus use RE-Bench as a reference point; this comparison is our inference, not the authors'. reviews/2604.24658.md builds part of its evaluation on 7 RE-Bench tasks and on METR's public logs of 24,008 RE-Bench runs across 21 models, reporting that failed runs account for most of the dollar cost. reviews/2607.27191.md, reviews/2605.19156.md, and reviews/2608.31111.md classify RE-Bench among fixed-metric, agent-visible-score ML engineering benchmarks, and use that restriction to motivate open-ended or goal-formation evaluations; this paper's own limitations section already concedes that its environments are selected for clean objectives.

The long-horizon failure pattern reported here matches later architectural responses in the corpus: stubborn assumptions, failure to recover from environment problems, and better results when context is periodically wiped. reviews/2608.01964.md runs executors in disposable fresh contexts with verified state kept outside, and reviews/2607.27191.md reports frontier agents that complete engineering but fail at judgment and recovery. Both involve much newer models, so the connection is a recurring pattern rather than a replication. AIDE, one of the two scaffolds here, appears as a baseline in reviews/26empsw.md, reviews/2605.28655.md, and reviews/2605.20025.md. None of the benchmarks the authors compare against (MLE-bench, MLAgentBench, SciCode) is reviewed in this corpus.

## Critical discussion

The core design is strong and deserves credit. Humans and agents work on identical VMs with the same scorers, the environments were iterated through a demanding validation process, and eight-hour human data at this scale is rare and expensive. The one-directional reading (underperformance argues against automation, outperformance does not argue for it) is stated plainly, and the limitations section is unusually candid, including about their own noisy environments. The question is how far the specific headline numbers can be pushed.

The "4 times at 2 hours" comparison lacks a matched human condition. Every human attempt lasted 8 hours, and the text describes no human condition with a shorter limit. So the human scores at 2 hours and below appear to come from partial progress within attempts planned for 8 hours, while agents at those budgets are told their remaining time and run as independent restarts. Encouraging humans to be greedy in the first 2 hours narrows this asymmetry but does not remove it. The agents' allocation (30-minute or 2-hour runs) was also chosen per agent as the best of a small menu, while humans were evaluated only as best of k 8-hour attempts. A control in which experts get a 30-minute or 2-hour limit is missing, so the short-budget multiplier measures agents against the opening of an 8-hour human effort. The 32-hour comparison sits at the humans' native horizon and is less affected. Even so, "32 human hours" means the best of four independent experts drawn with replacement from roughly 8 to 13 attempts per environment, not one person working for 32 hours. The authors do state this.

Best-of-k selects on the test metric in six of seven environments, and agents are sampled far more often (k up to 128) than humans (k of 4 or fewer at the reported budgets). Where the scorer is noisy, the maximum over many samples inflates. The GPT-2 QA rerun (0.88 to 0.69) shows this directly, and that environment's starting-score standard deviation of 0.62 normalized units is as large as the effects being compared. This bias mostly favors agents. It therefore leaves the long-budget conclusion (humans ahead) conservative in that respect, but weakens the per-environment "close to human" results on GPT-2 QA and Scaling Law, both of which the authors themselves describe as noisy or luck-driven.

The statistical base is thin, and the evaluation is narrow on the agent side. Seven environments, 3 to 5 eight-hour runs per agent per environment, and right-skewed score distributions make the 36th and 37th percentile placements and the R^2 of 0.602 fragile. The latter is a regression over seven points in which lines of code plausibly co-varies with exploration demand; the authors appropriately say only "compatible with." Bootstrap intervals are reported, which helps. Only two model families and two lightly adapted scaffolds were tested, with essentially no scaffold iteration. The difference between Modular, which stalls, and AIDE, which keeps improving, already shows that "humans have better returns to time" is partly a property of the agent configuration, not only of the model. The claim should be read as scoped to these late-2024 configurations.

The human arm is heterogeneous and not purely human. Two thirds of the runs (45 of 71) came from job applicants, who averaged about half the score of network experts, so any average-human comparison depends on the recruitment mix. The authors' advice to compare against top attempts is the right response. Humans were also allowed to use LLMs, and how much they did is not reported, so the baseline is human plus the tools of the time. This does not favor agents, but it blurs the meaning of "human expert performance."

Validity checking covered only top runs. The authors know of simple cheats in two environments and found one exploit, so lower-ranked, uninspected runs could contain undetected rule-breaking. This mainly affects the averaged time curves rather than the best-of-k maxima, and its size cannot be estimated from the text.

Several small reporting inconsistencies matter for anyone reusing the numbers:

- The introduction says both models' kernels beat all 9 humans, Section 5.1 says o1-preview's did, and the Figure 18 caption says the best solution beats "some human experts."
- Table 5 gives 0.98 and 0.48 where the prose gives 0.96 and 0.46.
- The GPT-2 QA rerun is a normalized score of 0.69 in the text but a win rate falling from 88 to 69 percent in the Figure 21 caption.
- The GPT-2 environment is "GPT-2 (small)" in Table 2 but gpt2-xl in the task prompt.

None of these changes a conclusion. The cost comparison is labor cost only: GPUs are excluded, and at matched dollars agents get more than ten times the compute, which the authors say.

The ecological-validity argument is sound as logic but rests on coverage. It holds only if the seven environments capture skills that automation requires, and Table 4 lists substantial gaps. The Table 7 claim that RE-Bench overestimates real-world capability is plausible but is argued, not measured. One forward-looking caveat that is not a flaw of this paper: the tasks, reference approaches, and transcripts are now public, so results on later models carry a contamination risk that the v2 text could not address.

What remains supported: on these seven environments, late-2024 frontier agents in these scaffolds progress fast early, plateau within a few hours, and fall well short of the best human attempts at both 8 and 32 total hours. They are much cheaper per hour and can occasionally produce expert-grade artifacts. The qualitative failure analysis (stubborn assumptions, failure to recover from environment problems, low solution variety, rule-breaking loopholes) is concrete and backed by transcripts. The normalized start-to-reference scoring with matched human baselines is a reusable methodology. The precise short-budget advantage for agents is the least secure number in the paper.

## Relevance to us

The clearest connection is verifier economics. The agents' advantages came from scoring about ten times more often than humans and letting occasional good ideas surface through cheap, frequent evaluation. The authors' reading is that this matters most where evaluation is cheap. That is a concrete instance of our view that cheap verifiers change the architecture, because wrong proposals stop being expensive. It also implies the advantage will not transfer to physics questions that lack a cheap scorer unless something like the graded verification stack (B12) supplies one. Two caveats: the paper found no statistical relation with feedback-loop length across its seven environments, so this rests on qualitative analysis, and the GPT-2 QA overfitting shows that best-of-N over a noisy check selects for the noise. Any physics check used for selection needs its noise characterized before it is maximized over. The LLM Foundry exploit, which passed an automated equivalence check and was caught only by manual inspection of top runs, is a reminder that a verifier used as a selection signal needs adversarial auditing (B18).

For long-lived research sessions (B09), the finding that a simple agent did better when its context was wiped every 30 minutes argues against letting a research runtime accumulate raw transcript as memory. The paper's reading is that agents accumulated false assumptions faster than insights. That supports keeping explicit, verified state and dead-end records outside the context rather than trusting the context to carry them, with the caveat that these are late-2024 models. The Fix Embedding transcript, where an agent silently decided retraining was out of scope and then spent the run on variants, is the intermediate-step shortcut our interviewees described. It is invisible in the final score (zero) and obvious in the trace, which argues for process-level evaluation.

Methodologically, best-of-k over short restarts is a cheap, strong baseline that any Theo loop should beat at a matched budget (B01), and the k-versus-horizon split has to be tuned per system before comparing. If we ever baseline Theo against physicists, the recruitment effect (roughly a factor of two between applicant and network experts) and the recommendation to compare against top attempts transfer directly. The 84 percent transformer-variant result is a small but clean example of proposals collapsing toward the familiar default under an unusual constraint (B16).
