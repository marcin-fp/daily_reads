Citation: Deng, K., Wang, X., Duan, G., Mo, C., Huang, J., Zhang, R., Qian, L., Huang, Z., Han, J., Luo, D. Towards Verifiable and Self-Correcting AI Physicists for Quantum Many-Body Simulations. arXiv:2604.00149, 2026.

## What this paper is about

Getting an LLM to write a simulation script that reproduces a specific figure from a published physics paper is much harder than getting it to solve a textbook problem, and the usual fix — an agent that writes code, runs it, and patches whatever error comes back — has two blind spots the paper targets directly. First, a script can run without crashing while still being physically wrong (wrong particle number, wrong sign in a Hamiltonian term, unconverged calculation), and a plain execution-repair loop has no way to notice this. Second, even for ordinary bugs, a loop that only sees "the first runtime error" fixes issues one at a time and can get stuck cycling through a long chain of them. The paper introduces two things together: QMP-Bench, a 100-task benchmark built from 21 published quantum-many-body-physics papers (not curated toy problems), and PhysVEC, a three-agent framework (an Author agent that writes the code, a Programming verifier that checks it runs correctly, and a Scientific verifier that checks the results are physically correct) designed to catch both failure modes explicitly rather than relying on an LLM to self-report confidence.

## Extended summary

QMP-Bench tasks are constructed by taking a published paper's LaTeX source directly from arXiv plus a short instruction naming a specific figure to reproduce (restricted to a few representative parameter cases when a figure involves an extensive parameter scan), spanning four computational paradigms with their standard community libraries: 36 tensor-network (DMRG, via ITensors), 18 neural-quantum-state (via NetKet), 20 quantum-circuit-simulation (via Qiskit), and 26 density-functional-theory (via ORCA) tasks. Baseline results on four frontier models (GPT-5.1, Gemini 2.5 Flash, Qwen3-Max, Claude Sonnet 4) under a standard ReAct execution-repair loop, and a ReAct-RAG variant augmented with retrieval over the target library's official documentation, show the benchmark is genuinely hard: pass@8 executability (fraction of scripts that eventually run without a runtime exception, given up to 8 repair iterations) is generally below 50% under plain ReAct and rarely exceeds 75% even with documentation retrieval, with the best-performing configuration (Claude Sonnet 4 + ReAct-RAG) still only reaching about 50% executability on the neural-quantum-state tasks. A qualitative failure case (reproducing a two-chain Hubbard model's spin-spin correlation function) shows both baselines producing scripts that run cleanly but are physically wrong in different ways — one configures the wrong total particle number for the required half-filling condition, the other defines a non-Hermitian (unphysical) hopping term — illustrating the paper's core point that executability and physical correctness are separate failure modes requiring separate checks.

PhysVEC's Author agent is required to structure its output into modular "element functions" (e.g., a function that builds the lattice, a function that defines the Hamiltonian) rather than a monolithic script, specifically so that downstream verification can inspect and correct each piece independently. The Programming verifier then runs unit tests (each element function is tested in isolation inside a constructed test environment, drawing on a pre-built "verifier library" of reference implementations distilled from the target package's own official repository/documentation) and integration tests (the computation is split into a level hierarchy and executed level-by-level to catch cross-function compatibility issues, which also cross-checks the unit-test results), aggregating all diagnostic reports and applying corrections in a single pass rather than fixing one runtime error at a time. The paper offers a simple probabilistic argument for why this should help: if each of N_E element functions is independently correct with probability at most p, a monolithic script's overall success probability decays as p^(N_E), while function-level unit testing counteracts this per-function rather than waiting for the failure to surface at the end of a long execution chain.

The Scientific verifier operates on scripts that already pass the programming test, and runs three checks in sequence: a rubric test (comparing the script against a manually authored per-task rubric specifying the intended physical system, computational method, and key parameters, flagging semantic mismatches even when the code runs); a physical assertion test (adapting the script into several test variants matched to physics-derived expected answers — small-system-size limiting cases solvable by exact diagonalization, symmetry-constrained outcomes, and parameter regimes with known analytical results — directly analogous to how a human researcher validates new simulation code against known special cases); and a convergence test (progressively increasing a numerical parameter, e.g. DMRG sweep count, until the result stabilizes). A worked case study (reproducing ground-state electron-density distributions in a 1D harmonic trap) shows the Scientific verifier catching an incorrectly configured trap depth and a missing density-rescaling step via the rubric test, confirming the fix against six physics assertions, then adjusting the sweep count from 40 to 80 based on observed convergence — producing a final figure the paper reports is visually near-identical to the published ground truth, versus both baselines' visibly incorrect reproductions (unconverged oscillations for ReAct-RAG; an overly concentrated, wrongly-trapped distribution for ReAct).

Quantitatively, PhysVEC substantially raises pass@8 executability over all three baselines (ReAct, ReAct-RAG, and "PhysVEC-1-shot," the Author agent's raw unverified output) across all four models and all four task categories, with executability approaching 100% for several model-topic combinations and the largest relative gains on the hardest category (neural quantum states). Finer-grained unit-test and integration-test accuracy metrics (not just the binary pass/fail) also increase markedly after PhysVEC's iterative correction relative to the unverified PhysVEC-1-shot baseline. PhysVEC also converges faster (steeper initial improvement curve) and to a higher saturation value than the baselines as a function of iteration count, and, in a tool-use efficiency comparison, extracts more executability gain per retrieval call than ReAct-RAG does. An inference-time-scaling experiment on the subset of initially-failed neural-quantum-state tasks (Gemini 2.5 Flash) shows the cumulative pass rate rising as more independent trials are allowed, framed as evidence the framework's structure makes repeated sampling productive rather than just repeating the same failure. Because scientific verification is more computationally expensive, the physical-validity evaluation is conducted on a five-task subset of QMP-Bench (all from the DMRG/tensor-network category), where PhysVEC produces substantially more physically-validated completions than either baseline across all four models, with completions accumulating steadily as Scientific-verifier iterations proceed. Token-cost accounting (Appendix E) reports PhysVEC's programming-verification stage typically costs under 1M input and 0.3M output tokens per task (a few dollars), and the scientific-verification stage under 0.5M tokens each way per task — presented as practically acceptable overhead given the accuracy gains.

## Learnings

The most transferable idea is the paper's explicit separation of two distinct failure modes that a single "does it run" check conflates: programming correctness (the script executes without error) and physical/scientific validity (the script computes the right thing), each requiring a structurally different verification mechanism — unit/integration tests for the former, physics-informed assertions grounded in known limiting cases, symmetries, and analytical results for the latter. This is a specific, reusable design principle for any AI-for-science agent pipeline: "runs successfully" and "is scientifically correct" are independent properties that can diverge in either direction, and the paper's own qualitative failure case (both baselines produce clean-running but physically wrong Hubbard-model scripts) is a concrete illustration of exactly the gap this separation is meant to close.

A second learning is the specific technique of validating a physics simulation against special-case ground truth the researcher can independently derive — exact diagonalization at small system sizes, symmetry-constrained outcomes, and known analytical limits — rather than relying on an LLM's own judgment of plausibility or an external LLM-as-judge. This mirrors, and makes explicit and systematic, the way a human computational physicist would sanity-check new simulation code before trusting it on the full-scale problem, and it sidesteps the "LLM-as-judge inherits the very hallucinations it's meant to detect" problem the paper explicitly identifies as a limitation of alternative evaluation approaches.

A third learning is the structural design choice of forcing the Author agent to decompose its output into named, independently-testable "element functions" as a precondition for verification, rather than treating verification as something bolted onto an arbitrary generated script after the fact. This is a specific architectural lesson (impose a testable structure at generation time, don't try to retrofit testability onto free-form code afterward) that is directly reusable for other agentic code-generation pipelines wanting to support fine-grained, localized error correction rather than only whole-script pass/fail feedback.

## Verification

Verification is close to the entire subject of this paper rather than a satellite concern, and the paper's approach is unusually layered: unit tests and integration tests independently cross-check each other (the paper notes integration-test results are "also used to double-check the judgments made in the unit tests"), and the Scientific verifier's three checks (rubric, physical assertion, convergence) are similarly complementary rather than redundant, each targeting a different way a script can be scientifically wrong. The paper also offers a specific, checkable account of why aggregating all diagnostics in one pass should outperform an execution-repair loop that only surfaces the first error: an explicit probabilistic model (independent per-function correctness probability p, N_E element functions, overall success scaling as p^N_E without per-function correction) rather than an unquantified claim that "more information helps." That said, the paper's own scope disclosures are important to weigh here: the Scientific verifier's rubrics and physical assertions are manually authored per task by the paper's authors rather than generated autonomously by the system, a limitation the Discussion names directly ("scientific tests still rely on human expertise. Automatically synthesizing rubrics and physical assertions is an important next step"). This means the "self-verifying AI physicist" framing in the title and abstract should be read carefully: what has been automated is the process of applying verification criteria and acting on the diagnostic evidence, not the process of deciding what should be verified in the first place, which for now still requires a human physicist's judgment about what limiting cases, symmetries, or analytical results are relevant to a given task.

## Field context

The paper positions QMP-Bench against a specific lineage of physics-reasoning benchmarks it traces explicitly: exam/Olympiad-level testbeds (SciBench, GPQA, PHYSICS, Physics Supernova), followed by more research-adjacent but still human-curated and simplified benchmarks (CriPt, TPBench), followed by the most directly comparable recent efforts (PRBench, PRL-Bench) that also derive tasks from published articles — with QMP-Bench's stated differentiator being a specific focus on a technically demanding domain (quantum many-body simulation) requiring genuine third-party community libraries (ITensors, NetKet, Qiskit, ORCA) rather than more generic computational tasks. On the verification side, it explicitly contrasts its approach with two other paradigms it names directly: formal-verification approaches (bringing Lean-style formal systems into physics/math theorem proving), which it argues remain "highly impractical" for complex numerical simulation specifically (as opposed to symbolic proof); and LLM-as-a-judge approaches, which it critiques for "inherit[ing] the very hallucinations they are meant to detect" — a criticism this batch has independently encountered in several other papers' treatment of same-family or self-referential evaluation. Within this batch, PhysVEC's core structural bet — that a monolithic, single-pass verification signal (does the whole script run) should be decomposed into many smaller, independently-checkable units to avoid exponential success-probability decay and enable parallel rather than sequential error correction — is conceptually related to 2603.28052's Meta-Harness (reviewed earlier in this batch), which similarly argues that compressed or aggregate feedback (a single scalar score) discards the diagnostic information needed to trace a failure to its specific cause, and that exposing more granular, structured information (Meta-Harness's raw execution traces; PhysVEC's per-function unit-test and per-check scientific-assertion results) is what actually enables effective automated correction rather than just more search.

## Critical discussion

The paper's physical-validity evaluation — arguably its most scientifically consequential claim, since programming correctness alone says nothing about whether a script's output means anything — is conducted on only five of QMP-Bench's 100 tasks, all drawn from a single task category (tensor-network/DMRG methods), a limitation the paper discloses directly ("Due to computational constraints") rather than hiding. This narrows what the headline "PhysVEC ensures physical validity" claim can support: it has been demonstrated for one computational paradigm (lattice-model tensor-network calculations, where limiting cases via exact diagonalization and symmetry constraints are relatively natural to construct) but not for the other three (neural quantum states, quantum circuit simulation, density-functional theory), where the availability and character of analogous physics-informed assertions is not obviously the same — DFT electronic-structure calculations of the kind in QMP-Bench's `dft` subset, for instance, may have fewer clean small-system exact-diagonalization limits available as sanity checks than a spin or Hubbard lattice model does. The paper does not discuss whether the Scientific verifier's specific assertion types would transfer as readily to these other domains, leaving the framework's core scientific contribution validated on a narrower slice of its own benchmark than the executability results.

A second concern, not addressed anywhere in the paper, is contamination risk specific to this benchmark's construction: QMP-Bench's tasks are drawn from "high-impact prestigious journals" (Physical Review Letters, Science, Nature Communications, JACS), several evidently well-known within their subfields (e.g., a foundational neural-quantum-states Science paper), and frontier LLMs are plausibly trained on discussions of these results, associated code (some of these methods have example implementations in the very libraries — ITensors, NetKet — the agents are instructed to use), or citing literature that describes the expected numerical outcomes. This does not undermine the paper's central comparative claim (PhysVEC beats ReAct/ReAct-RAG under identical potential-memorization conditions, since all methods use the same base models), but it does mean the benchmark's absolute difficulty and the framing of tasks as requiring genuine "reproduction from the article's description" rather than partial recall of memorized results is not verified by any decontamination check, unlike, for instance, 2603.28052's math-retrieval corpus in this same batch, which explicitly reports an exact-prefix-plus-fuzzy-Jaccard decontamination procedure against evaluation sets. A reader should be cautious about over-interpreting the absolute pass rates (rather than the relative PhysVEC-vs-baseline comparisons) as measuring pure from-scratch reproduction capability.

Third, the reported executability and physical-validity results appear to reflect single evaluation runs per model-task combination rather than repeated trials with reported variance (the inference-time-scaling experiment in Fig. 6(c) is the one exception, explicitly built around repeated sampling), so the fine-grained accuracy differences visualized in scatter plots (Fig. 6(a)-(b)) should be read with some caution regarding run-to-run stability, particularly for the smaller five-task scientific-verification subset where a single task flipping from fail to pass changes the reported completion count by 20%.

What remains well supported after these caveats: the qualitative, mechanistically-explained core finding — that decomposing verification into fine-grained, independently-checkable units (element-function unit tests; per-assertion physics checks) enables faster and more complete error correction than a monolithic execution-repair loop that surfaces only the first failure — is demonstrated consistently across all four evaluated models and all four task categories for the programming-correctness half of the claim, which is the paper's most broadly-evaluated result; the specific case study (harmonic-trap electron density) provides a concrete, inspectable trace of the Scientific verifier catching two distinct, correctly-diagnosed physical errors (incorrect trap depth, missing density rescaling) rather than a black-box before/after comparison, which is a genuine strength for the "human-auditable evidence" claim central to the paper's motivation; and the paper's own explicit acknowledgment that scientific-verification criteria still require human authorship, rather than presenting the system as more autonomous than it currently is, correctly scopes what has actually been automated in this work.
