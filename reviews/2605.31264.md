Citation: Zhou, T., Liu, D., Yuan, L., Shao, J., Hu, X. COLLEAGUE.SKILL: Automated AI Skill Generation via Expert Knowledge Distillation. arXiv preprint, 2026. https://arxiv.org/abs/2605.31264v1

## What this paper is about

When a knowledgeable colleague leaves a team, their review standards, incident heuristics, and communication habits usually leave with them, scattered across chat logs, code comments, and documents that nobody turns into a usable reference. This paper describes COLLEAGUE.SKILL, a deployed open-source system (Shanghai AI Laboratory) that automatically distills such heterogeneous human traces into a portable "Agent Skill" package — a folder an AI agent can load — with two separated parts: what the person knew and did (procedures, checklists, decision heuristics) and how they communicated (tone, interaction rules, boundaries). The explicit framing is a bounded, correctable, inspectable artifact rather than an attempt to simulate the person, and the same pipeline is repurposed for two further, progressively more sensitive settings: distilling a public figure's reasoning style from public evidence, and distilling private interpersonal interaction patterns from a relationship, each with different consent and evidence-boundary assumptions.

## Extended summary

The system formalizes "person-grounded skill generation" as producing a package S = (A, M, L) — generated files, machine-readable metadata, and lifecycle state (version, correction count, rollback history) — from a lightweight profile, a source scope, and a set of source materials, targeting five properties: portable (loads via standard Agent Skills mechanisms), inspectable (a user can read the extracted rules before use), composable (full/work-only/persona-only entry points can be invoked separately), correctable (feedback updates the package while preserving prior state), and governable (metadata and source boundaries support deletion, sharing decisions, and safety review). The pipeline runs in five stages: trace intake (parsing chat exports, documents, email, screenshots, subtitles, etc. from sources like Feishu, DingTalk, Slack, WeChat, or email archives into a local knowledge directory), a preset router (colleague, celebrity/public-figure, or relationship, each specifying its own source boundary, consent assumptions, and prompt bundle), a "dual distill" step that extracts a capability track (work.md: procedures, standards, heuristics) and a bounded behavior track (persona.md: expression style, interaction rules, and a correction log) as separately-invocable artifacts, an artifact writer that renders a versioned schema (SKILL.md as the combined entry point plus independently-loadable work-only and persona-only sub-skills, manifest.json and meta.json for installation and lifecycle metadata, following the community Agent Skills specification and its "progressive disclosure" convention), and an optional productization step (installation into supported agent hosts — Claude Code, OpenClaw, Codex, Hermes — or, with the user's consent and rights, submission to a public gallery).

Corrections are handled as a first-class lifecycle operation: natural-language feedback ("he would not say that") is converted either into a Markdown patch to a matching section of the capability document or a normalized correction record for the behavior document; the writer archives the prior version before applying any change, and a version manager supports listing, rollback, and pruning of archived versions. The celebrity/public-figure preset adds a dedicated research toolchain (subtitle download and transcription, research-note merging, and a quality checker scanning for mental-model coverage, evidence limitations, internal tensions, grounding URLs, and copyright-safety signals) explicitly designed to downgrade confidence when evidence is thin rather than fill gaps with generic persona text — though the paper is clear this "does not certify factual truth by itself." The relationship preset reuses the identical artifact format but is framed as requiring materially stronger assumptions about consent, retention, access control, and local-only defaults, since its source material is private interpersonal traces "supplied by the user" rather than public evidence.

As deployment evidence, the paper reports public counters observed on 2026-05-28: approximately 18.5k GitHub stars, ~1.8k forks, 104 commits on the public site, a gallery listing 215 skills and 55 meta-skills from 165 contributors, and more than 100k cumulative gallery-card star counts (reported at order-of-magnitude precision because the counters synchronize asynchronously). The authors explicitly caveat that these numbers indicate "deployment and distribution surface... rather than task performance, behavioral fidelity, or adoption-quality metrics." Section 8 ("Behavioral fidelity frontier") and Section 9 ("Limitations and Responsible Deployment") state directly that the paper makes only artifact-level claims: it does not claim generated skills faithfully reproduce a person, improve downstream task performance, or have been validated by any human-subject or task-based study; it explicitly lists open questions (whether colleague skills catch the same review issues as the source expert, whether corrections improve behavior without introducing regressions, whether relationship skills risk emotional overattachment) as future work requiring separate evaluation protocols that compare full, capability-only, and behavior-only variants under matched source evidence. No funding is disclosed; the Acknowledgements instead credit a long list of community members who contributed skills to the public gallery.

## Learnings

The core reusable design pattern — separating a distilled expertise artifact into an independently-invocable capability track (what a person knew/did) and a bounded behavior track (how they communicated), rather than a single monolithic persona prompt — is a transferable architectural principle for any system distilling a person's or role's knowledge into an agent-usable form: it directly targets a specific, named failure mode the authors identify in prior persona systems (conflating factual knowledge, procedural judgment, and surface tone into one object), and the separation lets a downstream user invoke expertise without also inheriting communication style, or vice versa, which is a concrete and checkable design property independent of whether this specific system's outputs are behaviorally faithful.

The versioned correction-and-rollback lifecycle (natural-language feedback converted into either a section-level patch or a structured correction record, with automatic archiving before every mutation) is a reusable pattern for any agent-artifact system where the artifact is expected to be imperfect on first generation and iteratively refined by a human in the loop — treating corrections as auditable, reversible version-control operations rather than silent overwrites is a generalizable governance mechanism, independent of whether the specific corrections here concern review checklists, public reasoning styles, or private interaction patterns.

## Verification

The paper contains essentially no verification of its central artifact-quality claims, and states this explicitly rather than implying otherwise: it is candid that the system "does not solve behavioral fidelity" and that the extraction quality, task utility, and safety properties of generated skills remain unmeasured, leaving human-subject and task-based evaluation to future work. The one verification-adjacent mechanism described is the celebrity preset's "quality checker," which scans generated public-figure skills for mental-model coverage, evidence limitations, internal tensions, grounding URLs, and copyright-safety signals — but this is a heuristic content-completeness check on the artifact's own structure, not an independent check against ground truth about whether the extracted mental models are accurate or whether the artifact's behavior matches the source person, and no accuracy, precision, or human-agreement statistic is reported for it. The reported deployment statistics (star counts, contributor counts, gallery size) are popularity and distribution-surface metrics, not correctness or quality metrics, and the paper is explicit that they should not be read as such.

## Field context

COLLEAGUE.SKILL adopts the Agent Skills specification (a SKILL.md-centered folder format with progressive disclosure, used by Claude Code and other agent hosts) as its packaging substrate, and explicitly targets installation across Claude Code, OpenClaw, Codex, and Hermes as supported agent hosts — the same OpenClaw and Hermes systems examined, alongside Claude Code, in [reviews/2604.14228.md](2604.14228.md) ("Dive into Claude Code: The Design Space of Today's and Future AI Agent Systems"), reviewed earlier in this batch, which reverse-engineers how these three independently-built agent systems answer recurring architectural questions (context management, sub-agent delegation, safety posture); COLLEAGUE.SKILL's skill-packaging problem is a natural downstream layer on top of exactly the host architectures that paper analyzes, though neither paper engages with the other. The paper positions itself narrowly against two adjacent literatures it reviews directly: agent skill-library/skill-synthesis systems (Voyager, SkillX, SkillGen, AutoSkill), which construct reusable skills from an agent's own execution trajectories rather than from a human's traces, and memory/personalization/role-playing systems (RAG, LaMP, PersonaAgent, Character-LLM, RoleLLM, SOTOPIA), which the paper argues keep the extracted representation inside retrieval stores or model behavior rather than as an inspectable, editable, version-controlled file artifact — this artifact-first framing, rather than a new extraction algorithm, is the paper's actual point of differentiation from both lines of prior work.

## Critical discussion

The paper is unusually candid, for a system-description paper with prominent deployment statistics, about the boundary of what it has and has not shown: it repeatedly and explicitly states that behavioral fidelity, task utility, and safety outcomes are unvalidated, names the specific studies that would be needed to validate them, and frames its own contribution as artifact-format and workflow design rather than a demonstrated capability improvement. This kind of explicit scoping is worth crediting rather than treating as a weakness in itself.

The more substantive gap is between the governance language used throughout (consent, access control, retention limits, local-first storage, non-mandatory use) and what the system is actually shown to enforce. These properties are described as design intentions and default assumptions of each preset — the relationship preset, for instance, is said to "require stronger assumptions about consent" — but no mechanism is described that verifies, at generation or correction time, that consent was actually obtained from the person whose private interaction traces are being distilled into a skill package, nor is any audit, red-team result, or even a described technical safeguard given for how the system would detect or prevent a user from feeding it another person's private chat logs without that person's knowledge. For a preset the paper itself flags as carrying risks of "emotional overattachment, non-consensual simulation, and misuse of private chats," relying entirely on the requesting user's honesty about consent, with no described verification step, is a real gap between the paper's protective framing and its actual technical content — this is a point the paper's own Limitations section gestures toward ("consent... require[s] separate review") but does not close. Similarly, the celebrity-preset quality checker's stated goal (downgrade confidence when evidence is thin rather than hallucinate) is a sound design goal but is reported with no measurement of how often it actually succeeds at that discrimination versus how often thin evidence still yields a confidently-stated mental model. What remains supported is exactly what the paper claims to have delivered: a working, publicly deployed artifact format and generation-correction-installation-distribution workflow with genuine adoption signal (a substantial, if unaudited, public gallery and contributor base), and a specific, well-motivated architectural choice (splitting capability from behavior into separately invocable, inspectable files) — not any claim about whether the resulting skills are accurate, safe, or useful in practice.
